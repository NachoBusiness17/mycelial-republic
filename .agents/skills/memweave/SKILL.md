# MEMWEAVE — memlang × RIB × weave

**Grounding:** the ghost operating doctrine rib (memweave, source: foundational,
in `memory/rib_bus/doctrine.json` + the Memweave rib family) · tested findings:
"MEMWEAVE MINDWEAVE: tested findings" + "MINDSWEAVE EVAL: adversarial harness
results" (2026-08-10, rib store) · distributor: `mag/mem_weave_distributor.py`.

**The law:** models perform on STRUCTURES better than on prose describing the
same content. Memory is woven as addressable structures (rows, ribs, keyed
packs) that ride the RIB kernel — not as narratives the model must re-parse.

## Procedure
1. Reduce the payload to its structure: rows with keys, typed fields, pointers.
2. Attach to the RIB kernel (byte-stable prefix) as TAIL — memweave never
   mutates the kernel (context-os linkage law).
3. Weave across seats via shared surfaces (rib_bus, chan rows, corpus tools) —
   each seat loads the structure it needs, not the whole weave.
4. Evaluate adversarially before trusting (MINDSWEAVE precedent: the harness
   attacks the weave, not the model).

**Falsifier:** a memweave pass is working when structure-fed seats beat
prose-fed seats on the same task at equal tokens; if prose matches structure,
the weave is ceremony — cut it.
