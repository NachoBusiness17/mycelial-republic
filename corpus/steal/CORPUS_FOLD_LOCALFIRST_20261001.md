## Top mechanisms

1. **Content-addressed snapshot compile with reader-side total verification.** ownmem binds the snapshot id to compiler version + source sha256 + content sha256 (lib/memory-index-store.mjs:74-76), re-verifies every manifest checksum on every load (:99-156), and on any mismatch never patches: it degrades to rebuild-from-Markdown, because "recompiling it is cheap and always correct, whereas a second reader for an older encoding is a parser that has no producer and never goes away" (:24-27). Feeds the estate's derived-cache organ: the corpus FTS5 index (B2-465 daily rebuild, tools/corpus_fts_rebuild.py) has a freshness gate that detects staleness but does not checksum the index body, and the verkle read path degrades to UNVERIFIED instead of refusing.
2. **$0 deterministic recall beside a fixed context pack.** Default recall runs five local lanes (exact, BM25F, n-gram, fuzzy, graph) with no model call and no query-time network (lib/features/recall.mjs:724-738; the embedding channel arms only when configured). The estate's mag/context_pack.py build_context_pack (:638) clips the same fixed files every turn regardless of task (:687-691), so query-conditioned law selection over memory/rib/ + the clippy bullets is an unbuilt, zero-cost upgrade. Feeds the context-pack organ.
3. **Two-slot immutable pointers, pointer-ordered GC, nonce-owned locks.** Snapshot publication moves previous-v1 then v1 symlinks (:279-280, with a Windows unlink-then-rename restore path :210-238); GC reads the reference set FROM the pointers and an empty reference set deletes nothing ("Deleting on an incomplete set is how a garbage collector eats the live snapshot", :290-309; their incident: 76 orphan dirs, 1.56 GB); recoverStaleLock removes a lock only when age > staleMs AND the owner pid is dead, and release requires a nonce match (:342-363, :399-409). Feeds estate lockfile surgery: the estate's own git log carries commit bdbb1714e where a human executed exactly this three-condition test as judgment on an 11-hour stale index.lock.
4. **Three-ledger honesty and the ratchet discipline.** Retrieval feedback, outcome receipts, and agent self-attribution are never merged (docs_TECHNICAL.md:181-202); self-attribution is reported as counts never as an adoption rate; missing data is shown as unavailable never as zero; "how often its answers were actually used is reported as permanently unmeasured"; the entry-count quota only ratchets downward and the audit "refuses the write, it does not pick a victim" (README:30, ARCHITECTURE.md:85-89); the MCP governance surface exposes exactly recall + read ("a governance command one token away from an autonomous agent is not governance"). Feeds the percolator/invariant promote-gate organ.
5. **PAM's falsification and the forgery class it demonstrates.** Census over sdk/python/pam (16 files): sha256=0, blake3=11, ed25519=19; entry IDs and root hashes are BLAKE3, and SHA-256 exists only in the browser-extension plugin whose own README documents the divergence. Ed25519 signing is real (artifact.py:162-183) but the import gate checks integrity only and never the signature (cli.py:351). This is the same by-construction class as the estate's own verify_seal (hashes-only, manifest and seal in one writable domain): a signature that exists but is not verified on the import path is decoration.
