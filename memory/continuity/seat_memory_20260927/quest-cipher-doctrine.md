(2026-09-14) The operator asked "when do we get to the part where anything the cloud sees is math or riddles about our videogames while real coding work is happening as behavior to game actions — hotdogs in cipher."

**The doctrine, as it already works (receipts from the MUD week):**
- "Make the horde stop stacking" → Barnes-Hut spatial index
- "The dragon should shatter" → entity-cascade system with scaling curves
- "Two lanterns in one dark" → multiplayer seam analysis
- Game wants expressed honestly ARE the requirements; infrastructure is what the work looks like from underneath. No disguise layer needed or wanted — the cipher is a true translation.

**Architecture (the privacy that actually works):** corpus, engine, verkle record, and plans stay local. The cloud receives only the quest text. Recipe stays in the kitchen; cloud gets the order.

**Limits, said once:** deliberate word-cipher degrades model output (proven twice this session — clear game wants got the best engineering; vague riddles got jargon), and nothing being built needs policy-hiding because building games is permitted work. If a request ever DOES need cipher to be permitted, that is a provider-reconsideration event, not an obfuscation task.

**How to apply:** route engineering needs as game-design wants ("the horde spreads" not "implement spatial partitioning"). Keep seeds, lore, and plans in repo-local records. The beacon stays public; the shape stays across-sessions.

**2026-09-16 inversion (Mark's journal answer #3):** "put Stockfish / AlphaGo models in charge — they're tricked into games as work. Hence the mapping." Until now the cipher made work legible to HUMAN spectators in a game skin; the new form makes work legible to ENGINES — players who only understand moves. That hardens the lossless requirement: if the mapping degrades, an engine player literally cannot act. First mapping stone pending — [[journal-orders-20260916]].
