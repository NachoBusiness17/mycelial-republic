Q1 — Epistemology engine
A provenance chain cannot become a knowledge system by growing. It becomes one when claims and events are different types, and “known” is a status a stranger’s script can revoke.
Types

Event — what happened: timestamp, surface, payload hash, parent hash, signer.
Claim — a sentence with a type: measurement, rule, score, judgment.
Warrant — pointers from Claim → Event[] plus a Check that is not a paragraph. A check is a command that exits 0 or 1.
Status — Recorded | Contested | Bound | Void. Status lives on the Claim, never on the Event. Events are not true or false; they occurred or they did not.

Transitions

Append Event → Event is Recorded. No knowledge yet.
Open Claim with Warrant → Claim is Recorded.
Run Check on a machine that is not the author’s login session.
exit 0 → Bound
exit 1 → Contested

Second independent Check that contradicts a Bound claim → both Contested.
Void is an Event that points at a Claim and freezes it. No delete. Bound may not be written by the same signer that wrote the Claim.

Falsifier
A Claim whose Check is “the author agrees.” If the only way a row becomes Bound is a seat saying so, you have a notary, not a knowledge system.
Experiment that closes it
Pick one existing room fact (example: “phase is measured from velocity, not a slider”). Write a Check that reads the live distribution, classifies phase, and compares it to the on-screen label. Run it on a second machine from a published head hash. If you cannot write that check for even one card, that card is not knowledge.
Do not build the semantic hash. It hashes the suspect’s alibi.
