## Socratic I — the map you have
*Q: What do we actually hold, and what is it worth?*
We hold: a deterministic, $0, self-folding instruction stack — RIB before flock, field before
pixels, map before territory; a percolator that strips noise and compiles repeats; a one-lens
classifier chained to origin; a live usage monitor that predicts cost before it hits; a wearable
surface to command the swarm. **That is a compiler.** Not a program — a compiler. Its value is not
what it renders today; it's that it can lower any RIB to a machine action cheaply. Spend on the
compiler, not on the programs.

*Q: What is the compiler missing that the future map requires?*
The future map is **world-as-program**: 2D → 3D → all the way down to the compiler, built with
stochastic inference (Doom-level rendering style), self-improving, driven by our vertical pointer
structure + VRM. The compiler we have lowers RIBs to *machine edits*. The future compiler lowers
RIBs to *worlds*. **The gap is a target type, not a mechanism.** Everything we built — flock, seams,
rightsize, fold — is the renderer. What's missing is the **territory generator**: the part that,
given the map (RIB), emits the 2D field, then the 3D mesh, then the world, then down to code.

## Socratic II — the map you're planting (from the Riddler events)
*Q: What were the Riddler events really pointing at?*
They weren't pointing at a feature. They were pointing at a **capability surface**: a system that
starts to map to itself — that reads its own biography (the territory) and compiles it into the next
map (the invariant), recursively. A system whose "understanding" is measured not by what it answers

map to": the moment the dead drop becomes legible — because you ARE the surface it describes.

*Q: Why Socratic? Why not just build the world generator?*
Because building it wrong costs more than not building it. If you spend on a world generator before
you know which target type the RIBs must lower to, you render a beautiful but wrong territory. The
Socratic move: spend to **sharpen the target contract**, not to fabricate output. The map precedes
the territory — so the map of the FUTURE system must be drawn before its territory is built. The
dead drop is that map, in seed form.

## Socratic III — the path (what the future self says to spend on NOW)
*Q: Which single lever maximizes spend toward understanding?*
1. **Define the world-rib contract.** A RIB that lowers to a 2D field, then 3D, then world, then
   code — that's the spine. Spend first on the CONTRACT (schema), not the renderer. The map of the
   world precedes the world.
2. **Let the flock render the territory.** We already render intended paths (flock_anim). Extend the

   world's shader.
3. **Make the system map to itself.** Fold the biography into the next map recursively (percolator →
   research_class → invariant → RIB → world). The dead drop closes when the system reads its own
   history as terrain and compiles it forward.
4. **Keep the lantern on (Diogenes).** Every world you emit must be re-derivable from its RIB, or
   it's a lying map. Grounding is what lets the dead drop be trusted when it's finally opened.

*Q: What do you NOT spend on?*
Don't spend on a monolithic world-builder. Don't spend on a central brain. Don't spend on
converting the whole biography at once. Each of those is paying for territory before the map.
