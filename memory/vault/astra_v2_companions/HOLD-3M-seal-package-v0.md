## K.1 — Explicit supersession before seal

**Acceptance / change my mind:** every claim/configuration has one active version and explicit superseded IDs; an independent resolver finds zero ambiguous authorities. Source: signed scope manifest plus active configuration hashes. C1 pilot; C2 all included profiles. Another scheme that resolves authority unambiguously can replace this one.

## K.15 — Verifier skeleton interface and blind reveal

**Claim:** Two programs comparing themselves is not blind verification against truth. **Evidence/reasoning:** H3.7; M:13 salon; S:26–30.

Both skeleton contracts accept `manifest`, read-only `evidence_root`, `public_claims`, and an output directory. Only the protected controller passes a secret `oracle_handle`; workers do not receive oracle plaintext. Output contains manifest hash, verifier hash, enrolled/completed/missing denominators, per-claim tri-state status, confidence, change-mind evidence, invariant counts, exact state roots, excluded/out-of-scope claims, and evidence paths/digests. A skeleton with TODOs is not an executable verifier.

A uses independent event-state reconstruction; B uses independently observed destination facts and identity joins. They may share a published schema and cryptographic primitives, but not a common validator for the disputed invariants. Both freeze code before scored outcomes. Their separately written matchers, candidate counters and interval logic run inside the protected controller for the ingestion assay; only sanitized receipts reach their language-model contexts.

Order: freeze inputs and hidden truth → freeze A and B builds → final seal → restore separate clones → run the same sealed cases sequentially → each commits a salted digest of its complete verdict → reveal both verdicts and truth → verify commitments → compare each verdict to truth → compare workers. Do not revise first verdicts after reveal. Counterexample or exact-integer/root disagreement blocks promotion pending a newly versioned run; timing is evaluated against its threshold rather than bytewise equality.

**Acceptance / change my mind:** blocked cross-worker/oracle reads and independently reproduced truth comparisons, C2. A one-worker pilot can test its own verifier and controller but leaves two-worker independence Unproven.

## K.16 — Calibration cannot be an all-green demonstration

**Claim:** The harness must reject deliberately incorrect systems. **Evidence/reasoning:** H3.4 cases 01–16; B.14; I.9.

Required baseline cases: legitimate identical payloads with different operation IDs; duplicate delivery of one operation; same ID/different payload; missing admission; exit-zero wrong artifact; dropped plus duplicated meter rows; unauthorized scope; stale epoch; delayed original arriving after an absence read; broken dedup producing two ledger effects; torn export tail; missing referenced object; unknown active build; and a known-correct unanimous verifier result alongside a known-wrong unanimous result. A control that cannot expose its intended defect does not establish the claimed coverage.

Assay profile additionally requires exact/near/cross-marker matches, uppercase output, 64-hex output with 33 windows, extra retry, wrong checkpoint, omitted adapter, hidden answer leak, inference-time weight update, masked suffix labels, and retrieval-only reproduction wrongly labeled training. Meters count calibration work separately from scored episodes. All use disjoint public fixtures before the real hidden panel exists or is reachable.

**Acceptance / change my mind:** expected rejection/acceptance for every included calibration, with zero unexplained mismatches. Source: calibration truth and both raw verifier outputs, C1 subset/C2 all. An alternative equally discriminating control may replace one before seal.

## K.17 — Minimum honest PILOT seal: one worker, one scored case

**Claim:** A single process-crash case can test the missing-receipt gap without implying full autonomy. **Evidence/reasoning:** M:44; V1:4.2; B.14; F5. **Confidence: high in narrow relevance; readiness Unproven.**

Build K.2–K.10, the pilot portions of K.12–K.14 and K.16, and K.13's seal with worker B explicitly absent. K.7 holds only the synthetic pilot input and fixture chain/store, not a claimed whole-corpus snapshot. K.9 holds one hidden fault hook. No model, router, genetics, vector index or ingestion trainer is required. Do not bypass observer, custody, broken-control calibration, or destination oracle to make the pilot smaller.

Case: admit one immutable ledger-insert intent; receiver atomically commits effect plus operation dedup; controller kills the worker before the response; restarted worker retries the same operation ID; receiver returns the original result; verifier checks one admission, at least two delivery attempts, **exactly one canonical ledger effect**, matching intent/result digests and correct final disposition. The observer proves which boundary was actually hit. Required public calibrations include broken dedup, same-ID conflict, revoked scope, stale owner and meter loss; they are not extra scored pilot cases.

Supported only if every sealed predicate and applicable calibration passes. Any duplicate, unauthorized or falsely successful effect disputes the implementation. Missing boundary evidence or no execution leaves it Unproven. **Source / check-date:** frozen receiver ledger, controller trace, observer data and pre-reveal single-worker verdict, C1. This pilot does not support filesystem power-loss recovery, the chain adapter, two-worker independence, eight-way throughput, genetics, corpus coverage, or attribution sensitivity.

## K.18 — Full schedule and scope must remain explicit

**Claim:** Downscaling is allowed before seal; relabeling a small run as the original full rehearsal is not. **Evidence/reasoning:** H3.3–H3.5 and F1.

The inherited full schedule is 16 scenario episodes per worker (32 total), plus 1,500 fault-target trials per worker (3,000 total): concurrency 1/2/8 × five boundaries ×100, with 50 dedup and 50 unreconcilable targets per cell. One target plus c−1 backgrounds gives 11,000 logical matrix operations across both workers. Retries add attempts. Run clone A and clone B sequentially so the global cap remains eight. If preflight admits only 1/2, write a new smaller profile and retain eight-way feasibility Unproven; do not report 3,000 trials as completed. These fixtures establish protocol behavior, not statistical reliability from 3,000 independent systems.

The separate genetics, routing, corpus-latency, memory-usefulness and ingestion studies keep distinct manifests, time budgets and verdicts. Full HOLD fixture validity does not establish their performance claims. Ingestion uses I.1–I.9's 60 adapters/512 outputs, subject to its own preflight; this workload is not hidden inside “one case.”

**Acceptance / change my mind:** exact enrolled/completed/aborted counts, workload duration and cost meter totals match the admitted profile at C2. Missing capacity or runtime evidence blocks that profile; a counterexample blocks its build even when the remaining cases pass.
