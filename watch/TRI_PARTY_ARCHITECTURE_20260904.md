## THE MONITOR PATTERN (the new organ — done honestly)

The harvester browses and NARRATES VERBOSELY: every snapshot, every scroll, written raw to
a narration file (the "unstructured BS" stream). A second agent — the MONITOR — reads the
stream and does exactly three things, tri-state:
1. FLAG: "this fragment is signal for arc X" (names the arc, cites the fragment).
2. HARVEST: extracts URL + verbatim text into the intake batch file.
3. STEER: tells the harvester what to browse next (the steering-signal loop).
Guard (Desk law): the monitor's flags are claims with citations to the narration file —
a monitor that flags without quoting the stream is a rubber stamp and gets replaced.

## THE DRIVER'S DECISION GRAMMAR (formalized — this is the "next steps" after rubric)
Per scored item, the driver picks exactly one:
- **DIG** — spawn a deep pass (thread archaeology, repo probe). For BUILD-NOW candidates needing facts.
- **FILE** — register + move on. For REMEMBER-band items (the shelf grows, nothing blocks).
- **MOVE** — skip, tagged WHY (one line). Moves are data: the skip-log trains future scouting.
- **BUILD** — spawn a builder with kill conditions. For BUILD NOWs that survived triage.
