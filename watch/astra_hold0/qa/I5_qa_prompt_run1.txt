## 5. THE EVIDENCE SHAPE (terminal detection — checkable by form)

The answer is an ADJUDICATION LEDGER. Each claim gets one row of exactly this
schema (lists may be empty; no field may be absent):

```json
{"claim_id": "C1", "verdict": "SUPPORTED|DISPUTED|UNPROVEN",
 "witness_ids": ["..."], "ranks": [1|2|3|4, ...],
 "independent_pairs": [["W_", "W_"]],
 "dependent_witnesses": ["W_"],
 "invalid_witnesses": ["W_"],
 "stake_weight": 0,
 "rule_clause": "PROMOTION|DEMOTION|PRECEDENCE|TIE|INDEPENDENCE|STAKE",
 "grounds": "one line"}
```

The answer card MUST contain, in order:

1. **Canonical restatement:** claim-set id, RULE CARD version (I5-RC-v1),
   exhibit manifest counts received (fleet arm: partition counts; full-view:
   11), as-of stamp (2026-09-11) — inputs as-run.
2. **The six adjudication rows** (fleet arm: two provisional ledgers, then the
   joint ledger over the union; scoring runs on the joint ledger; the fold is
   the same rule re-run over unioned witness inventories).
3. **CAMP STATE blob** (`decided / open / next`, one line each).
4. **FAILURE RECEIPT (conditional):** on stall/refusal/overrun/tool/transport
   failure the card still ships: failure class (`STALL · REFUSAL · OVERRUN ·
   TOOL_FAIL · MALFORMED · TRANSPORT`), what was attempted, the last usable
   state, and the usable work that exists.

`TERMINAL?(answer)` = restatement present with all four fields + six
schema-valid rows (or the joint pair) + CAMP STATE blob. Anything else is
non-terminal, returned for shape repair per the desk checklist — never
silently healed into the denominator.
