WHAT IT DOES
This is a runbook, not code: it pins the procedure for renting one vast.ai 3090 box and self-hosting GLM-5.3-Flash as UD-IQ3_XXS GGUF via ollama, gated by an ssh6.vast.ai reachability probe. A detached `seeker.py` loop (verified present at `state/vast/seeker.py`, alongside `box_contract.sh` and `launch_vast.py`) acquires the box automatically; on health OK, `scripts/council_runner.py` and `scripts/steering_suite.py` run the evaluation battery over an ssh tunnel.

DESIGN PATTERNS (named from the file)
1. Contract-as-artifact / self-provisioning boot: `box_contract.sh` v2.1 runs as onstart and self-reports via `status.json` heartbeat on port 8001.
2. Blocklist memoization: known-bad machines persist in `state/vast/blocked_machines.json`; successes in `reachable_machines.json`.
3. Fallback ladder: quant downgrade (UD-Q2_K_XL), RAM-only residency, hosted model as last resort.

RISKS
SPOF: one seeker process, single endpoint file `brain_v2_endpoint.txt` — its death strands the runbook at step 2 with no recovery path. Hidden shared-state mutation: seeker silently writes the endpoint and whitelist files other steps consume. Duplicate scheduler: nothing locks seeker; "ONE instance max" is prose only — a second window re-runs it, double-probing at ~$0.03 each.
