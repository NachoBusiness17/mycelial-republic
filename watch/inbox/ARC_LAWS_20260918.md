# ARC LAWS — tombstone GC boundary + DISTINGUISH schema (2026-09-18)

Two laws from the DeepSeek adversarial arc, drafted for operator gate. Neither touches
the amendment ledger directly; the ledger is human-only (the arc validated that
invariant even while calling it the bottleneck).

## LAW: THE CHAIN NEVER ENTERS ACTIVE CONTEXT UN-PRUNED (ADV-I-5)

The verkle chain is the archive. It is correct as an archive and poison as a context.
Retraction in an append-only log adds a meta-belief (believed-then-rejected) that is
strictly noisier than never believing; loading raw chain rows re-poisons every read.
AGM K*2 formalizes it; the entropy cost is ~0.69 bits per retraction (C01, burn receipt).

The boundary, three stores:
1. ARCHIVE (chain, trails): append-only, immutable, never deleted, never loaded raw.
2. ACTIVE VIEW (context packs, boot packs): compiled, pruned, the only thing agents see.
   Retracted/superseded claims are excluded here; a tombstone sidecar (bloom filter of
   retracted row hashes) is consulted at pack compile; the precedent-of-error (what was
   believed, what killed it, what it cost, compressed) is the ONLY retracted material
   that may appear, priced as fragility weighting.
3. WORKING (runner_state, queues): fully mutable, forgetful, tracks what REMAINS.

Enforcement (ordinary code, A3-clean):
- The G02 race is real: our pack watermark (last pruned row) must be committed in the
  same transaction as the pack write, or a crash re-injects pruned rows. Fix owed in
  the pack builder.
- Audit query: any pack artifact containing a row hash that the tombstone sidecar
  knows is retracted = violation row, alarm.
- Law text for the ledger when the operator gates it: "The archive remembers; the
  active view is innocent; the tombstone stands between them; the precedent of error
  is the only ghost allowed in the machine."

## SCHEMA: DISTINGUISH (ADV-I-6), draft for the amendment ledger

Current amendment row: {id, date, law, status, receipt_hash}. Binary keep/kill.
DISTINGUISH adds the third move: narrow a law's applicability to a fact-pattern
without retracting it. Common law survived centuries by accumulating distinctions,
not overrules.

Row schema:
- id: D-<seq>
- date
- target: <law id or amendment id being distinguished>
- dimension: the axis of distinction (one of a controlled vocabulary, extensible by
  operator gate only): lane | environment | scale | time-window | stake-class | actor
- predicate: the fact-pattern that bounds applicability, stated as ordinary code
  (deterministic, A3-clean), e.g. "status == 'night' AND lane == 'harvest'"
- branch: what applies inside the predicate (narrowed reading, or pointer to a fork)
- remainder: what applies outside it (default: unchanged original law)
- receipt_hash: the evidence that motivated the distinction
- conflict_rule: two DISTINGUISHes on the same target resolve narrowest-predicate-wins;
  equal specificity resolves by operator gate (never by model vote)

Fleet landing: registry tombstones (Desk/AOS steal) already do lifecycle narrowing for
tools; DISTINGUISH generalizes it to laws. Build order: schema first, writer second,
and the DISTINGUISH-writer itself is deterministic code over a proposal row the
operator files, never an autonomous amendment path.
