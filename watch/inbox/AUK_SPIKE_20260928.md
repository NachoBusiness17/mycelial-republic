# AUK SPIKE 2026-09-28 — Tencent AuK Voice Model

## What AuK Is
Tencent Hunyuan open-sourced AuK (Sep 7-9, 2026): a 1.5B-parameter foundation model for speech generation and editing, plus a distilled sibling AuK-Flash. Both MIT-licensed, weights on HuggingFace (tencent/AuK, tencent/AuK-Flash) and ModelScope (Tencent-Hunyuan). Paper: arXiv:2609.08936.

## Params & Architecture
- Backbone: hybrid rectified-flow Transformer, 30 layers (10 dual-stream MMDiT + 20 single-stream DiT), hidden 1536, 24 heads dim-64, SwiGLU intermediate 3072 → ~1.5B
- Separate runtime components (not in the 1.5B count):
  - Qwen/Qwen2.5-Omni-3B MLLM encoder (text + reference-audio semantic conditioning)
  - BigVGANFlowVAE causal 24kHz audio VAE, 64-dim latents @ 50Hz frame rate
- Checkpoint sizes: auk_base.safetensors 6.12GB + vae.safetensors 637MB (~6.8GB total)
- AuK-Flash: 4-step distilled, no CFG, 4.5x wall-clock speedup over base, near-teacher quality (Seed-TTS-Eval 2.85 WER, 0.790 similarity)

## License
MIT — both weights and code. Permissive; no cost, no attribution-heavy chain.

## VRAM (Unpublished — Honest Gap)
- No inference VRAM figure published anywhere (model card, README, paper all silent)
- Training config notes gradient-checkpointing peak ~91GB → ~75GB (training only, not inference)
- Computed floor: weights ~6.8GB loaded + activations/caches/Audio buffers
- Sensible inference starting point: 24GB GPU single card; config shows both AuK+Flash can share one GPU but references two-GPU spread
- Qwen2.5-Omni-3B encoder adds ~6GB (loaded separately at runtime)

## Task Surface (single natural-language instruction interface)
- Speech generation: zero-shot TTS, instruct TTS (voice from description, no reference)
- Content editing: replace/insert/remove words, lyric editing (preserve melody+voice)
- Acoustic editing: pitch (semitones), speed, volume (dB)
- Paralinguistic editing: emotion, timbre, de-accent, breaths/laughs/coughs, whisper conversion
- Enhancement/separation: denoise, dereverb, speech separation, music/vocal separation, target speaker extraction

## Integration Shape for Mountain NPC Gateway (tools/roblox_npc_gateway.py)

Current gateway: Roblox `NpcGateway.luau` POSTs `{head, player, message, room}` → free LLM lanes (openrouter/nous, stealth/space-bunny-alpha) → text reply.

AuK extension for Mountain NPC voice:
1. **New POST fields**: `voice_ref` (base64 audio or HuggingFace file URL), `voice_task` (enum: tts|edit_content|edit_acoustic|edit_paralinguistic|enhance|separate)
2. **AuK-Flash as audio lane**: after LLM generates the text reply, gateway calls AuK-Flash locally to render it as speech — either in the reference voice (if voice_ref provided) or a default NPC voice
3. **Runtime deps**: `tencent/AuK-Flash` weights (~6.1GB) + `Qwen/Qwen2.5-Omni-3B` encoder (~3B) + BigVGANFlowVAE — all downloadable via `hf download`
4. **Gateway code change**: add `_auk_lane()` in `ask_lane()` fallthrough — if `voice_task` present and AuK weights local, call AuK-Flash inference CLI; else fall through to existing text-only reply
5. **Audio output**: return `{"reply": text, "audio": base64_pcm_24k}` or stream WAV file — Roblox Luau can play via `Sound` object from bytes
6. **VRAM budget**: single 24GB GPU for AuK-Flash + encoder; gateway stays on CPU for LLM, GPU for audio render

## Falsifiable Go/No-Go

| # | Claim to falsify | Threshold | How to test |
|---|---|---|---|
| G1 | AuK-Flash 4-step inference renders 24kHz audio in <2s on single 24GB GPU | latency ≤2s per clip | `hf download tencent/AuK-Flash`, run CLI gen, time it |
| G2 | Voice cloning from reference audio preserves speaker identity >70% similarity | similarity ≥0.70 | Seed-TTS-Eval or manual MOS with 5 listeners |
| G3 | Gateway integration adds <200ms overhead to existing text reply | end-to-end ≤2.2s | Benchmark gateway POST with/without voice_task |
| G4 | MIT license allows fleet commercial use without attribution chain | legal OK | Attorney check or confirm MIT terms cover fleet ops |
| N1 | VRAM exceeds 24GB single GPU for AuK-Flash + encoder | VRAM ≤24GB | `nvidia-smi` during inference, peak measurement |
| N2 | AuK-Flash quality below usable (WER >15% on clean speech) | WER ≤15% | Seed-TTS-Eval on clean test set |

**Go condition**: G1, G2, G3, G4 all pass, N1/N2 both fail (i.e., fits 24GB and quality acceptable). **No-Go**: any G-fails or N1 passes (out of VRAM).

## Verdict (spike — not yet tested)
AuK-Flash is the right shape for Mountain NPC voice: MIT-licensed, 4-step fast, single interface, speech editing built in. The VRAM gap is the unknown — needs a real run on the box's GPU to confirm fit. Do not build until G1/G4 pass and N1 is measured.
