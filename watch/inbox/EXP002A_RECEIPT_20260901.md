> **[AUDIT-TYPED 2026-09-08]** status: LIVE · claims: an append-only event log + derived fold eliminates lost-update races on INDEX.json — SUPPORTED (as-built verify 26 hash-clean, race-kill sequence, nonce-gap warning proof in card) · falsifier: a folded INDEX.json losing an appended entry, or verify reporting a hash mismatch on an active item

## Problem fixed

`/board/inbox/INDEX.json` was clobbered 2026-09-01 ~02:36Z (and historically) because
writers did read-modify-WRITE on the whole file. Two concurrent writers both read the
same snapshot, each wrote back its own copy, and the last writer silently erased the
other's entries — the classic lost-update race.

Ethereum's answer is a structurally different write path: **append-only transaction log
+ fold**. Writers never rewrite the canonical index; they *append* a single immutable
event line atomically (`>>`). The index is *derived* by folding the log, so nothing can be
lost to interleaved writers — every append survives.

## What was built

### 1. `/board/inbox/index_events.jsonl` — the append-only source of truth
Never rewritten, never deleted. Every change is one appended JSON line.
- Seeded with one `register` event per existing INDEX item (26), derived from the
  current `items[]` array.
- Plus one `{op:"note"}` genesis marker: `exp002a genesis - event log becomes source of truth`.

### 2. `/root/.openclaw/workspace-worker/index_fold.mjs` — the fold tool
| command | effect |
|---|---|
| `node index_fold.mjs rebuild` | Fold ALL events -> rewrite `INDEX.json` items (schema `shared_inbox.v1`, sorted by `seq`) |
| `node index_fold.mjs add <file> [class] [purpose]` | Append a `register` event + refold |
| `node index_fold.mjs invalidate <file> [reason]` | Append an `invalidate` event + refold (history kept) |
| `node index_fold.mjs verify` | Re-hash every active item's file vs the event log |

**Every appender must APPEND (`>>`), never rewrite the events file.** The fold writes
INDEX.json atomically via write-then-`rename()`, and only the fold touches INDEX.json.

**Replay protection:** each `add`/`invalidate` carries a per-writer `{writer, nonce}`
field. The fold tracks last-seen nonce per writer and **warns on any nonce gap** — the
signal that a concurrent writer interleaved or a nonce was skipped.
