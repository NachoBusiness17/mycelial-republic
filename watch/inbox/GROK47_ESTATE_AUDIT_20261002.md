## 1. Bug hunt — five patterns that actually take production down

**1. Torn JSONL lines treated as records.** A writer does `open(..., "a").write(json.dumps(obj) + "\n")` without a lock, flush, or single-writer rule. A crash or a second writer splits a line. The reader `json.loads`s every line and either dies or, worse, skips bad lines and silently drops the newest event. Detection: concurrent-append test (two processes, 10k lines, then parse); kill -9 mid-write and parse; flag any reader with `except: continue` and no corrupt-line counter. Also flag `write` without a trailing newline guarantee, and Windows opens that are not exclusive-append.

**2. Scheduler cwd and clock are not the dev machine’s.** Task Scheduler and cron do not start in the repo. Relative paths, unactivated venvs, and `datetime.now()` without a timezone break the first night. DST makes a 02:00 job skip or run twice. Detection: inventory every path in task definitions; fail the build if any are relative; run the task once under the service account with cwd set to `System32` or `/`; grep for `datetime.now()`, `datetime.utcnow()`, and naive/aware compares. Require a monotonic deadline for “run every N seconds” loops, not `time.sleep` plus wall clock.

**3. Success is recorded before the work commits.** The ledger appends `{"status":"ok"}` and the scheduler marks the task complete, then the HTTP handler, file rename, or subprocess fails. Retries double-apply, or nothing retries because the receipt already says done. Detection: look for ledger writes that precede the side effect, missing idempotency keys, and `except Exception` that still appends success. Fault-inject a failure after the receipt write and see if the next run is a no-op.

**4. The HTTP handler does unbounded synchronous work.** A request triggers a full ledger scan, a PowerShell subprocess, or `json.loads` on an unlimited body, on the request thread, with no read timeout and no body cap. One client stalls the process; a partial last line in the ledger becomes a 500 on every poll. Detection: grep handlers for ledger scans and `subprocess` with no timeout; check for missing body-size limits and for `debug=True`. Replay a truncated final JSONL line and a slow client.

**5. Encoding and lock leaks on Windows, invisible in CI.** PowerShell `Out-File` defaults to UTF-16. A Linux CI run never sees it. An unclosed handle on Windows makes the next scheduled run fail with a sharing violation, which a bare `except` turns into a green exit code. Detection: assert UTF-8 on every ledger read; run the scheduled path on Windows, not only in CI; flag bare `except`, `except Exception: pass`, and opens outside `with`. Treat any non-zero child exit as failure, including PowerShell’s, which is easy to drop if you only check that the process started.

## 2. Claim audit — five unverifiable-receipt patterns

**1. The receipt is the only evidence.** “Verified”, “tests passed”, “audited” with no command, exit code, artifact hash, or log line outside the receipt. Detection: schema-require `evidence_ref` that resolves to something the model did not write (tool trace, file hash, CI id). If the evidence graph is closed over model text, the claim is unverifiable. Do not score it as false; score it as unearned.

**2. Universal quantifiers over an unenumerated corpus.** “No bugs in 20+ tools”, “all tasks healthy”, “ledger is consistent”. Detection: reject `all|none|every|no bugs|production-ready` unless the receipt lists the exact file set, the check, and the negative-evidence procedure. Compare that set to `git ls-files`. A mismatch is inflation, not a style issue.

**3. Phantom anchors.** Paths, line numbers, function names, or SHAs that do not exist or do not contain the quoted behavior. Detection: resolve every path; hash-pin every cited snippet; fail if the line range’s hash does not match. A line number without a content hash is not an anchor.

**4. Model-minted timestamps and identities.** `observed_at` and `verified_by` are generated by the model, not taken from the filesystem, the OS clock, or a tool trace. Detection: join claimed times to mtime, git history, and process logs. If the only copy of the timestamp is inside the receipt, drop it. Same for “agent B confirmed” when B’s only input was A’s receipt.

**5. Canary blindness.** The estate can contain a known defect or a known false sentence, and a receipt still says clean or confirmed. That is the mechanical test. Plant one broken JSONL line, one relative path, one false claim. A receipt that does not name the canary did not inspect the thing it claims to have inspected. I would trust that test over any wording score.

Hedged language that a later summarizer promotes to “confirmed” is the same family: diff the receipt against the raw tool trace and flag certainty that was not in the trace.

## 3. Security — three issues, in the order you named them

These are vulnerability classes and impacts, plus what to check. Not exploit procedures.

**(a) Shared JSONL ledgers are not an audit log under concurrent multi-agent writes.** Two failures stack. Integrity: torn and interleaved lines, and any agent that can append can forge history. Trust: later agents that read the ledger treat forged or hallucinated lines as ground truth, so one bad record poisons every downstream receipt. Detection: prove single-writer or OS-level exclusive append; require per-record hashes chained to an external anchor you recompute; alert on lines that fail to parse. A ledger agents both write and believe is a shared prompt surface, not a source of truth.

**(b) Import-time dotenv puts the OpenRouter key in the wrong lifetime and the wrong places.** The secret lands in `os.environ` for every importer, is inherited by PowerShell children, and can show up in tracebacks, debug handlers, and crash dumps if anything interpolates the environment into an error. The `.env` file is often committed or readable by every account that can run the task. Detection: grep for module-level `load_dotenv` and any log or exception path that prints `environ`; check file ACLs and git history for the key file; confirm child processes do not receive the key unless they need it. Load lazily, restrict ACLs, scrub errors, prefer a secret store. I am not going to describe extraction.

**(c) Scheduled PowerShell with relative paths runs as the task identity in a cwd you do not control.** The usual cwd is not the repo. Relative script, module, and binary paths resolve somewhere else. If that directory is writable by a weaker user and the task is elevated, this is unintended code execution under the task account, not just a file-not-found bug. Detection: dump the task definition (action path, start-in, principal); fail if the action or any script it calls is relative; confirm start-in is an absolute, non-writable-by-others directory; confirm the principal is not broader than the job needs. Fix is absolute paths, an explicit working directory, and a least-privilege account.

## 4. Consensus-illusion — the part that is easy to miss

Agreement between your agents is evidence that they share a context, not evidence that the claim is true. I am not aware of a settled detector I can cite by title, and I will not invent one. The classical point that does transfer is the Condorcet jury theorem: majority voting helps only if votes are independent and better than chance. Same-model agents, especially at temperature 0, reading a shared ledger, are one sample and N−1 echoes. Counting their votes double-counts.

The check I would actually run:

Hide the ledger and shuffle speak order. Re-run the committee. If the conclusion and the wording hold only when later agents can read earlier receipts, you measured an echo, not a quorum. If it still holds when they are isolated, demand that each agent cite a distinct external artifact you can recompute (file hash, command output, canary). Identical wording plus identical citations plus a shared ledger is one measurement.

Two related tells. First, the base rate of “yes, I verified” in model text is high whether or not a tool ran, so an AI receipt alone barely moves the probability; a fresh canary or a re-executable command does. Second, once receipts are written back into the ledger that the next agent reads, consensus and ledger integrity are the same bug: a single unverified line becomes the premise everyone agrees on.
