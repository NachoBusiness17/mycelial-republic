## The law (filed beside the other laws)

One key, one name, one loader. A provider key's env name is declared exactly once — in its provider block's api_key_env field in configs/providers.yaml (a string, or a list only for genuinely distinct accounts of the same vendor, where _2/_3 suffixes are the only permitted variation and match the .env line names exactly) — and spelled identically on its .env line. models/env_load.py is the only .env parser and, over models/providers.py's manifest read, the only key resolver in the estate: no lane, registry, probe, guard, recorder, doctor, dashboard, or script may carry its own key-name list, alias, fallback spelling, hardcoded alternate, or private .env scrape. A declared-but-empty name is surfaced as empty — never silently dropped — and any component that reports a key missing must print the exact env name it looked under. Env names match [A-Z_][A-Z0-9_]*: no hyphens, no case games. Names do not live in comments; a comment naming a key's location is stale the day it is written. Adding a second name for an existing key is a bug, not a fix: rename the .env line, do not grow a list. A lane-referenced provider whose manifest name is absent or empty in .env is a loud, boot-visible failure with the offending name in the message; a key-shaped line in .env that no declaration references is a warning the operator resolves, not parks. Two .env parsers may not coexist. Falsifier: any diff that adds a second field spelling (api_key_envs), a second name for an existing account, a key lookup outside env_load/providers, or a key name that exists only in a comment fails review on sight.
