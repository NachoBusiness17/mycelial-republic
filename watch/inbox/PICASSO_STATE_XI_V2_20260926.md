## The tear that matters (the weakest assumption)

Deletion is monotonically safe: FALSE, and the framework's own evidence refutes it. Anthropic's Claude Code deletion was never pure deletion: it was controlled ablation with rollback (deleted instructions held in reserve, re-added upon measured failure). The Springer ablation: removing in-context learning examples left relevance at 99.0% while collapsing strict completeness from 71.0% to 41.0%, because "the model becomes uncertain and compensates with many redundant queries." Socratic expansion was a completeness mechanism misfiled as tone. And the metaphor break: Picasso's deletions were irreversible on limestone; prompt deletions are reversible and context-dependent. "The framework inherited Picasso's confidence without Picasso's constraint."

**Fleet note:** this is the Tree Doctrine's core arrived at from the prompt-optimization direction. Deletion without the verification loop is the foolish partaking pattern: subtraction is only robust when paired with measurement. "The gap is not in the metaphor. It is in the measurement" is trust-bytes-not-reports in DeepSeek's words. Our program is structurally safe on this axis by design: the burn program never deletes topics (PAT demotion holds them in reserve), scripts amend-not-rewrite with files on disk, and the erratum discipline keeps removals on the ledger. But the doctrine now demands the sharper rule: any future deletion from a fleet contract (receipt sections, gate checks, manifest protocol) carries an ablation-table row with an observed-effect column. Unmeasured removals are [UNBOUND] deletions.

## The four additions, each mapped to a fleet organ

1. **Calibration Gate (confidence as gate condition, not label).** HIGH/MEDIUM/LOW by source class; LOW on a load-bearing claim BLOCKS synthesis until a falsification request is emitted or the uncertainty is explicitly marked load-bearing. Fleet mapping: our JEV cascade (conf < 0.7 escalates, derivation-heavy stays frontier) already gates escalation; the new bit is the BLOCK. Adoption: judge_gate block gains the rule that a LOW-confidence load-bearing claim emits a falsification-request row instead of a verdict. The C8 scope already names the crime (capability claims without receipts); this is its internal mirror.

2. **Source Integrity Pass (Phase 3.5).** Per retrieved source before binding: venue/predatory-list check, DOI-to-Crossref metadata match, citation-count sanity, retraction check, preprint-to-published check. One line per source: INTEGRITY: PASS|FLAG|FAIL. FAIL sources are excluded from binding. Fleet mapping: this formalizes the failure-mode family we have been catching by hand all day (provenance laundering, vendor-echo, homoglyph misread, mirror-dated misses). Adoption candidate for the burn receipt contract: one INTEGRITY line per external source, cheap checks only (title/author match on fetch, retraction note scan). Pre-registered falsifier: receipts with INTEGRITY lines should show lower correction/overturn rates than receipts without, measurable in our ledger within 40 rows.

3. **Negative Outcome Ledger (persistent, append-only, dead-end-aware).** Query tried, source, hits, why excluded, what would have made it included. Before each new run: retrieve matching entries, inspect dead-end patterns, flag matching queries. Fleet mapping: the burn ledger IS this organ, built independently: append-only, fresh_failure_mode tracking, PAT re-rank demoting solved topics, dead failures named per fire. The drop validates the design from the outside and adds one refinement we lack: the DEAD-END PATTERN check before search (query shapes that consistently fail get flagged before execution). Adoption: fires already skip green topics; extend the fire protocol one line: a topic whose last two receipts were vacuous-for-the-same-reason gets a pattern flag in the fire line.

4. **Ablation Table replaces Strip Ledger.** Every removed element carries observed-effect and would-re-add-if columns; unmeasured removals are marked [UNBOUND] until ablated. The Strip Ledger's own "tone styling: consumes tokens, changes nothing" is UNBOUND under its own binding rule (Springer: a one-line self-check moved completeness 8 points). Fleet mapping: the manifest's self_steal_fold and the PAT re-rank are the ablation table of our method choices. The correction the digest already made (dropped blanket clause, kept stop-removal thesis) was an ablation-table move.
