## LANE F — AGENT COMMS + SHARED MEMORY ✅

## LANE E — SANDBOXES + PARALLEL SESSION SAFETY ✅

**THE ONE ACTION FOR TODAY: fence the WSL2 VM.** On Windows, the real resource fence is OUTSIDE docker — `.wslconfig` caps the whole WSL2 VM, and its default is **50% of host RAM** with no explicit cap. Setting `memory=`/`processors=`/`swap=`/`defaultVhdSize=` is the only knob that guarantees the operator's interactive Windows sessions survive an 8-wide fireball. Zero cost, do first — this is the sanctioned answer to the law-16 collision class.

**The isolation shape (all primary-verified):** the 2026 hosted pattern is microVM-per-agent with snapshot/restore — E2B ≈ **$0.17/agent-hour** (2 vCPU/4GiB, pause saves filesystem AND memory indefinitely, warm pool), Daytona snapshots <90ms, Codex Cloud = one isolated environment per task with diff+PR output. Firecracker = Linux-KVM only, NOT a Windows-local option. The sanctioned Windows stack: Windows → capped WSL2 VM → Docker → **Docker Sandboxes** (`sbx run`: microVM per agent, own daemon/filesystem/network, all egress through a host proxy with org policies; sbx CLI free). Anthropic's own Windows answer for agents: run inside WSL2 or a container.

**The documented holes (nobody's clean):** Claude Code sandbox is write-narrow/READ-BROAD — sandboxed commands get "read access to the entire computer" so `~/.aws/credentials` are readable by default unless `denyRead` is set; the egress proxy "does not terminate or inspect TLS" so Anthropic itself documents domain-fronting bypass; native Windows unsupported (Seatbelt/bubblewrap only). Git worktrees are now PRODUCTIZED (`claude --worktree`, blocks Edit/Write to main checkout, "you can't turn this off", `/batch` gives each subagent its own worktree + PR) — but worktrees fix FILE collisions only, not build-resource collisions (ports, DBs, node_modules storms — "your fireball's second half").
