## THE TORRENT-AS-MEMORY DESIGN (self-steal, grounded)

The idea is already banked: `docs/ref/MCP_EPISTEMIC_MESH_SPEC.md` (768
lines) opens with it - **"MCP servers become a distributed epistemic memory
layer: a mesh of openly accessible, typed knowledge and capability reservoirs
that agents can query, test, cite, and contribute back to under explicit
governance"** - and closes with the vision of **"a distributed cognitive
organism whose memory and capabilities can evolve without modifying the
underlying model weights."** The torrent framing is that spec's distribution
layer.

A torrent is three things, and the estate already builds all three:

| torrent anatomy | estate organ (shape) |
|---|---|
| content-addressed chunks | verkle knots + the percolator's content-hash invariants (THE LEDGER + THE COMPILER) |
| the .torrent manifest | MANIFEST.sha256 + delta_index pins + the horizon self-hash (THE PIN + THE BOUNDARY OBJECT) |
| seeds that stay up | the decaying capability manifest - ed25519-signed node advertisement re-signed every T hours with exponential trust decay to zero for silent nodes; the mesh audit ruled this "a PORT not a BUILD" because seed_seal.py already ships ed25519 signing |
| the reading client | an MCP server (gps_mcp and gstd_mcp are the precedents) exposing typed query/fetch/cite over the manifest |

## THE GUARDRAILS THAT MUST RIDE (the audit's own findings, same doc)

  probe - runnable on the estate's free lanes this week."
