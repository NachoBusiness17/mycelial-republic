## Thesis

Git answers "which bytes moved". The estate runs on four artifact classes whose MEANING lives above the bytes, and a byte diff actively lies about three of them: it screams on reflowed receipts whose claims did not move, shrugs on a 29-line Python edit that could be a comment pass or a behavior change, and cannot distinguish a lawful ledger append from a doctored history. A semantic diff is not one algorithm. It is a per-surface CONTRACT: a grammar to extract meaning, a key law to identity facts, a set of lawful change classes, and a fail-close rule for everything the grammar cannot parse. The pipeline is identical on all four surfaces: **extract -> key -> classify -> verdict**, with the estate's existing exit-code convention (0 lawful, 1 named drift, 2 cannot-verify).

The discovery of this pass: the estate already runs four half-instances of this design and the design is their generalization, not a foreign import. (1) `tools/census_drift_patrol.py` is a markdown CLAIM-grammar differ with fail-close (parse returns None -> exit 2, `parse_carrier` at `tools/census_drift_patrol.py:148-170`, claim regex at :117-119, B2-245 order-poisoning defense and B2-274 grammar-ownership law in the comments at :84-116). (2) `tools/violation_ratchet.py` is a verdict cache over semantic code changes: "only NEW violations fail... Debt that gets fixed leaves via prune, so the register trends down" (`tools/violation_ratchet.py:6-8`). (3) The FW-03 grounding verify (commit b34ccd3ba message) ran a ledger integrity check: "all 137 rows hash-faithful, none edited in place" -- that IS a JSONL prefix-invariant diff. (4) `roblox/src/shared/Flock.luau` carries a MECHANICS MANIFEST (named constants with provenance comments, :47-87) and `Q_032_flock_check_gen.py` pins the real module bytes by sha256 and refuses blind regeneration (`Q_032_flock_check_gen.py:76-77`, hashes at :81-83).

## 1. Markdown receipts: diff CLAIMS, not bytes

Receipts are claim-bearing prose with two load-bearing structures observed in Q-028.md: heading-carried status ("## FW-45 ... - LANDED + live-verified") and inline numeric receipts ("34 passed", "register now 941", "signatures_after 1421"). The grammar is: (a) status vocabulary {LANDED, EXECUTED, SUPERSEDED, ALREADY ABSORBED, OWED, VOID, REFUTED, diagnosis banked, plan-only}; (b) numeric claims (count + unit + optional receipt pointer); (c) path pointers (the `_REF_RE` class from mag/prose_census.py:55-56 already exists and even carries its own truncation-bug history). Key law: (heading id, claim ordinal) or, for single-carrier docs like AGENTS.md, the carrier line itself. Lawful classes: CLAIM_ADDED (new work), STATUS_ADVANCE (plan-only -> LANDED: the ratchet only turns one way), NUMBER_REFRESH (same claim, new byte truth, census-date bumped), REPHRASE (identical claim set, moved words). Unlawful classes, i.e. the fabrication taxonomy: **STATUS_FLIP** (LANDED -> OWED without a supersession pointer: the estate's own tombstone discipline says supersession is a record, not an edit), **NUMBER_SHRINK_UNNAMED** (a count drops with no receipt: the asymmetry the live collect_patrol encodes at census_drift_patrol.py:195-216, "an over-claim is worse (tests removed or a number invented)"), **CLAIM_LOSS** (a heading vanishes), **GRAMMAR_BREAK** (fail-close to exit 2, never guess: the parse_carrier law at :305-309).

Two pieces of literature land here. Myers' O(ND) diff (Algorithmica 1986) remains the correct layer-0 substrate: keep git for bytes, diff meaning above it. Winnowing (Schleimer, Wilkerson, Aiken, SIGMOD 2003) gives the claim-move detector: k-gram fingerprints per claim sentence, so a receipt that reorders its sections classifies REORDER (benign) rather than CLAIM_LOSS (fatal). And the Semantic Line Breaks convention (one clause per line) is worth adopting as an authoring law for machine-read receipts: it makes line diff approximate claim diff for free, which is exactly why the estate's JSONL ledgers are already line-oriented while its markdown receipts are not.

The census carrier is the proof of concept the estate already shipped: a reworded claim grammar must break the gate loudly (B2-249 "rewording the claim breaks the gate instead of silently rephrasing it"), and the ownership law B2-274 (census_drift_patrol.py:97-116) states the deeper principle: THE PARSER GRAMMAR IS OWNED BY THE REGEX + FROZEN VECTORS, and live carriers moving must not move the witnesses. Generalized: every markdown claim grammar needs frozen regression vectors, or the differ's own reword becomes invisible.

## 2. Python modules: diff a behavior fingerprint, classify by caller risk

The live result is the argument. `git diff --numstat` said 29/3 on mag/prose_census.py; the AST probe said: both versions have 2 functions, zero added/removed, `run_census` body changed, ZERO signature changes (no caller risk anywhere in the estate), and a literal-level delta that reproduces, item for item, the three fixes the code comments name with receipts (FW-07 mdx extension, FW-10 jsonl-before-json alternation order, FW-11 fence-owner marker + URL strip). A byte diff of 32 lines cannot tell you the change is (a) confined to one function, (b) signature-safe, (c) exactly the documented changelog. The AST diff can, in 40 lines of stdlib Python, no tree-sitter required.

Change classes, from cheapest to most expensive to verify: `SEMANTICALLY_IDENTICAL` (same ast.dump up to alpha-rename/formatting: format-only passes classify free), `CONSTANT_FLIP_ONLY` (same shape, different literals: this is ratchet territory, a flipped threshold in a tools/ gate script is exactly the debt class violation_ratchet requires to be accepted BY NAME, :6-8), `BODY_CHANGED` (behavior candidate), `SIGNATURE_CHANGED` (caller risk: requires the import graph, the one step above what the probe does), `API_SURFACE_CHANGE` (added/removed functions). This taxonomy is the estate-sized version of ChangeDistiller's change-type classification (Fluri et al., IEEE TSE 2007, tree edit distance on ASTs mapped to high-level change types) and GumTree's fine-grained AST matching (Falleri et al., FSE 2014); difftastic (Hughes, 2021) and tree-sitter (Brunsfeld) are the production-grade substrates if the estate ever needs multi-language coverage. But the sharpest anchor is the equivalence-testing school (equivalence-modulo-inputs compiler testing, mid-2010s): semantic diff's real job is BUDGETING, deciding where expensive behavioral evidence must be spent. `SEMANTICALLY_IDENTICAL` and `CONSTANT_FLIP_ONLY` need no test run; `BODY_CHANGED` demands one; the estate's pre-push already has the test machinery, it just has no machine telling it WHICH files changed in meaning rather than in bytes.

## 3. JSONL ledgers: diff the FACT SET under the ledger's DECLARED key law

The v1 probe failure is the finding. Keyed on slug, LEDGER.jsonl HEAD vs worktree read as "0 appends, 21 duplicate slugs, common-key order not preserved" -- three red flags on a perfectly lawful write. Keyed on position, the same delta reads clean: 654 prefix rows byte-identical, 39 tail appends, every appended slug a re-verdict of a slug already in history (re-verdicts ARE the ledger's point: verdict vocabulary {steal, green, built, vacuous} evolves per slug over time). Lesson one: **the key law is part of the artifact, not of the differ**. burn LEDGER = positional append; `watch/inbox/LINKS.jsonl` is content-keyed (rows carry `canonical_sha256` + `duplicate_of`, per the FW-45 section of Q-028.md, which a byte diff cannot see); `memory/workflows/REGISTRY.jsonl` is keyed by (name, digest) with a verdict field. A differ handed a ledger with no declared key law must exit 2, not pick one: that is the census-patrol fail-close convention applied to data.

Class taxonomy under a declared key law: `APPEND` (new tail rows: lawful everywhere), `PREFIX_MUTATION` (any history row changed at its index: THE fabrication class, the thing FW-03's "none edited in place" checked for, and what makes the ledger differ the estate's integrity instrument), `REORDER` (set-equal, position-changed: lawful only under compaction contracts), `DUPLICATE_KEY` (lawful for LEDGER re-verdicts, unlawful for LINKS), `UNPARSEABLE_ROW` (tail poison: exit 2 even though the bytes diff is clean). The two contracts in the literature are exactly these: append-only event sourcing (Fowler) where history is immutable, and Kafka-style log compaction where last-value-wins per key is the CONTRACT -- the same physical file under the wrong contract turns a lawful compaction into a fabrication charge and vice versa. Practical form: the differ stores a rolling sha256 of the frozen prefix (the Q_032 generator pattern: pin bytes, refuse blind rewrites), so the daily check is O(1) hash compare, and a hash mismatch enumerates the mutated indexes.

## 4. Lua game scripts: diff the MECHANICS MANIFEST, graded per constant

The port already contains its own semantic diff target. `roblox/src/shared/Flock.luau:47-87` is a manifest of named constants, each with provenance (`FLEE_SPEED = 26 -- orig 320 x SPEED_SCALE`, `DRAG = 0.985 -- verbatim, per 1/60s source frame`, `SCHOOL_RADIUS = 20 -- orig 155`). The commit 0f75d80c8 records the port law as "scale law documented one place: speeds x0.08 the player ratio, lengths tuned". I graded all 12 orig-referencing constants against their declared law: only 2 are exact scale (FLEE_FATIGUE_SLOPE 12.8 = 160x0.08, GRAVITY 11.2 = 140x0.08), 2 are rounded-to-integer scale (FLEE_SPEED 26 vs 25.6, FLEE_SPEED_MIN 11 vs 11.2), and 8 are hand-tuned at ratios from 0.13 to 0.25 -- including a ratio-keeper (FLEE_RADIUS_RAIN 10 preserves the source's 68/95 brave-in-rain ratio, :51) that NO single global scale factor can express. So the real port law is a four-class taxonomy: SCALED_EXACT, SCALED_ROUNDED, TUNED, VERBATIM (+ a RATIO_OF-sibling relation). That is the design: **each constant declares its law class; the semantic diff re-grades the manifest; a value change inside a class is TUNING (log it), a class change is MECHANICS_CHANGE (spec first, per build discipline), and integer constants near caps are the alarm class (POP_CAP 45, TRAIL_CAP 140: the Q-032 pass itself caught a real "cap off-by-one" mid-check)**. Byte diff sees "20 -> 21"; the manifest diff sees CAP_CLASS delta on a population law.

Two more mechanics layers sit above constants: composition order (the commit calls "the source's exact composition order" load-bearing; a reordered update pipeline is ORDER_FLIP even with zero constant changes) and frame normalization algebra (Flock.luau:12-13 documents `0.985` per source frame normalized as `0.985^(60*dt)`; a naive port writing plain `0.985*dt` would byte-diff clean and change the physics). The estate's substrate for executable truth already exists: `tools/luau_lint.py` does structural headless checks with named disease tripwires (poll disease t56, RMW disease t74, :1-14), and `Q_032_flock_check_gen.py` embeds the REAL module into the check, pins both sha256s, refuses to regenerate without the checks body marker (:19, :76-77), and I re-ran the committed suite live this session: 37 passed, 0 failed. The semantic diff for Lua is therefore: manifest extraction -> per-constant law grading -> order diff -> regenerate-and-rerun the sha-pinned executable checks, which the generator's own docstring already mandates after any module edit.

## The unified verdict vocabulary and where it hooks

All four grammars share the exit-code contract the census patrol fixed: 0 = meaning preserved or change lawful-by-class, 1 = named drift (the drift is printed with the delta, never just a count: B2-216's "name the delta" law), 2 = cannot verify (grammar break, undeclared key law, unparseable row: fail-close, never guess). Asymmetry is inherited from collect_patrol: over-claims are the worse direction everywhere (invented numbers in receipts, population caps that shrink, histories that silently reorder). Hook points are the ones the estate already gates: githooks/pre-push (alongside the ratchet and the scenario suite) for py/jsonl, the daily patrol cadence for AGENTS.md carriers, and day-end pile for receipt directories. The verdict cache should be a ledger of its own (append-only, slug-keyed, the LEDGER.jsonl shape), so the differ's own history is subject to its own prefix law.
