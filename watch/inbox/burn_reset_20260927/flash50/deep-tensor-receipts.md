## 1. Diagnosis: the estate already has a scattered tensor, not a flat one

The premise "receipts are currently flat" is only half true, and the half-truth matters for design. Measured across the three real carriers, relationships are already recorded, but they are recorded FIVE different ways with five different readers and zero shared query surface:

- C1, the hash chain: every grounding-wave row carries `prev` (`mag/grounding_wave.py:113-126`, `_V1_KEYS` through `_KIND_KEYS`), a built-in order-2 relation PREV.
- C2, the act rows: `kind:"witness"` rows carry `signs -> target hash`, `kind:"void"` rows carry `voids -> target hash`, `kind:"contest"` rows carry `contests -> target hash` (`_KIND_KEYS`, `mag/grounding_wave.py:119-126`). My probe counted 10 such directed edges over 137 rows with perfect referential integrity. This is a genuine typed edge list, materialized inside the same tape as the claims.
- C3, the set-once pointer: `superseded_by` in the Republic letters, write-once, re-pointing refused at save time (`mag/republic.py:114`, guard at `:209-218`), plus `in_reply_to`, `forwarded_from`, and cross-graph `dag_refs` (`mag/republic.py:109-117`).
- C4, the prose pointers: backtick file paths, commit hashes, and "per Q-039 precedent" phrases inside receipt markdown. Q-028.md carries 44 of them; 32 of 49 queue receipts carry commit-hash references. Machine-unreadable, human-parsed, LLM-parsed-on-each-read (the context tax, paid over and over).
- C5, the implicit chain: the burns ledger re-posts a slug with no pointer at all. 223 of 693 rows re-use one of 470 slugs (probe section 1); the fact that row 687 of `free-resource-landscape` supersedes row 651 of the same slug is recoverable only by sorting on `(slug, ts)` in the reader's head.

So tensor receipts are not an invention, they are a MATERIALIZATION: one address space, one edge grammar, one query layer, replacing five partial encodings. The design constraint that follows: the estate's existing relation carriers must become VIEWS over the tensor (C2 and C3 should be derived from or admitted through it), never a sixth parallel encoding beside it.

## 2. The tensor dimensions (question 1)

The naive answer is a 3-mode object T[i, r, j] (subject, relation, object), which is just a labeled multigraph wearing a costume. The estate's own laws force two more modes, and the interesting design question is exactly which extra modes earn their keep.

**Mode 0 and mode 2 (subject and object), hash-addressed.** Both index over receipt ids, and the ids must be content hashes, not line numbers. Grounding wave already learned this the hard way: `_admission` keys unhashed legacy rows as `line:{i}` (`mag/grounding_wave.py:272-273`) and those line anchors are exactly the fragile carriers (rows 122, 123, 131 are line-anchored defects "contained by void" in my verify output). The wave's G2 binding practice (`src_sha256_12` recorded at post time, `mag/grounding_wave.py:24-27`) and the republic's full-hash field discipline already fix the convention: sha256 for self-hashed rows, sha256_12 for foreign artifacts. The tensor never materializes the dense N×N frame; it is a sparse COO structure from birth, which at estate scale (thousands of receipts, not millions) is pure JSONL plus an optional sqlite sidecar.

**Mode 1 (relation type r), small and frozen.** The vocabulary is already drafted by the estate's own verbs, each with a code precedent:

| r | existing carrier | precedent |
|---|---|---|
| PREV | `prev` in every v1+ row | `mag/grounding_wave.py:113` |
| WITNESSES | `signs` in kind:"witness" | `mag/grounding_wave.py:125` |
| VOIDS | `voids` in kind:"void" | `mag/grounding_wave.py:122` |
| CONTESTS | `contests` in kind:"contest" | `mag/grounding_wave.py:124` |
| SUPERSEDES | `superseded_by` set-once; `SUPERSEDED` is already a void reason_code | `mag/republic.py:114`; `mag/grounding_wave.py:131` |
| REPLIES_TO, FORWARDS | `in_reply_to`, `forwarded_from` | `mag/republic.py:109,115` |
| IMPLEMENTS | plan receipt -> landed work receipt | queue receipts vs commit d90bc8607 |
| DERIVES_FROM | amendment -> base row | Q-022 amendment 005 as ledger row 6 |
| DUPLICATES | re-post -> first post | `VOID_REASONS.DUPLICATE`, `mag/grounding_wave.py:131` |
| BINDS_SURFACE | receipt -> path it speaks about | G2 `src_sha256_12`, AGENTS.md census-carrier bullet |

MODIFIES from the ask's phrasing folds into SUPERSEDES with a reason code, because the house chain law is delete-as-append: a modification that leaves the old receipt live is a DERIVES_FROM, one that buries it is a SUPERSEDES. The schema-rot law (stated in `mag/accumulator.py`'s registered purpose in `memory/knowledge_graph.json`: "schema rot = noise; freeze before anything else") applies to R: additions require a named consumer, exactly like the gene-pool tombstone's revive condition (`mag/gene_pool_feeder.py:6-16`, quoted in Q-028).

**Mode 3 (warrant grade k), the estate-native dimension.** Generic knowledge-graph tensors treat all edges as equal. The estate cannot: "CORROBORATED means the warrant exited 0 under two independent hands, not 'true'" (`mag/grounding_wave.py:32-33`), and "corroboration raises confidence, never grants permission" (`:54-55`). So every edge carries its proof grade: k=0 declared (a seat wrote it), k=1 hash-bound (target and subject hashes verified, G1), k=2 witness-signed (a second seat appended a signs row, G2-class), k=3 warrant-run (a recorded command exit, G3). The mode converts a policy sentence into a queryable column: permission-affecting queries filter `k >= 2`; analytics may read k=0 edges; nothing ever auto-upgrades a grade. This is the one mode a textbook tensor lacks and the estate's two-eyes doctrine demands.

**Mode 4 (time t), tide-day buckets.** The estate already organizes work by tides, waves, and burn days (`memory/burns/BURN_WAVE_STATE.json`), and the staleness diseases this tensor must catch are temporal (section 5). Bucket edges by UTC day; finer granularity rides edge attributes, not the mode.

**Seat is deliberately NOT a mode.** The two-eyes law needs seat DIFFERENCE, not seat value (the author-exclusion filter at `mag/grounding_wave.py:325-326` and the self-delivery ban at `mag/republic.py:314-316` are both negations). Making seat a dimension would multiply the tensor by S seats for no query that cannot be an edge attribute; the witness seat rides on the edge row and the diversity predicate is a constraint in the query layer. Restraint is the design principle: every mode must pay for itself in a named query.

Full shape: a sparse typed 5-mode structure T[hash_i, r, hash_j, k, t], physically an append-only edge log.

## 3. Edge grammar: what the house chain already proved about relation algebra

Three typing laws, each already enforced in code today, carry over verbatim:

1. **SUPERSEDES is functional and set-once in the subject.** `superseded_by` may be written once and never re-pointed (`mag/republic.py:209-218`). In tensor terms: for each i there is at most one j with T[i, SUPERSEDES, j, *, *] effective. Never a fan-out.
2. **Edges are themselves receipts, so edges can be voided.** This is the deepest thing the estate has already learned and the thing generic graph models get wrong. A void of a void REVERSES the original (`mag/grounding_wave.py:281-291`, "void-of-void = reversal, same verb"): the admission loop keeps only effective voids, and a void whose own hash gets voided stops counting. Consequence for the tensor: relation closure is NON-MONOTONIC. You cannot precompute "the live set" once; appending an edge today can re-validate a receipt buried weeks ago (the re-anchor machinery exists precisely for this, `mag/grounding_wave.py:381-399`). The admission docstring already states the physical law: the tape is never mutated, admission is a VIEW (`:265-267`). The tensor inherits it: every closure query runs the fixed point at read time or caches with explicit invalidation keyed on the chain tip (today `fc3c32be6f26`).
3. **Edge admission is gated, not free.** The G1 gate refuses hashless or prev-broken rows at append (`_admit`, `mag/grounding_wave.py:403-446`). The edge log keeps the same discipline with its own `_row_hash`-style versioned key set, so an edge is as tamper-evident as the rows it connects, and the void-of-void machinery applies to edges unchanged.

## 4. How you query the tensor (question 2)

Five query shapes, each named to a real estate pain, ordered from cheapest to most analytical. All operate on the sparse COO log; none materializes the dense frame.

**Q1, the live-slice query: "what is currently true on surface S?"** Filter the edge set to r ∈ {SUPERSEDES, VOIDS}, take the fixed point of section 3.2, and compute the frontier: receipts on surface S with no effective outgoing SUPERSEDES/VOIDS edge. This is the query that does not exist today, and its absence has a receipt trail: the census-carrier disease needed a four-law patrol stack to guard ONE line of AGENTS.md (the clippy census bullet's B2-215 drift patrol, B2-244 deep collect check, B2-246 daily schedule, B2-249 carrier shape law, per the ask's workspace context). Every one of those laws exists because the question "which receipt currently owns the census claim?" could not be asked of a byte store. A live-slice query answers it in one fold, and the patrol laws demote from enforcement to spot-check.

**Q2, the independent-witness query: "is r corroborated under the two-eyes law?"** Predicates over the incoming WITNESSES fiber of r: at least 2 distinct seats, no seat in authors(r), checks pass. This is exactly the ad-hoc computation at `mag/grounding_wave.py:325-334`, promoted to a named query. Generalization the tensor buys: witness diversity as a numeric (size of the seat fiber), and cross-receipt corroboration, which today has NO mechanism at all. The case is not hypothetical: my verify run in section 0 byte-matched the sibling seat's run, which is corroborating evidence for two prior receipts at once (the FW-03 receipt and the wave's stability claim), and the only way I could assert it was prose in this file. Under the tensor it is two edges: (this_item, CORROBORATES, k=3, Q-020_FW03_receipt) and (deep_quantum_receipts, CORROBORATES, k=3, same), queryable, instead of re-discovered by the next reader.

**Q3, the propagation contraction: "what downstream rows does this void contaminate?"** The propagation flags the wave already computes (witness-of-void at `mag/grounding_wave.py:316-317`, child-of-void at `:336-337`) are literally a 2-hop contraction: transpose the VOIDS slice against the WITNESSES and PREV slices and mark the fiber. The tensor states it as T_voids^T · (T_witnesses + T_prev) and asks the question the hard-coded depth-2 rule never asked: is depth-k propagation ever wanted? The measured answer supports restraint: 3 propagation flags exist today for 3 voids, all depth 1 or 2; no query in the receipts asks for deeper. Keep depth 2 as a law, note that the tensor form makes the depth an explicit parameter a future wave could revisit with evidence instead of vibes.

**Q4, the path predicate: "is this re-anchor valid?"** `_reanchor_ok` (`mag/grounding_wave.py:381-399`) is a reachability query on the PREV slice constrained to the complement of the voided set: every live row strictly between base and i must be buried. Expressing it as a graph query instead of bespoke index arithmetic is what makes the SAME predicate reusable for the SUPERSEDES and DERIVES_FROM slices (can a new receipt cite a base three supersessions back? only if the intermediates are all voided). One predicate, three slices, today three hand-rolled answers.

**Q5, the analytic layer: projections and spectra, on demand, never load-bearing.** Per-slug supersession chains from the burns ledger (the 35-row `free-resource-landscape` stream becomes a first-class chain with a diff pointer per edge, instead of 35 prose one-liners a reader mentally interleaves); degree-0 orphan detection across all slices (the vapor class; the day_work trail's opening row of 2026-09-04 declares "no more vapor, no more orphan mines for this era", `dashboard/static/trails/day_work.jsonl` row 1, but nothing today can enumerate orphans mechanically); per-lane churn as degree distribution of the SUPERSEDES slice per tide-day. Spectral work (eigenstructure of the CONTESTS/CORROBORATES slices, polarization-style analysis per Garimella et al.'s controversy detection) is the analytics lane and stays off the permission path entirely, per the corroboration law.

Implementation shape, following the house's own derived-index precedent: the FTS5 sidecar behind corpus_search (B2-465 law in the ask's workspace context, `tools/corpus_fts_rebuild.py` as the one sanctioned writer with a freshness gate) is the template. The edge log is primary (append-only JSONL, hash-chained); a derived sqlite view (COO columns + resolved hashes) is rebuildable at any time; a read-only CLI (`python -m mag.receipt_tensor query live --surface AGENTS.md`) is the entire first query surface. No auto-migration (the `mag/grounding_wave.py:40-41` law): old prose receipts get edges only when a seat files them deliberately, one act each; the 44 pointers in Q-028 become edges if and when a future wave needs to traverse them.

## 5. Patterns that emerge from the relationship structure (question 3)

Measured today, plus what the structure makes newly visible:

1. **Corroborate-once-then-freeze.** CORROBORATED status is recomputed at read time inside the wave, but receipts quoted downstream (AGENTS.md lines, commit messages, digest files) freeze the verdict at copy time and carry it forever. The witness-age distribution over the temporal mode exposes the pattern mechanically: witness edges cluster at t0 and never recur. The sibling deep item's amplitude design is the node-side cure; the tensor's edge-side contribution is the query "receipts quoted downstream whose last witness edge is older than N tide-days", which is the B2-215 disease as a SELECT instead of a scheduled patrol.
2. **Supersession depth as an amendment smell.** Depth of SUPERSEDES chains on one surface measures whether the estate amends or re-measures. The census bullet's B2-215 → B2-244 → B2-246 → B2-249 stack is four laws accreted over one carrier line in two days; as a chain, its depth-4 shape screams "we kept amending the claim instead of re-running `pytest --collect-only -q`". Pattern rule, offered for a future wave: depth ≥ 3 on one surface flags the base receipt for re-measurement, not another amendment.
3. **The same-slug stream without diffs.** 223 of 693 ledger rows re-post an existing slug. Some are genuine updates (quota numbers drift), some are noise (the same fact re-burned). The tensor forces the distinction at write time: a re-post with a DERIVES_FROM edge plus a diff pointer is an update stream; one without is a DUPLICATE candidate, and `VOID_REASONS.DUPLICATE` (`mag/grounding_wave.py:131`) already exists to bury it. The pattern that emerges: duplicate-edge density per slug is a quality metric for the burn waves that produce them.
4. **Cross-carrier fork drift.** One fact (the census count) lives in AGENTS.md, in receipts, and in commit messages, and the copies fork silently. BINDS_SURFACE edges make every carrier a node the live-slice query covers; drift between carriers becomes a diff instead of a discovered contradiction. FW-02's "the plan's 69 is a stale denominator" (commit b34ccd3ba body) is exactly this pattern caught by hand.
5. **The witness bipartite projection.** Projecting the WITNESSES slice onto seats yields who vouches for whose work, and the propagation flags (3 today, all witness-of-void or child-of-void) seed a per-seat contamination signal that is currently computed per chain and never aggregated. The estate's judge-lane doctrine (escalation as calibration alarm, per the burns ledger's judge-lane-spec rows) wants precisely this projection as an input; it exists in the tensor at query cost, not as new machinery.

The meta-pattern: every one of these is a query the estate has needed, suffered the absence of, and then hand-built a special-case patrol for (B2-215..249, drift patrols, FKB thresholds per Q-008's commit). Tensor receipts are the general surface those patrols keep re-deriving.

## 6. Literature anchors

- **Knowledge graphs as tensors.** RESCAL (Nickel, Tresp, Huang, ICML 2011) models a knowledge base as a 3-mode tensor X with X_ij^(k) = 1 when entity i relates to entity j under relation k, and factorizes it; DistMult (Yang et al., ICLR 2015), ComplEx (Trouillon et al., ICML 2016), RotatE (Sun et al., ICLR 2019), and TuckER (Balažević, Allen, Hospedales, EMNLP 2019) are the learned-completion line. The estate's r-slices ARE RESCAL's relation matrices. Position is deliberate: embedding-based link prediction is an analytics lane only, because a predicted edge can never exceed k=0 (declared) under the no-fabrication law; exactness is the substrate, prediction is at most a hint. Temporal knowledge graphs (HyTE, Dasgupta et al., AAAI 2018; RE-GCN, Li et al., 2021) justify mode 4 as first-class rather than an attribute.
- **Provenance.** W3C PROV-O (Moreau & Groth) gives the standard typed vocabulary: wasRevisionOf ≈ SUPERSEDES, wasInvalidatedBy ≈ VOIDS, wasAttributedTo ≈ the seat attribute, wasQuotedFrom ≈ CORROBORATES, wasDerivedFrom ≈ DERIVES_FROM. The estate's extension over PROV is mode 3: PROV records that something was asserted, not the graded warrant behind the assertion, which is the G1/G2/G3 distinction.
- **Citation networks.** de Solla Price, "Networks of Scientific Papers" (Science 1965): the directed citation DAG as cumulative knowledge structure; PageRank and HITS as its analytical descendants; Garimella et al. (2018) controversy detection via conversation structure maps onto the CONTESTS slice. The burn ledger's slug streams are structurally citation networks with the citations implicit; the tensor makes them explicit.
- **Belief combination.** Dempster-Shafer (Shafer, 1976) combines evidence from independent sources and explicitly requires independence; correlated witnesses double-count. The two-eyes law (distinct seats, neither the author, `mag/grounding_wave.py:50-51`) is DS's independence assumption made structural at the schema level, which is why seat distinctness belongs in the query predicates and not in a learned weight.
- **Content-addressed DAGs.** Git's commit DAG and IPFS's Merkle DAG (Benet, IPFS, 2014) are the production-grade precedents for hash-addressed nodes with multi-parent typed edges. The estate's chains are single-parent; the tensor allows multi-parent PREV (a receipt grounded in two prior tips) without committing to it, and the re-anchor predicate of section 4 Q4 is the tool that keeps multi-parent reachability honest.

## 7. Restraint, costs, and falsifiers

What this design refuses: no dense tensor ever materializes; no embedding model on the permission path; no relation vocabulary growth without a named consumer; no auto-migration of prose receipts; no second admission system (the edge log reuses the wave's hash discipline, lock, and gate pattern rather than inventing a parallel one, per the no-fallback-creep build discipline). Costs: one new append surface (EDGES.jsonl) with a real per-edge write cost, which is the point, relations should be deliberate acts; and a fixed-point computation per closure query, which at today's scale (137 rows, verify returns instantly) is free and only becomes a cache-invalidation problem orders of magnitude later.

Falsifiers, in the estate's style of banking them with the design: (a) if after one month of use the edge log holds fewer than one edge per receipt filed in the same window, R is mis-sized and the vocabulary should shrink, not grow; (b) if a closure query over 10k edges exceeds one second, the derived sqlite view is owed its invalidation law; (c) if no query from section 4 changes a decision in a full burn wave, the tensor is a museum piece and should be tombstoned the way `mag/gene_pool_feeder.py` was, with a revive condition naming the query that was missed. The probe's numbers argue the demand is real: 223 slug re-posts, 44 unparsed pointers in a single receipt, 10/49 receipts speaking supersession in prose, and one cross-seat byte-match that today survives only by luck.
