## What the ask asked vs what was done

Ask: "Census all JSONL ledgers in the repo (find . -name '*.jsonl' not in .venv/.git). For each:
how many rows, last modified, what schema, what reads it, is it growing?"

Done, at full repo scale, no substitution:

1. `./.venv/Scripts/python.exe watch/inbox/burn_reset_20260927/flash50/_f26_sweep.py` walked the
   entire repo excluding only `.venv` and `.git` (subprocess calls carry CREATE_NO_WINDOW on win32).
   Result: **11,854 .jsonl files, 19,538,633 rows (non-empty lines), 9,325,758,540 bytes (9.33 GB)**.
   For every file it measured: rows, empty lines, bytes, mtime, distinct top-level JSON key tuples
   (json.loads of every row for files <= 20 MB; first 20,000 rows for the 25 bigger files),
   git tracked/ignored status, rows at HEAD via `git show HEAD:<path>`, delta vs HEAD,
   last commit date via `git log -1`, and literal reader hits from a scan of 2,512 code/config files.
2. `git check-ignore --stdin` batch inside the sweep silently returned nothing (cause not
   reproduced); a fresh run of the identical command returned 11,364 ignored paths and those flags
   were patched into `_f26_raw.json` (`_f26_fixup.py`, evidence `_f26_ignored.txt`). Tracked counts
   and all row counts are from the original pass.
3. Reader claims were hand-verified per named ledger with targeted greps (e.g. `mag/ingest_registry.py:42`,
   `mag/coordination.py:97`, `tools/index/projects_index.py:31,34`, `mag/fact_bus.py:45`,
   `mag/percolator.py:222`, `mag/ghost.py:44`, `mag/lanes.py:42`). Grep logs in session transcript;
   machine-readable map in `_f26_readers_major.json`.

## Headline answers

  `dashboard/data/` twin at 3,485,538 rows each (2.58 GB combined, one walk two outputs).
- last modified: 2,313 files touched within 24h; 0 files older than 90 days.
- schema: per-file key families in census doc sections 4/7; 2,598 of 11,854 files carry >1 key
  family (append-ledger column drift is the norm). 88 files are empty. 58 files contain >=1 row
  that fails json.loads (29 of them are pytest corruption fixtures, agents/pytest-tmp-*).
- readers: 41 named operational ledgers mapped to writer/reader code (census doc section 4);
  bulk trees characterized by their owning subsystem (census doc section 6).
- growing: 44 tracked ledgers grew since sweep-time HEAD `0d6ace6b06` (+289,922 rows), 442 stable,
  0 shrank; 2,258 untracked ledgers touched within 24h (untracked files have no baseline, so mtime
  is the only growth instrument for them). All 44 grown ledgers listed with +rows in census 5a.
