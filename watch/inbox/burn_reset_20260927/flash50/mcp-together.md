## 3. Audio generation

### Text-to-speech (fetched live: https://docs.together.ai/docs/text-to-speech, via webReader MCP)

- **What it does:** text in, synthesized speech audio out, from a multi-vendor model catalog behind one OpenAI-style endpoint.
- **Endpoint:** `POST https://api.together.ai/v1/audio/speech`; voice catalog at `GET /v1/voices`.
- **Models:** `canopylabs/orpheus-3b-0.1-ft` (Orpheus), `hexgrad/Kokoro-82M` (Kokoro), Cartesia Sonic 2 (voice ID, not name), Rime Mist v2/v3 and Arcana v2/v3/v3 Turbo, Minimax Speech 2.6 Turbo / 2.8 Turbo.
- **Inputs (exact names):** `model` (req), `input` (req, text), `voice` (req), `response_format` (mp3 | wav | raw PCM | mulaw; default wav; Minimax also opus/aac/flac), `sample_rate` (e.g. 24000, 44100), `bit_rate` (mp3 only, 32000-192000, default 128000, Cartesia only), `language` (locale like "zh-hk"), `alignment` (word|none, streaming), `segment` (sentence|immediate|never), `extra_params.pronunciation_dict` (source/replacement entries). No speed parameter in this doc.
- **Outputs:** binary audio written straight to file; streaming supported only for raw/mulaw; wav/mp3 are not streamable.
- **Pricing on page:** Orpheus $15 / 1M chars; Kokoro $4 / 1M chars; Cartesia Sonic 2 $65 / 1M chars.
- **Speech-to-text is the same family** (sitemap + batch endpoint enum): `POST /v1/audio/transcriptions` (whisper-large-v3 class), `/v1/audio/translations`, plus realtime and VAD doc pages.
- **Estate use:** the estate already runs a local voice stack: `mag/voice_stt.py:1-8` (faster-whisper, model name from `MAG_VOICE_WHISPER_MODEL`, default "base"), `mag/voice_pipeline.py`, `mag/voice_lanes.py`, `mag/voice_dictate.py`, `mag/game_dm_voice.py`, `docs/ref/VOICE_DIG_LOOP.md`. Together adds a server-side lane: Kokoro at $4/1M chars is the cheap speak side for keeper/biographer readouts with no local GPU; whisper via **batch** transcriptions (endpoint enum confirmed in the batch API) can bulk-transcribe recorded sessions into corpus, the paid version of the manual 1,391-row transcription job banked as `watch/inbox/burn_wave_20260926/B2_130_session_inputs_raw.txt`. Local faster-whisper stays the zero-cost default; Together is the upgrade path, same trust tier as any paid lane.
- **MCP shape note:** synchronous binary return. An MCP wrapper must hand back a file path or base64; watch the payload-size laws (the batch API itself charges 10 MB per line for inline base64, a fair ceiling to copy).

## 4. Video generation

- **What it does:** async text/image/audio-conditioned video clip generation. (Page fetch: webReader 500ed twice; recovered via `https://docs.together.ai/docs/inference/videos/overview.md` and `.../videos/parameters.md` WebFetch.)
- **Endpoints:** create + retrieve (SDK: `client.videos.create`, `client.videos.retrieve(job.id)`; reference pages `reference/create-videos`, `reference/get-videos-id`). Docs pattern: submit, get job id, poll every 60 s.
- **Models shown:** `minimax/video-01-director`, `minimax/hailuo-02`; sitemap also carries Wan 2.7 and Seedance 2.5 quickstarts. Full catalog lives in serverless/DMI catalogs, not this page.
- **Inputs (exact names):** `model` (req), `prompt` (req except Kling; max 32,000 chars), `negative_prompt`, `width` 1366 / `height` 768 defaults, `resolution` (720P|1080P, Wan 2.7), `ratio` (16:9|9:16|1:1|4:3|3:4, Wan 2.7), `seconds` (1-10, default "6"), `fps` (default 24, some models to 60), `steps` (10-50; 10 preview / 20 balanced / 30-40 production), `guidance_scale` (6.0-10.0 recommended, avoid >12 artifacts), `seed`, `output_format` (MP4|WEBM), `output_quality` (default 20), `generate_audio` (audio-capable models), and the `media` object: `frame_images` (first/last keyframes), `frame_videos` (continuation), `reference_images`/`reference_videos` (consistency R2V), `source_video` (edit, Wan 2.7), `audio_inputs` (WAV/MP3, 3-30 s, <=15 MB, lip sync). Top-level `frame_images`/`reference_images` deprecated.
- **Outputs:** `id`, `model`, `status` (queued|in_progress|completed|failed|cancelled), `size` ("1366x768"), `seconds` ("6"), `outputs.cost` (example 0.28 for a 6 s 1366x768 clip, illustrative not documented), `outputs.video_url` - **URLs expire; download immediately**. Failure: `outputs` null plus `error.message`/`error.code` (example "unsupportedParameter").
- **Estate use:** weakest of the six. Nothing in the load-bearing path needs video; plausible edges are demo/dashboard assets or campaign artwork animation. Not recommended under the funding law; if ever used, `outputs.cost` is the receipt and the expiring URL is the trap (download to `watch/inbox/` before banking).
- **MCP shape note:** minutes-long polling does not fit a one-shot MCP tool call cleanly; the right server shape is create + status + fetch, or the workflow owns the poll loop like the docs' 60 s loop.

## 5. Batch inference

- **What it does:** many independent inference requests from one uploaded JSONL, async, discounted, separate rate-limit pool. (Fetched live: overview via webReader MCP; schema via `https://docs.together.ai/reference/batch-create.md` WebFetch.)
- **Endpoint:** `POST /v1/batches` (base `https://api.together.ai/v1`). Required: `endpoint`, `input_file_id`. Optional: `completion_window` ("24h"; overview says defaults to 24h and cannot be changed), `priority`, `model_id`. Per-request `custom_id` field reconciles inputs to outputs (results come back in arbitrary order).
- **endpoint enum:** `/v1/chat/completions`, `/v1/audio/transcriptions`, `/v1/audio/translations`. DMI endpoints also work but get no discount.
- **Status lifecycle:** VALIDATING, IN_PROGRESS, COMPLETED, FAILED, EXPIRED, CANCELLED; `progress` 0.0-100; results in `output_file_id`, failures in a separate `error_file_id` (per-request errors do NOT change batch status - always pull the error file). Support guidance: 72 h of IN_PROGRESS before escalating.
- **Limits:** 50,000 requests per batch, 100 MB per file, 10 MB per line (inline base64 counts), 30 B tokens enqueued per model at once. One uploaded file can back multiple batch jobs.
- **Pricing:** up to 50% off serverless rates, pay only for successful responses (cancel does not refund completed work); discounted models named: `meta-llama/Llama-3.3-70B-Instruct-Turbo`, `openai/whisper-large-v3`. Best practice from the page: 1,000-10,000 requests per batch; validate JSONL locally (malformed files die in VALIDATING); classification shape = `max_tokens` 4 + `temperature` 0.
- **Estate use:** the headline fit. The lane's own role in `configs/keys.json:87` is literally "bulk", and `docs/ref/ZAI_API_EXPERT_REFERENCE.md:433` already banks "~19x cheaper for bulk". Concretely: (a) corpus classification/tagging passes over the catalog (temp 0, max_tokens 4 matches the doc's own best practice); (b) bulk audio transcription into corpus; (c) off-seat grader sweeps of scenario cards; (d) the async twin of the offpeak-overflow law in AGENTS.md (route overflow when the account caps - batch is that, priced). The 24 h window matches the overnight pile habit.
- **MCP shape note:** submit + status + download triple, or one tool holding the job handle. `custom_id` should carry the estate receipt pointer so results land attributable.

## 6. Dedicated endpoints / deployments (the ask's "dedicated containers")

- **Naming truth:** the current docs sitemap (fetched live this session) has **no "dedicated containers" page**. The family is now **Dedicated Model Inference (DMI)**: `endpoints` (id prefix `ep_`) hosting `deployments` (`dep_`) with rollouts (`rol_`), A/B (`abx_`) and shadow (`exp_`) experiments. If the MCP tool in the ask is named "dedicated containers", it maps onto this surface.
- **What it does:** reserved GPUs serving any catalog model (or your fine-tune / an uploaded LoRA from HF or S3), same shared inference API, `model = "<project_slug>/<endpoint_name>"`, no hard rate limits, billed **per GPU-minute per running replica** (example hardware `1x_nvidia_h100_80gb_sxm` at $0.06/min from the v1 page), "Stopping an endpoint pauses billing", stopped/deleted replicas incur nothing. Prototype serverless, flip to DMI without code change.
- **v1 API shape** (`https://docs.together.ai/docs/dedicated-endpoints/v1/manage.md`, deprecated by end of 2026): `client.endpoints.create/retrieve/list/update/delete`. Create fields: `model`, `hardware`, `display_name`, `autoscaling {min_replicas, max_replicas}` (must be supplied together), `availability_zone` (e.g. "us-east-1a"). Response fields: `object`, `id` ("endpoint-d23901de-..."), `name` ("devuser/Qwen/Qwen3.5-9B-FP8-a32b82a1"), `model`, `hardware`, `type`, `owner`, `state`, `autoscaling`, `created_at`. Update takes `state` STOPPED/STARTED. Filter list with `"type": "dedicated", "usage_type": "on-demand"`.
- **Next-gen shape** (`.../dedicated-endpoints/manage.md` + overview): CLI `tg beta endpoints deploy/get/rm`; config resources `cr_...`; placement `pp_...` with `--placement.regions`, `--placement.constraint` (required|preferred), HIPAA compliance flag; traffic weights (weight 0 = dark deployment); endpoint responses embed up to 10 newest deployments (createdAt desc) plus `activeRolloutId`; deployment states PROVISIONING, SCALING, READY, DEGRADED, STOPPING, STOPPED, FAILED; pagination `next_cursor`. REST paths for the new generation live in `reference/dmi/endpoints-create` and `reference/dmi/deployments-create` (not fetched this session; OWED only if the estate adopts DMI).
- **Estate use:** two sharp fits, both operator-gated. (1) The 50-wide envelope's first contact is a shared-cap HOLD signal (`watch/inbox/ENVELOPE_50W_HIT_20260926.md`, B2_443 DWF error census); a DMI replica removes the shared-cap variable for graph fan-out. (2) A fine-tuned fleet successor needs a permanent home; DMI is where `model_output_name` gets served. Against it: $0.06/min = $4.32/hr while STARTED, and the on-file verdict (`ZAI_API_EXPERT_REFERENCE.md:431`) already rules raw vast.ai rent 4-7x cheaper. DMI buys zero-ops + same API + no hard limits, not cost-floor.
- **MCP shape note:** these are the most dangerous tools of the six for a seat to hold - create/destroy stateful infra on a running meter. Under the estate's effect law (model text proposes, only the switchboard/effect broker authorizes), an MCP wrapper must put create/delete behind an approval gate and auto-STOP idle replicas.

## 7. Fine-tuning

- **What it does:** LoRA (default) or full fine-tune, SFT or DPO, of catalog models (or bring-your-own from HF), with checkpoints, continuation, W&B integration, and price in the response. (Fetched live: quickstart + `https://docs.together.ai/reference/post-fine-tunes.md`.)
- **Endpoint:** `POST /v1/fine-tunes`. Upload via files API (`POST https://api.together.ai/v1/files/upload`, `purpose="fine-tune"`; quickstart also shows `tg fine-tuning create --training-file <FILE_ID> --model Qwen/Qwen3.5-9B --lora`).
- **Inputs (exact names):** required `training_file`, `model`. `validation_file`; `training_type` LoRA (default) or full, LoRA fields `lora_r`, `lora_alpha` (required), `lora_dropout` (0), `lora_trainable_modules` ("all-linear"); `training_method` sft|dpo; `n_epochs` (1), `n_checkpoints` (1, max 10), `n_evals` (0), `batch_size` ("max"), `gradient_accumulation_steps`, `learning_rate` (1e-5), `lr_scheduler` object, `packing` (true), `max_seq_length`, `warmup_ratio`, `max_grad_norm` (1, 0 disables), `weight_decay`, `random_seed`; early stopping block (`early_stopping_enabled`, `_patience` 2, `_min_delta`, `_warmup_evals`); `suffix` (<=64 chars into the output model name); `wandb_api_key`, `wandb_base_url`, `wandb_project_name`, `wandb_name`, `wandb_entity`; `train_on_inputs` (deprecated, default "auto"); `multimodal_params.train_vision`; `from_checkpoint` (`{$JOB_ID}` | `{$OUTPUT_MODEL_NAME}` | `{$JOB_ID}:{$STEP}`); `from_hf_model`, `hf_model_revision`, `hf_api_token`, `hf_output_repo_name`.
- **Outputs:** response `id` (`ft-...`), `status`, `created_at`/`updated_at` (required fields) plus `model_output_name` (e.g. "mynamespace/meta-llama/Llama-2-7b-hf-32162631"), `total_price`, `token_count`, `events`, `progress`, `early_stopped`, `early_stopping_best_step`/`_metric`. Lifecycle: pending, queued, running, uploading, completed (terminal: completed|error|cancelled); poll `retrieve` every 60 s; `list-checkpoints`; download weights for local use per the overview page; serve via DMI.
- **Estate use:** the direct hit on an existing doctrine. `.agents/skills/code-agent-data/SKILL.md:1-40` (read this session): room.jsonl rows + seat tapes + intake cards ARE the training corpus for the fleet's successors, gated by a substance floor (>=600 bytes + a Result-class section), with a "Stage 2/3 corpus packer" that already expects to feed a QLoRA campaign. Together LoRA is the hosted version of exactly that: JSONL in, `ft-...` job out, `total_price` giving the receipt the ledger needs, `model_output_name` feeding either DMI or a weights download. The corpus gate (training-grade vs vapor) maps to `validation_file` + `n_evals`. Funding gate: training spend is new money; the right first bite is one small LoRA run over the already-passing tape corpus, receipted, before any campaign.
- **MCP shape note:** submit + poll + checkpoints triple; the expensive accident is a duplicate `create()` (quickstart: each `create()` starts a new billed job), so a wrapper should carry an idempotency key or at least echo the job id loudly.

## 8. Evaluations

- **What it does:** model-graded eval jobs of three kinds - `classify`, `score`, `compare` - with an LLM judge, over an uploaded dataset, returning aggregate + row-level verdicts. (Fetched live: `https://docs.together.ai/docs/run-an-evaluation.md`; reference pages `reference/create-evaluation` etc. exist in the sitemap, not fetched.)
- **Shape:** `client.evals.create(type=..., parameters=...)` / `tg evals create`; create returns `{"status": "pending", "workflow_id": "eval-de4c-1751308922"}`; poll `tg evals status $WORKFLOW_ID`, full detail via retrieve; list via `tg evals list`.
- **Inputs (exact names):** `type` classify|score|compare; `parameters.input_data_file_path` (file id; CLI auto-uploads local); `parameters.judge {model, model_source (serverless|dedicated|external), system_template}` (example judge `openai/gpt-oss-120b`); `parameters.model_to_evaluate` as a config `{model, model_source, system_template, input_template, max_tokens, temperature}` OR a dataset column of pre-generated responses; classify: `labels`, `pass_labels`; score: `min_score`, `max_score`, `pass_threshold`; compare: `model_a`, `model_b`, plus `disable_position_bias_correction` (single-pass judging halves judge cost/latency). Dataset is JSONL/CSV with `{{prompt}}` placeholders from `input_template`; every column must be consumed somewhere or validation fails `user_error`; images must be base64 data URLs.
- **Outputs:** aggregates like `A_wins`, `B_wins`, `Ties`, `generation_fail_count`, `judge_fail_count`, `result_file_id`; row-level file (via `client.files.content(result_file_id)` / `curl https://api.together.xyz/v1/files/$RESULT_FILE_ID/content`) carries original input, generated responses, judge decision + feedback, `evaluation_successful`. Failures end in `error` or `user_error` with reason at `results.error`.
- **Estate use:** model-graded judging is already estate culture (workflow_gate scenario cards; graders dogfooded every wave per the max-concurrency law). Together evals are the off-seat judge lane for successor-model work: `compare` between two fine-tune checkpoints over held-out operator turns, `classify` over RIB-law-adherence labels. Trust law holds: results bank as **findings**, never as gate verdicts - the workflow gate stays deterministic-local, and an eval is evidence for a promotion decision, not the decision.
- **MCP shape note:** submit + status + retrieve + result-file download; `workflow_id` is the handle (note: it is a workflow id, which reads naturally to this estate but is Together's own concept).

## 9. Cross-family pattern for the harness

1. **Money-bearing surface.** Chat is the only funded piece today ($5 sub, verified live). Audio, video, batch discounts, training, GPU-minutes are all new spend. A single estate helper (a `tools/` script lane like `B2_04_probe.py` driving REST directly) beats waiting for an MCP plugin: workflow children can run scripts, but cannot call MCP tools that are not attached to their seat, which is exactly the wall this item hit.
3. **Gate placement.** If any of this becomes a pre-push/CI consumer, it lands under `tools/workflow_gate.py` discipline. Create/delete on DMI belongs behind the effect broker, full stop.
4. **Trust tier.** Paid-lane outputs are better than stealth-lane sensing but still climb the verification ladder: bank as findings, verify at the funded tier before anything claims done.
