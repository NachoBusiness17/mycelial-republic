## 2. The new decomposition: erasure loss vs mutation loss

The data processing inequality (Cover and Thomas 1991; the sibling cites it) says a Markov chain raw -> receipt -> finding -> law -> rib -> pack can never ADD information about the underlying event. Correct, and incomplete as a design guide, because there are two ways to fail:

- Erasure is entropy: a stage drops detail. I(X; A_k) decreases. The dropped detail is usually pointer-recoverable, and the loss is per-read: the same section that sheds from this render renders fine in the next build. Erasure damages one read at a time.
- Mutation is fabrication: a stage changes a claim. The DPI does not forbid it; the stage adds bits that are ANTI-correlated with the source. Mutation is per-eternity: it propagates into every downstream stage that consumes it and persists until some verifier happens to check. A drifted index hash poisons every future "trust bytes" recovery that consults it. A stale carrier count poisons every seat that cites it, and, worse, gets re-cited into new receipts, which then look byte-backed.

The estate's instrument census splits exactly on this line. Erasure instruments, everywhere: byte budgets on every source (MODE_CONFIG, context_pack.py:52-146), the four-rung shed ladder (:1238-1279), the PACK_OFFLOAD ledger (:34-49), read-time caps, the quantizer's two-pass gate, staleness gates (7d render gate :376-378), the fossil arm (thought_quantizer.py:22-23), the census-carrier tripwire. Mutation instruments, nearly none: `tools/census_drift_patrol.py` guards ONE claim in ONE file (the AGENTS.md Tests bullet, and per arch-04's D1 the frozen vectors no longer even match the live grammar); the fossil arm guards ONE property (pack age); the verkle chain hashes session knots; nothing anywhere re-hashes INDEX.json against its files, nothing re-runs a receipt's instrument after landing, nothing diffs AGENTS.md's ~30 numeric claims against their receipts. The estate checksummed the wide mouth of the funnel (step_hash on the raw tape, sha256 on receipts, verkle knots on sessions) and left the narrow stem open: the pack, the only artifact the model actually drinks, is verified by nothing, and the integrity layer just above it (INDEX) rots unwatched at 77.5 percent on today's sample.

This inverts the actual risk. Erasure loss is bounded by construction (budgets are finite, pointers are cheap, 318 B per index row). Mutation loss is unbounded by construction: there is no budget, no ledger, no ratchet on it anywhere in the tree I read. The funnel loses bytes where it is watching and truth where it is not.

## 3. Optimal compression at each stage: the verifier-horizon rule

Rate-distortion says there is no abstract optimum, only optimum-for-a-distortion. For a fleet funnel the distortion currency is the downstream seat's re-derivation cost, and each stage already has, or should have, a mechanical verifier that bounds how far compression can go. The rule this item proposes: a stage may erase any byte it does not need to answer its stage verifier, and may not carry a claim its verifier cannot refute. Compress to the verifier horizon, then stop.

Two corollaries the estate's current shape violates:

- Fidelity should run INVERSE to the consumer's ability to re-derive. A full seat with tools can follow pointers; a janitor cannot. But measured today: the janitor's 1,196-char pack carries no compiled laws (`has_laws` false, my probe; the quantizer docstring at context_pack.py:344-353 names janitors as its audience), no task tail (rung 4 amputates L3), and clips mid-objective (arch-01 D2, cross-cited). The narrowest packs feed the least-capable re-derivers the worst-fidelity bytes. The funnel currently inverts the fidelity gradient.
- Supersession must be structural, not prose. AGENTS.md carries two Hermes budget figures in the same file ($220 armed in the clippy header, $180 Nous credits in the DRIVING LADDER bullet, given material), reconciled only by the prose "supersedes the tier-ladder line above". Interpretation, labeled: un-reaped dead law is mutation-adjacent, because a seat that loads only the header inherits the dead figure with nothing mechanical to tell it which law is live.

## 4. Total information loss, the honest live ledger

The gross number first, because the ask asks: 8,206,274,631 bytes of S0+S1 surfaces render into a 4,496-char full pack. That is 1,825,150:1 (6,861,433:1 for the janitor tier). Like the sibling concluded, this number is nearly meaningless, because most of the mass is pointer-recoverable. The loss that is real, with today's numbers:

1. Pointer-recoverable (dominant, near-zero true loss): index rows, knots, receipt citations. Loss here is retrieval latency. One dent: coverage is 12.2 percent and only 16.7 percent of today's new files got rows, so the recall layer is selective by whoever wrote rows, and the selection is unaudited.
2. Erased-but-logged (repairable waste): 228 overflow events, 226 of them ending in the hard clip (99.1 percent), each row naming the shed sections and persisting none of the shed bytes (context_pack.py:34-49, read). The funnel's biggest designed shed, rung 3, is all-or-nothing (arch-01 D3, cross-cited; my three builds all fired it).
3. Erased-unlogged: the tail clip inside the downstream tail and preamble paths emits no rows (arch-01 section 4, cross-cited); never-captured stdout is unbounded by construction.
4. Dead-stage loss (100 percent, measured today): the rib stage. 43 ribs, 152,666 B, excerpt built at 4,235 chars by 43 file opens on every build (arch-01 section 2, cross-cited), rendered into 0 of my 3 live packs. Production without consumption: a shredder with extra steps, exactly the fossil pattern the quantizer's own docstring (thought_quantizer.py:4-10) says killed v0.2, one stage up.
5. Echo (the inverse failure): 290,507 counts compress into 366 leaves with 79.9 percent of repetition mass in one leaf. Dedupe that cannot distinguish a chorus from a stuck loop. Mitigation already coded (counts are provenance-only); the count-ceiling censure remains owed (sibling section 5, endorsed).
6. Mutation (the unwatched channel, measured today): 31/40 sampled INDEX pointers stale (77.5 percent); the census carrier +107 tests / +16 files stale for over a day against the one claim in the estate that HAS a patrol; the false in-code claim "Directive tier survives the ladder" at context_pack.py:1262 (comment read by me, falsity proven by arch-01 probe 2, cross-cited); the retired 1,341-test headline that rode for weeks hand-copied and never byte-backed (given material, AGENTS.md). Four independent instances, three different stages, one pattern: no verifier between landing and consumption.

So the answer to "what is the total information loss": by bytes, about 1.8 million to one, and that figure is almost empty. By truth, the loss concentrates exactly where the estate is not looking: 226 unpersisted hard clips, one dead understanding stage delivering 0 bytes, and a mutation channel running at 77.5 percent on the integrity layer and +107 on the best-guarded claim, both measured live in this session. The funnel's compression is close to optimal; its translation is not audited at all.
