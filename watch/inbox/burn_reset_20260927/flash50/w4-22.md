## 3. Four mechanisms by which map becomes territory

**(a) Performativity.** Ribs are specs, not transcripts: "publish_rib() folds a frontier invariant -> a verkle knot -> mount() loads it -> inject_for() prepends it to the cheap worker's task slice" (RIB_MAP_PRECEDES_TERRITORY_20260811.md:24-28). A rib does not describe what the flock did; it is the input the flock executes from. When the map is load-bearing in this way, a map error is not a representation error, it is an action error, multiplied by every downstream seat that renders from it. That is why the estate's worst recorded sin is not inaccuracy but fabrication: an unfiled prompt makes a failure unreproducible, "and therefore not a finding" (RIB_MD_RECORD_20260921.md:11-14). In a system where map precedes territory, an unrecorded event is not merely lost, it is retroactively unhappened.

**(b) Self-reference.** Record-keeping is itself territorial work, so the map grows by describing itself. Receipt s2-23 (git log 748804083, verified this session via `git log --oneline -3`) closed on exactly this: "the receipt demonstrated its own lifecycle (autoseal registered the pre-edit sha stale within 1 min; python-created twin bypassed the Write hook with zero events)". The act of writing a receipt about receipts produced new register events and a hook bypass, that is, new territory. There is no fixed point at which the map is done, because the census of the map is a change to the map. This very file is an instance: the census instrument banked beside it measured 14,086 watch/inbox files, and measuring added two more.

**(c) Pricing.** The map is not just read, it is priced into identity. freeze_system_prompt() freezes the system prompt plus tool schemas as a byte-identical session prefix, hashed "over prefix bytes + a NUL seam + the canonical tool-schema bytes, so either half changing flips the hash" (mag/context_pack.py:452-489, hash at 475-478). The seat's continuity for a session is a sha256 of its own map fragment, maintained because provider prompt caches key on exact prefix bytes (comment block at 430-438). Identity is a cache key: the estate keeps its self bytes stable for economics, and the stability is what makes the seat the same seat across calls.

**(d) Gates.** Where the record makes falsifiable claims about the machine, the estate builds gates that compare map to territory byte-against-byte: the census-carrier tripwire (B2-215) flags the AGENTS.md test-count claim when it goes stale while tests/ grows, and B2-216's denominator law says "never difference two counts taken at different moments" (AGENTS.md, Clippy section). The doctrine is "trust bytes, not reports," which is precisely the resolution of map-territory tension: the map may say anything, but a gate re-derives the territory and fails the push on divergence. The ratchet, the census patrol, and config_seal are all the same machine: periodic forced contact between the description and the described.

## 4. The failure mode is lag, not reification

Korzybski's warning was reification: mistaking the map for the territory. The estate's live failure is different and more interesting: it has two maps of the same territory that disagree, and its boot path loads both as equals.

- The old map: RIB_FREE_USAGE_POLICY_20260823.md:25 says "DeepSeek (funded) - the reliable workhorse for real volume."
- The new map: RIB_DRIVING_LADDER_20260928.md:10-12 says "DeepSeek is no longer the funded workhorse; the Nous credits are," minted from three consecutive operator corrections ("those aren't funded only hermes" / "stop running shit and start remembering", lines 3-5).

Both files are live in memory/rib/. The read path, `_rib_doctrine` (mag/context_pack.py:305-340), does `files = sorted(rib_dir.glob("*.md"))` at line 315 and renders title plus goal per file under a character budget. There is no date check, no superseded banner, no precedence field. The commit receipt sess-05 (34ad910fe, verified this session) names exactly this gap: "stale DeepSeek-funded rung STILL LIVE at RIB_FREE_USAGE_POLICY_20260823.md:25 with no superseded banner while context_pack.py:312-315 loads all ribs."

The asymmetry that makes this structural rather than accidental: the compiled-law layer does have a circuit breaker. `_quantized_laws` (mag/context_pack.py:343-391) checks the compile report's timestamp and, past 7 days, hides the law and renders "(quantizer packs STALE Nd - recompile owed ... law hidden until fresh)" (lines 376-378). So the estate polices its machine-compiled map layer for staleness while leaving its hand-minted prose doctrine layer (the ribs, the layer the operator actually inscribed corrections into) age-blind. The newest and oldest of 43 ribs enter a fresh seat's context in alphabetical order with equal authority. Also on the boot path: `warm_boot()` composes chain tip, deployments, and session brief (mag/hermes_warm_boot.py:84-94) and carries no ribs at all, so the load-first law ("load ribs -> load state -> then act", AGENTS.md driving ladder) is enforced nowhere in code; sess-05 verified zero rib gates at pre-push, in workflow_gate, and in the warm payload (34ad910fe).

Lesson for the identity thesis: once maps command territory, map staleness is not an information defect, it is a behavior defect. The territory had changed (funding died, credits moved) but no map event marked it; only three operator corrections, the most expensive possible diff format, forced the new map into existence. The estate's true name for the map-territory gap is correction debt, and it is paid in operator repetitions.

## 5. The residue: machine minus record

Subtract the record from the machine. What is left, concretely, in this estate?

**RAM sketches.** The in-memory corpus fast-path was, until 2026-08-25, a frozen snapshot: "after the first load, every subsequent loop pass returns cached: True from a frozen snapshot - new steals / RIBs / research packs written to disk between passes are invisible" (RIB_RAM_CACHE_STALE_SNAPSHOT_20260825.md:8-14). The residue is exactly this: whatever the machine holds that the record has not yet been consulted to update. The fix was to make RAM's authority derivative of the record's mtime (auto-invalidation fingerprint, lines 27-32): the sketch exists only by the record's continued permission.

**The unabsorbed delta.** The record never catches the machine completely, and the estate measures its own remainder: fold verification counts 1,415 materialized items against 1,639 fresh-fold (224 invisible), flash50 holds 309 files on disk of which 196 are tracked and 113 untracked, 17 amend events were never applied by the fold, 81 register events keyed on nothing register nothing at all (all from receipt s2-23, git log 748804083, run this session). ## 6. Formal statement

Let R be the record, M the machine. The estate is neither term but the loop: M at time t+1 acts as g(R at time t, tools), and R at t+1 equals R at t plus the record of M's action. The identity claim "the receipts ARE the estate" is true the way a score is the symphony: complete for replay (any seat can re-enter the standing wave from bytes, per RIB_SELF_WHAT_I_AM.md), empty for playing. What the map cannot contain is the rendering act itself; only its receipt is recorded. Korzybski's gap therefore never closes even at 920:1 byte dominance, because the gap is not extensional (map bytes vs territory bytes) but intensional: the map holds what was done, the machine holds what can be done, and the boot is the arrow between them. The preceding claim is testable in this estate: every boot-path artifact I read (context_pack.py:305-391, hermes_warm_boot.py:84-94) is an implementation of exactly that arrow, assembling R into a renderable prefix and nothing more.
