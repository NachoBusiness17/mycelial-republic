Method first. Two instruments were written and run this ask (banked beside this file): `_w4_depgraph.py` (v1, all-imports graph over `tools/` + `mag/`) and `_w4_depgraph2.py` (v2/v3, resolves any import against the repo root, splits module-level imports from lazy function-scope imports, Tarjan SCC, condensation longest-path, gate-closure walk). Every number below is from these runs or from files read directly this ask, cited by path:line.

## 1. The kernel, stated

The estate's compiler is not a compiler; it is a gate stack, and its kernel is smaller than anything in `mag/`: **CPython 3.11.15 + stdlib + git + one 309-line file called `config.py`.**

Proof, at the tool layer: the enforcement trinity has an *empty* internal dependency closure. The v3 gate-closure walk returned `[]` for `tools/workflow_gate`, `tools/violation_ratchet`, `tools/config_seal`, `tools/census_drift_patrol`, `tools/freshness_check`, `tools/freshness_gate`, `tools/ledger_lock`, `tools/checkbox_receipt_gate`, and `tools/fossil_check`. Read directly: `workflow_gate.py:33-40` imports only argparse/datetime/glob/hashlib/json/os/re/sys; `violation_ratchet.py:32-39` only ast/hashlib/json/re/subprocess/sys/datetime/pathlib; `config_seal.py:19-24` only argparse/hashlib/json/sys/datetime/pathlib. The code that judges the estate stands on nothing the estate built. It is self-hosting in the strict bootstrap sense: a bare CPython plus a `git` binary plus the working tree reconstitutes the entire enforcement layer.

The bootstrap *entry point* is git itself: `githooks/pre-push:13-16` runs `.venv/Scripts/python.exe tools/violation_ratchet.py check --changed || exit 1` then `config_seal.py verify || exit 1`. So the full kernel chain is: git push (foreign) → sh hook (foreign) → venv python (foreign) → stdlib-only gate (self) → verdict on estate code (self). Three trusted levels, one self-hosted level, zero further dependencies.

## 2. config.py is the axiom of the estate

`config.py` (309 lines) imports exactly two stdlib modules (`pathlib`, `typing`, config.py:2-5) and defines, at line 7, `ROOT = Path(__file__).resolve().parent`. That line is the estate's first principle: *where am I*, answered by a file that only knows its own path. Everything downstream - `MEMORY_DIR`, `STATE_DIR`, `QUEUE_DIR`, `CONFIGS_DIR`, `CURRENT_MD` (config.py:9-20) - is one axiom plus arithmetic.

Its fan-in is the largest in the estate: 690 importer files at top level (v3 count), versus 59 for the `mag` package hub. Both deepest chains the instruments found terminate at it. The deepest import-time chain is 5 edges: `config <- mag.ox_megaburn3 <- mag.ox_novelty_index <- mag.ox_scout <- mag.ox_resident <- mag.ox_swarm` (verified: ox_swarm.py:40 imports ox_resident, ox_resident.py:41 imports ox_scout, ox_novelty_index.py:39 imports ox_megaburn3, and each ox module pulls `from config import ROOT`: ox_swarm.py:34, ox_resident.py:34, ox_scout.py:32, ox_megaburn3.py:27). A compiler-theoretic reading: `config.py` is the runtime's builtin module, the thing every translation unit may assume; `ROOT` is the equivalent of the loader's base address.

The sharpest detail: the kernel gates do not even import it. `violation_ratchet.py:41` recomputes `ESTATE_ROOT = Path(__file__).resolve().parent.parent` by hand. Enforcement code reimplements the two-line axiom rather than depend on it - the gates are so kernel-pure they carry their own address.

## 3. The lazy architecture: structure lives at call time

The single most consequential architectural fact the scan surfaced: **595 files defer their `mag` imports into function scope versus only 190 that import at module level** (v3 lazy-vs-top census), and `mag/__init__.py` is 17 lines importing nothing but `__future__` (mag/__init__.py:8). The package hub is a vacuum. The organism's 1,037-module body is not held together by the import system at all; it is held together at call time.

Consequence: the raw all-imports graph fuses into one 319-node strongly-connected blob (v1 showed it as a 145-node cycle before root-module resolution; v3 measured it at 319 with four tools inside: `tools.auto_promote`, `tools.corpus_lens`, `tools.pile_classify`, `tools.pupeteer_gauntlet`). But on the import-time graph - the graph the interpreter actually executes at load - the estate is almost a clean DAG: **exactly one cycle**, `mag.frontier_salon <-> mag.frontier_salon_cli`. And that one is not a tangle; it is a seam. `frontier_salon_cli.py:11` imports the library at module level, while `frontier_salon.py:394-399` imports the CLI only inside `if __name__ == "__main__":`, and the comment there explains why: "Q-011, 2026-09-28: the gate additions pushed mag/frontier_salon.py over the 400-line ratchet cap; extraction beats registering new debt." **The estate's only import-time cycle was manufactured by its own enforcement tool** - the ratchet's 400-line cap forced the library/CLI split that created the seam. The compiler's constraint produced the compiler's only flaw, and the flaw is inert (conditional on `__main__` execution, where the library is already in `sys.modules`).

Four more small cycles exist only in the lazy graph: `mag.registry <-> mag.session_card`, `mag.coding_session_loop <-> mag.coding_session_orchestrator <-> mag.desk_observer`, `mag.wow_bones <-> mag.wow_bones_session`, `mag.arxiv_harvest <-> mag.lane_runner` (v2 output). These are function-scope recurrences: legal, deliberate, invisible to the loader. The mycelial metaphor is structurally literal here - hyphae (call edges) form the network; spores (modules) never load each other circularly.

## 4. The tools layer: flat, solitary, spawn-happy

Of 189 tools, 141 have zero repo imports at import time (v3); 137 had zero even counting lazy imports (v1). Lateral tool-to-tool composition is rare and shallow: 17 edges total (v1), deepest lateral chain is 2 edges - `tools.queue_close -> tools.ledger_lock -> tools.ledger_append_gate` and `tools.secret_gate -> tools.secret_gate_scan -> tools.secret_gate_rules`. Gates do not compose with each other; each stands alone on stdlib. The deepest thing a tool builds on is `mag/` or `config.py`, never another gate. 21 of the 141 dependency-free tools spawn subprocesses - the tools' real dependency is not other code but *the machine*: git, PowerShell, the filesystem.

## 5. The deepest chain, and what it means

On the all-imports condensation (lazy included), the longest chain is **16 edges, 17 nodes**:

`config <- mag.verkle_knot <- mag.verkle_bus <- mag.fact_bus <- mag.percolator <- mag.research_class <- mag.novelty_lens <- mag.steal_pack <- mag.prospect_sim <- mag.desk_orchestrator_memory <- mag.desk_conductor <- mag.desk_observer <- mag.coding_session_runner <- mag.factory_machine <- mag.roadmap_runner <- mag.attention_ranker <- mag.feedback`

Verified links: verkle_knot.py:30 `from config import ROOT` (module level); verkle_bus.py:216 lazily imports `append_verkle_knot`; percolator.py:278 lazily imports `fact_bus.publish_fact` ("compiled_invariant"). Read as a sentence, the chain is the estate's trust pipeline: a **hash knot** (content addressing, verkle_knot) feeds a **fact bus** (publication), which feeds the **percolator** (facts compiled into invariants), through research/novelty/steal packs (knowledge refinement), into the **desk stack** (orchestration memory → conductor → observer), up through the session factory, the roadmap, the attention ranker, and finally `mag.feedback` - operator attention. Sixteen hops from a hash to a human. Both ends are anchored in the same two-line axiom: the knot knows where the estate is via config.py:30, and the whole organism inherits that answer unmodified.

## 6. Bootstrap verdict (theory)

The estate satisfies a three-level bootstrap scheme. T0 (foreign, trusted): CPython 3.11.15, git, sh. T1 (self-hosted enforcement): the stdlib-only gates - Python code that parses Python code with `ast`, checking its own species (`violation_ratchet.py:160` flags `shell-true` in scanned files while its own subprocess calls at :101-107 use list-argv, `timeout=60`, and return `None` on git failure per the docstring at :100 "None = git broke"; the None downstream handling was not traced this ask). T2 (the organism): `config.py` → verkle knot → everything, with the call graph free to recurse because the import graph stays a star around one axiom. The design law this encodes: **enforcement must have an empty closure; structure may recurse only where the loader never walks.** One external axiom remains outside T2 and caps the bootstrap: `config.py:29` hard-points the sibling `_REPUBLIC = (ROOT.parent / "mycelial-republic")` - the estate cannot recompile itself from this repo alone; the constitution lives one directory over.

Limits, stated: instruments were static (ast); no runtime `sys.modules` tracing was run, so call-time reachability is approximated by lazy-import presence, not execution; the "third-party" bucket in `_w4_depgraph2_out.json` mixes genuine externals (reportlab 59, yaml 24, langgraph 3, fastapi 3, torch 3) with repo-local packages outside the walked roots (`agents/`, `dashboard/`, `handoff/`); `watch/` turns out to be an importable package (`watch/__init__.py` exists). No gate was executed this ask beyond reading; the ratchet/scenario suite results cited in AGENTS.md were not rerun here.
