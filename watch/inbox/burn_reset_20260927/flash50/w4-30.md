# w4-30: Multimodal memory in the estate - the hash-indexed sensorium

Ask: design how text receipts, image drops, audio transcriptions, and video references integrate into unified memory, and name the cross-modal retrieval paths. Everything below is grounded in files read this session (paths and lines cited) or in checks I ran here (named with output). Nothing is asserted from memory of other sessions.

## 1. Thesis: the estate already has a memory theory, and it is not an embedding space

The estate's unified memory is best described as an **indexing theory of memory**: content lives in bytes on disk (the cortex), memory lives in the pointer graph over those bytes (the hippocampal index), and the index language is text plus one identity operator, sha256. This is Teyler and DiScenna's hippocampal indexing theory (1986) implemented as a filesystem discipline: the hippocampus does not store the episode, it stores a sparse index sufficient to reinstate the cortical trace; here the chain tip, the catalog map, and the caption/media registers do not store the image or the audio, they store path + hash + derived text sufficient to reinstate the bytes on demand.

Three laws already on the books make this non-metaphorical:

- "Prefer an artifact plus bounded pointers and hashes over a copied transcript" (watch/inbox/SHARED_SURFACE_CONTRACT.json, laws list, printed this session).
- "Our estimation of the thing must not replace the thing. Every byte-serving tool echoes the sha256 of exactly the bytes served" (tools/corpus.py:9-11; cap at tools/corpus.py:70).
- Bounded event pointers: memory_event.v1 caps artifact_refs at 12 strings of 240 chars with a scope_hash (mag/memory_events.py:56-57).

So the answer to "how do modalities integrate" is not "put images in the vector store." It is: every modality enters memory as a **register row** - (path, sha256, modality, derived text, provenance, status) - and retrieval is a join over identity (hash equality) plus lexical search over the derived text. The estate runs this today, incompletely, across four modality organs.

## 3. The cross-modal retrieval paths that exist today

- **P1 text to text**: corpus_search over path+title via scan (substring-AND) or FTS5 (token/phrase-prefix), with the engine, index_state, and the B2-22 parity note attached to every answer because the two engines disagree honestly (tools/corpus.py:14-34); body text since Q4 via receipt_body_fts. Map-plane freshness disclosed on every map-derived answer (C6 policy, tools/corpus.py:39-48).
- **P2 text to image**: search caption text in the caption ledger, or join kind=image rows in tags.jsonl, then re-verify bytes by sha (the gate I ran). Identity is the join key, not similarity.
- **P3 image to text**: mag/vision.py:68-102 transduces pixels to a description through deepseek-v4-flash-vision-exp (image in USER message only, base64 or URL). Separately, mag/whisper_image.py:103-191 makes the image itself the storage: text payload XORed with a secret keystream hidden in PNG LSBs under the WHSPIMG1 magic (line 57). **Executed this session**: encode_image of a probe string produced a 40,914-byte PNG, decode_image recovered the exact payload (match True), and the wrong secret correctly failed with "decoded bytes not utf-8 (wrong secret?)". That is a lossless text-image-text retrieval path, keyed - retrieval IS the secret.
- **P4 audio to text**: transcribe_file (mag/voice_stt.py:75-111); the transcript can then ride P1. The upload blob is retained, so the transcript is re-derivable from bytes at any model quality later.
- **P5 video to audio to image to numbers**: media_register row, ffprobe, spectrogram PNG, pixel thresholds, anomaly row plus receipt (the50_t08_spectro.py:6-25). A video reference in memory is a register row whose "content" is a chain of derived artifacts, each individually hashable.
- **P6 text to geometry (the reverse direction)**: mag/visual_pack.py:499-557 renders the living record into a deterministic seven-chamber geometry whose commit is a sha over its inputs ("Same session_id + same living record -> same commit when inputs unchanged", line 553); mag/rib_gif.py:1-18 compiles a RIB into a deterministic GIF-render spec so the image is a legible TEST INSTRUCTION - "same rib -> same gif (re-derivable)", line 66. Memory can be rendered out as image whenever the image is a proof.

## 4. The gap, stated honestly

(a) **No dense path.** All retrieval is lexical plus join. CLIP (Radford et al. 2021) and ImageBind (Girdhar et al. 2023) bind modalities in a shared embedding; the estate binds them by hash join over derived text. The difference is epistemic, not merely technical: a cosine hit is unfalsifiable after the fact, a sha join is re-verifiable forever, which is why the trust-first estate chose joins. The cost is recall: the B2-22 spike already measured the lexical engine missing mid-token hits (3 of 10 queries short, tools/corpus.py:21-27) - the same shape of blindness, one level up, would be "the caption that used different words than your query." (b) **The caption gap.** The sha gate proves ledger bytes match disk; nothing proves the caption describes the image. The caption is an estimate; the law "estimation must not replace the thing" (corpus.py:9-11) is the estate's own rule for treating it: derived text is a finding, the bytes are the artifact. (c) **One-to-many bindings both ways.** In the three caption-ledger rows I sampled (msg_176, msg_177, msg_178), three different messages with three different captions all carried the SAME sha256 and the same 4,727 bytes - one recovered thumb bound to many episodes. Cross-modal memory must model artifact-to-many-captions AND caption-to-many-artifacts; a naive image-to-vector design flattens the first multiplicity silently. (d) **No audio transcript register.** Voice uploads persist at memory/agent_uploads/voice_stt but nothing ledger-rows them the way the caption ledger rows images. (e) **The pack is text-totalitarian.** Every layer of the context pack is a string (mag/context_pack.py:884-953); modality reaches working memory only after transduction at the door, exactly Baddeley's phonological loop converting speech to an inner code. The pack's clip ladder (drop L4 heat, compact L3, shed L0d/L0f context, hard clip, each shed receipted to watch/inbox/PACK_OFFLOAD.jsonl, context_pack.py:34-49, 1235-1278) is MemGPT-style paging (Packer et al. 2023) with an eviction log - but it has no budget lane for "one image worth 384 tokens" (the deepseek resize economics documented at mag/vision.py:6).

## 5. The design

**media_register.v2**, one schema generalizing the three existing registers: rows of {path, sha256, modality in (text,image,audio,video), derive: {kind: caption|transcript|spectrogram|lsb, text, via, model, ts}, cite, provenance, status}. Identity by sha; meaning by derive.text; NEVER conflated. Derived text indexes into an external-content FTS5 built by the one-sanctioned-writer pattern (tools/corpus_fts_rebuild.py:1-27) with the meta-table freshness contract (bytes + mtime + deep sha). Five laws:

1. **Transduce at the door, register the byproduct.** Every image drop gets a caption row; every audio blob gets a transcript row; the derivation names its model in `via` (the ledger already carries caption_via and recovered_provenance - the schema exists, it just does not cover audio).
2. **Identity by hash, meaning by estimate.** The caption/transcript is admissible evidence, never the artifact; any claim past the sha is a finding requiring corpus_get (the FTS-only "path and title" blindness that Q4 fixed for text bodies, receipt_body_fts.py:4-9, is the same disease one modality over).
3. **Re-derivability over persistence.** Store the small truth, regenerate the big artifact: whisper_image's keystream regenerates the payload from bytes, visual_pack and rib_gif regenerate geometry from record, the spectrogram pass regenerates PNGs from video. Memory compresses to generators plus hashes, not artifacts - the engram's template-plus-delta with payload_hash verify-on-read (mag/engram.py:54-77) is the same move inside pure text.
4. **Registers are living surfaces with the C6 disclosure.** A stale register is a wrong memory (the Sep-18 map answered every question with a week-old estate, corpus.py:39-48); every modality answer carries map_asof and age, and the drift detector (caption_ledger_sha_check as post-write gate, caption_ledger_sha_check.py:7-9) generalizes to all registers.
5. **A modality lane in the pack (L1m), staleness visible.** One bounded slot: "3 images, 1 audio, 0 video in scope; captions fresh/sha-verified," rendered like the quantized-laws block renders staleness as debt (context_pack.py:343-392). What cannot fit rides as bounded pointers; the model that needs pixels climbs to the vision transducer - which is exactly the endowment result: scripts/vision_endowment.py:1-25 proved the blind/endowed/native arms differ only at the tool boundary, "the endowment is the tool boundary, whichever transducer it picks" (line 15). Flamingo (Alayrac et al. 2022) fuses vision by gated cross-attention inside the model; the estate fuses it by tool call at the boundary, and its own falsifier says that boundary, not the retina, is the unit of sight.

## 6. What this is, in one line

The estate's cross-modal memory is a sensorium whose lingua franca is the hash: modality lives at the edges (transducers), text lives in the index, bytes live in the territory, and truth is enforced by sha equality between index and territory. The build order is small and in house style: transcript ledger for audio, caption pass over the 31,837 image-kind rows (local ladder first), media_register.v2 unify, register-wide sha patrol, L1m pack lane. Not run this session: any dense-encoder path (none exists in the estate to run), and no full-ledger sha pass (only --limit 50).
