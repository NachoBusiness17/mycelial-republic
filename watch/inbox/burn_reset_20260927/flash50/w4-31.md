## 1. The estate's definition of trust is a negation

The single most important sentence in the codebase for this ask is in a docstring: "Trust is not the fix - a CANARY is" (the source line is `mag/chain_guard.py:7`; the docstring says it about the 2026-08-25 incident where the live chain was rebuilt from a pre-repair lineage by a raw restore outside the writer lock, source unidentified, `mag/chain_guard.py:1-12`). The estate's working definition of trust is therefore: trust is a residual, a bug class, something a design is supposed to have eliminated. The shared surface contract says the same thing structurally: inbox content is "untrusted_data_until_classified", side effects route through "switchboard_and_effect_broker_only", and "consensus ... raises confidence but never grants permission" (`watch/inbox/SHARED_SURFACE_CONTRACT.json:87-91`). Workspace doctrine compresses it to "Trust bytes, not reports" (AGENTS.md Clippy block). Luhmann's classical framing (trust as a reduction of social complexity, from training knowledge) describes what most institutions do; this estate does the opposite: it increases complexity (hashes, locks, canaries, exit-code grammars) precisely so that the residual need to trust approaches zero on the paths that carry risk.

That inversion is the game-theoretically interesting fact. A trust game in the textbook sense has a trustor who cannot verify and a trustee who can defect. The estate's design goal, visible in every instrument this ask read, is to remove the first clause: make the trustor able to verify at a cost so low that verification is no longer a strategic choice. When that succeeds the situation is no longer a trust game at all; it is a verification game with only one rational action per node. The formal question is then: where does the conversion succeed, where does it fail, and what happens in the failure zones.

## 3. The stage game, formally

Players: a Reporter R (any seat about to claim "done", "clean", "2,303 tests") and a Consumer C (the next reader of the claim: another lane, a gate, the operator, a future session of R itself). Time is discrete and effectively infinite (the estate is a going concern; seats die but the estate persists, which is what makes the folk-theorem machinery available at all).

Actions: R chooses h (report what the instrument showed) or f (report what R wishes were true: hand-copy a count, skip the run, widen an exemption). C chooses v (verify: run the instrument, re-hash, recompute the root) or t (trust: consume the claim as given).

Payoffs, per stage: verification costs C the amount c. An undetected fabrication gives R gain g and costs C loss l. A detected fabrication gives R a loss L (blocked push, voided claim, named shame in a receipt) and C payoff 0 from having avoided the loss. Honesty gives R 0 and C 0 before costs; with verification of an honest report C pays c for nothing. Detection probability p.

One-shot Nash analysis: if c < p*l then v dominates t for C; against v, f yields g - pL which for any real gate is negative (push is blocked, L >= g), so R plays h; against h, C would rather save c, so (h, t) is also a best response pair - the classic cycle: (h, v), (f, t) unstable, and the mixed equilibrium where everyone verifies everything at real cost or nothing at all. Textbook trust games resolve this with reputation (Kreps-Milgrom-Roberts-Wilson 1982, training knowledge) or with repetition and patience (Fudenberg-Maskin 1986 folk theorem): if C can condition future play on an observed history, cooperation is sustainable whenever players are patient enough. The folk theorem's standing problem is information: it needs the history to be observed accurately (perfect monitoring) and punishments to be credible. Almost every real institution fails at one of the two.

The estate's four mechanisms are each a piece of parameter surgery on this game, and each is findable in the code read this ask:

- M1, public perfect monitoring: the chain is a shared, append-mostly, hash-committed history that no player can quietly rewrite (one flipped field diverges the root; tamper demo measured in the sibling bank Q-047.md section 2 row 7, and re-verified live here at 8,280 leaves). Deviations enter common knowledge. This is the monitoring condition of the folk theorem, engineered rather than assumed.
- M2, verification cost collapse: c is driven toward zero so that v is no longer contingent. Root recompute over 8,280 leaves is sub-second (the guard's canary does it on every check; my receipt 2 took seconds including interpreter startup). Membership proofs are 14 hashes. Exit codes make "verify" a subprocess away. When c < (expected cost of one swallowed lie), t stops being a best response to anything, and the (h, t) cell of the matrix becomes irrational rather than merely risky. This is Holmstrom's informativeness principle (1979, training knowledge) turned into infrastructure: the signal that disciplines the agent must be cheap enough that the principal actually looks at it.
- M3, graduated priors over claim shapes: the gate's blockable/never-block partition (`tools/secret_gate_rules.py:127-142`) is an asymmetric-error-cost calculation written as law. A provider-shaped token is a high-precision signal (false positives are rare, so blocking is cheap and missing one is catastrophic: a rotated credential costs a real invoice). A generic NAME=value line is a low-precision signal (the audit cited there measured a 99.5 percent false-positive rate for GENERIC-KEYASSIGN), so the gate refuses to let it veto. My probe (receipt 4) watched the same run block XAI-KEY and merely count ENV-ASSIGN from two files in one scan. The gate is a game-theoretic actor that declines to make claims it cannot defend - an honesty law for instruments, not just for agents.
- M4, priced restoration: defection is not banishment but a fine. A blocking finding is excused by named acceptance in a baseline file where a reasonless entry is itself a scanner error: "a reasonless allowlist is how gates get silently emptied" (`tools/secret_gate_rules.py:199-213`). The ratchet accepts debt "by NAME" and blocks new debt (AGENTS.md build discipline). The pin ledger accepts drift only via an explicit repin with a reason (`tools/mcp_pin.py:24-26,45`). In game terms: grim trigger (permanent punishment) is softened into a fine schedule with a price F that must be paid publicly and attributedly. Williamson (1983, training knowledge) calls these credible commitments; Axelrod (1984) observed that punishment strategies which keep the game alive outperform strategies that end it. The estate's F is deliberately payable but non-anonymous, which preserves both deterrence and continuity.

## 4. What breaks trust: the measured taxonomy

The incidents the code itself memorializes sort into five mechanical classes and three human ones. Mechanical: (1) out-of-band write, the worst class - a raw restore rebuilt the live chain from a pre-repair lineage, no code path in the repo does that, source never identified (`mag/chain_guard.py:3-7`); the response was the canary, a repair-state marker the live chain is compared against (`:54-66`). (2) Silent divergence between two records that should agree - the tip bookmark froze at a poisoned snapshot while rows continued (CHAIN_STOP, `:90-95`), and the fix taught the estate a meta-lesson: a mismatch field that rides inside a "healthy" verdict is unconsulted decoration, so tip_stale was promoted to its own actionable state (`:151-161`). (3) Corruption invisible to content verification - a text-mode writer rewrote every LF to CRLF while content checks stayed green; only a raw-byte read catches it, so the guard now reads bytes, not parsed content, for exactly this class (`:78-87`, `:120-131`). (4) The blind instrument - the gate's combined alternation matched non-overlapping, so generic NAME=value alternatives swallowed lines and a real provider key landed report-tier instead of blocking (GATE_DEFECT_ASSIGNMENT_BYPASS, `tools/secret_gate_rules.py:144-155`); the gate looked green while seeing nothing, which is class (4)'s signature: the instrument's silence was mistaken for the world's cleanliness. (5) Noise floods - 48,427 hits burying one critical (`tools/secret_gate.py:16-22`), the Green-Porter (1984, training knowledge) world where the public signal is noisy: the estate's answer was not to punish anyone but to clean the signal (entropy floor at 4.3 bits/char, hex sits near 3.9 and cannot pass, `:20-22`).

Human: (6) laziness-fabrication, the retired "1,341 tests" census headline hand-copied for 12 days while 31 files grew (AGENTS.md B2-215), which produced the deepest law in the workspace: name instrument, moment, and delta before comparing counts, and treat an unattributable drift as a fabrication smell (B2-246). (7) Attribution violation - a concurrent lane's staged change rode into another lane's commit through the shared git index; the remedy recorded was full disclosure in the receiving receipt plus a pathspec-commit discipline (`watch/inbox/burn_reset_20260927/queue/Q-001.md:41-43`). (8) Upstream mendacity by malfunction - rate-limited workflow children surfacing fake "subscription" errors, i.e., a provider's failure mode wearing the costume of a different failure mode; the estate's fix redefines the dispatch shape so the lie cannot propagate (`maxAttempts 0`, AGENTS.md fan-out law).

The pattern across all eight: none of them is a sophisticated adversary. Every break in the estate's lived record is an accident, a shortcut, or a signal-quality failure. The game-theoretic consequence is that the estate's defenses are aimed almost entirely at the f-by-negligence strategy, not the f-by-cunning one, and the instruments are tuned accordingly: deterministic, cheap, byte-level, fail-closed.

## 5. What restores trust: restoration is a priced move, not a feeling

Every restoration mechanism read this ask has the same shape: a public, attributed, priced act that converts a detected deviation back into common knowledge. The canary is re-marked only AFTER a repair lands, recording expected state, root, timestamp, and who (`mag/chain_guard.py:54-66`). A blocking secret finding is closed by excise, rotation, or acceptance "by name in configs/secret_gate_baseline.json (accepted_by + reason ...) ... never loosen the hook" - the gate prints this instruction itself (`tools/secret_gate.py:282-284`). Drifted MCP surfaces survive only through repin with a reason string (`tools/mcp_pin.py:45`). The census claim is refreshed only from a fresh collection run with the landings that moved the count named (AGENTS.md B2-246). Even the workflow gate participates: a red workflow is amended, not rewritten, so the failure row stays in the ledger (AGENTS.md workflow-gate block). And disclosure itself is a restoration move: Q-001's correction section volunteering that its own commit carried a stranger's staged file is precisely the act that keeps the shared index race from eroding trust in every other commit (`Q-001.md:41-43`).

Note what is absent: forgiveness without record. There is no mechanism that restores trust by forgetting. The chain has an amend path and a planned compaction, but both are operator-gated (Q-001 stands unexecuted pending operator GO as of this writing) and both leave hashes of the pre-state in the archive anchor. Restoration in this estate always costs F and always leaves a receipt; a restoration that leaves no trace would be indistinguishable from a cover-up, and the design treats that equivalence as the threat model.

## 6. Equilibrium analysis

Proposition (informal but checkable against the receipts): under M1 through M4, the profile (honest report, verify-always) is the unique stationary pure-strategy equilibrium of the stage game as actually played, and it is subgame-perfect in the repeated game because the punishment (detection plus a permanently consultable record) is triggered by the deviation itself rather than by anyone's willingness to punish. Grim trigger usually fails because someone must bear a cost to carry out the punishment; here the gate carries it automatically and the chain remembers it for free. That is the folk theorem with the two hard parts - monitoring and credible punishment - implemented as code paths this ask ran (receipts 1, 2, 4).

Three residual equilibria persist, and the estate's attitude toward each is different and instructive.

First, the noise-tier equilibrium. For generic claim shapes the gate concedes that p is irreducibly low and refuses to block (class 5 above); reporters of generic-shaped findings and consumers of them settle into a profile where findings are counted but never enforcing. The estate does not pretend this is trust; it marks the tier "report only" and stores counts with a results path, never the flood (`tools/secret_gate.py:24-27, 255`). Quarantining an unreliable signal into a non-blocking role is better game design than raising a false alarm rate into the blocking path: a gate that blocks on 99.5 percent false positives trains every player to bypass it, which is the true death of a gate.

Second, the quarantine equilibrium for untrusted players. Free stealth lanes are doctrinally "a SENSING surface only - their outputs are banked as findings, never as done/trusted work" (AGENTS.md driving ladder); quantized tiers are read-only in the MCP manifest. Rather than spend mechanism making untrusted players honest, the estate caps the payoff of their defection by capping their authority. In payoff terms: when you cannot raise p, lower g. That is why the equilibrium holds without any punishment of those players at all.

Third, the normalization hazard, live right now: the chain canary is red (receipt 1), has been red since before 2026-09-26 (marker_at), and work proceeds. A permanently firing alarm carries no marginal information; the classical failure is alarm fatigue, where the next, real regression hides inside the acknowledged one. The estate's counter is that the red state is in common knowledge, not habit: Q-001.md:25 discloses the exact numbers and states "this item did not create the regression," and the planned compaction's apply() re-marks the canary with post-fold truth. The information content is preserved by documentation rather than by silence. Whether that survives five more weeks of red is an open empirical question, and it is the single best candidate for what would break the equilibrium next: not a clever adversary, but an acknowledged alarm aging into wallpaper.

The meta-game, finally: every instrument named here is code written by the same class of agent it gates. The ratchet is a self-steal; the workflow gate enforces the no-fabrication law inside the asks it gates; the scenario suite re-validates the gate's own behavior against real registry FAIL rows (AGENTS.md build discipline). Self-referential enforcement cannot close over itself - a coalition of all players could always vote the rules away - which is why the constitution phrase "never loosen the hook" (it appears in the gate's own operator-response line, `tools/secret_gate.py:284`) is enforced by nothing except doctrine, and why the terminal authority is an operator GO that no gate can simulate (`Q-001.md:5,12`). Every formal trust system terminates in an unformalized principal; the honest statement of this estate's Nash equilibrium is conditional on that principal's continued refusal to accept baseline debt anonymously, re-mark canaries lazily, or GO chain rewrites casually. Those refusals are the only moves in the whole game that no mechanism checks.

## 7. Verdict, falsifiers, not run

Verdict: the estate does not solve the trust game; it dissolves most of it (M1, M2 convert trust decisions into verification reflexes), quarantines the rest (M3 moves low-p signals out of the enforcement path; doctrinal quarantine caps g for untrusted players), and prices the remainder (M4 makes restoration public, attributed, and costly). Where trust genuinely remains - the operator's judgment, the residual dangling-evidence class, the can't-compute paths instruments honestly report - it is enumerated rather than hidden, which is the strongest thing a trust architecture can say about itself.

Falsifiers: (a) a fabrication that survived M1-M2, i.e., a materially false claim that passed a gate and a chain check and was later caught only by luck, would falsify the p-approx-1 premise for the classes that matter; (b) a silent loosening - a baseline entry, repin, or ratchet debt accepted without by/reason making it through - would falsify M4's premise that named acceptance is mechanically enforced; (c) the standing red canary still red with no operator GO and no re-mark a month from now would confirm the normalization hazard as the live failure mode; (d) a second out-of-band chain restore (class 1) would show the canary detects but does not deter the one adversary class it was built for.
