## 1. Thesis: a semantic diff is three comparators, not one

"Semantic diff" is usually designed as a smarter version-vs-version compare. The estate's own instrumentation proves that is only one third of the problem. `tools/census_drift_patrol.py`, read in full this session, runs three distinct comparators inside one tool:

1. **Mode A, version vs version.** `test_files_added_since` (tools/census_drift_patrol.py:219-247) walks `git log --diff-filter=A` to compare the carrier's snapshot against committed history. This is git's native territory.
2. **Mode B, claim vs world.** `patrol()` (tools/census_drift_patrol.py:250-288) compares a claim written in prose against measured bytes: commits landed after the census day, on-disk candidate counts. The claim is treated as a hypothesis about the world, and the world is re-measured.
3. **Mode C, artifact vs contract.** `parse_carrier` (tools/census_drift_patrol.py:148-170) tests the artifact against a grammar (`CENSUS_CLAIM_RE`, :117-119) and fail-closes to None on any shape mismatch, which `run()` maps to exit 2 (:305-309).

Most diff tooling, including git itself, implements only Mode A. The estate built B and C first because its disease was never "which bytes moved" but "does this report still tell the truth". That inverts the usual design order, and it is the right order: Mode A without B and C is a chatty noise generator (a receipt reflow is a wall of red), while B and C without A cannot localize which claim moved. The design conclusion: **the estate differ is one pipeline, `extract -> canonicalize -> key -> classify`, run three times with three different second operands** (the prior version, the measured world, the declared grammar), sharing one verdict vocabulary: exit 0 lawful-or-unchanged, exit 1 named drift with the delta printed, exit 2 cannot verify (tools/census_drift_patrol.py:30-32).

## 2. The change-class algebra

A change class is a 4-tuple: **(preserves, breaks, witness, audience)**. What invariant holds if the change is lawful, what invariant fails if it is not, what byte evidence distinguishes the two, and who must react (nobody, the lane, the operator, or a gate). Unverifiable states are not a fifth category; they fail closed to exit 2, never to a guess, the convention `parse_carrier` already fixed.

Read this way, the estate's gate history is a sequence of change classes discovered in the wild and then hardcoded, one per gate:

| Estate law | The class it discovered | Where I read it |
|---|---|---|
| B2-215 stale-carry | a report frozen while the world moved under it | tools/census_drift_patrol.py:2-7 |
| B2-216 denominator mismatch | two counts taken by different instruments at different moments differenced as if comparable | AGENTS.md Clippy bullet; census_drift_patrol.py docstring |
| B2-245 order poisoning | extraction reads the first matching number instead of the anchored claim | census_drift_patrol.py:84-96 |
| B2-249 grammar break | a reworded carrier silently becomes unparsable | census_drift_patrol.py:97-116 |
| B2-274 grammar ownership | the differ's own grammar and fixtures drift apart from the live artifact | census_drift_patrol.py:97-116 |

The general design is the algebra; each gate is one row of its table. Directionality is a first-class property inherited from `collect_patrol` (census_drift_patrol.py:197-216): an over-claim is the worse direction everywhere ("an over-claim is worse (tests removed or a number invented)"). Classes are therefore signed: cap shrink, count shrink, and history rewrite are negative-direction classes that gate; growth classes mostly bank and log.

## 3. Markdown receipts: diff claims, keyed by identity, in three modes

The receipts are not one genre. `ls watch/inbox/burn_reset_20260927/flash50/*.md | wc -l` returns **298 files** in this directory alone, in visible families (w4-*, f-*, s2-*, r-*, deep-*, oral-*, sess-*, stealth-sw-*, *-census.md). A differ with one grammar for all of them would misparse most of them; per-genre grammars are the design, and an unparsable new genre is a discovery event, not an error.

The claim grammar is exactly what the census carrier proves: status vocabulary, numeric claims, path pointers. The live run this session: feeding AGENTS.md to the estate's own `parse_carrier` returned `{"date": "2026-09-27", "collected": 2303, "files": 352}`, matching the AGENTS.md Clippy bullet. The extractor exists, runs, and is fail-closed.

Change classes for markdown receipts, with the tuple fields made explicit:

- `CLAIM_ADDED`: preserves append discipline; breaks nothing; witnessed by a new claim identity; audience lane. (New work banked.)
- `STATUS_ADVANCE`: preserves the ratchet direction (plan-only to LANDED); the reverse, `STATUS_FLIP` (LANDED back to OWED without a supersession pointer), is the fabrication class; witnessed by the status token under the same claim key.
- `NUMBER_REFRESH`: preserves the claim, updates byte truth (census date bump). Distinguished from `NUMBER_SHRINK_UNNAMED` by direction and by the presence of a receipt pointer; the asymmetry is `collect_patrol`'s, cited above.
- `REPHRASE` / `REORDER`: preserve the claim set; witnessed by k-gram fingerprints per claim (winnowing, Schleimer, Wilkerson and Aiken, SIGMOD 2003) so a reordered receipt classifies benign instead of triggering `CLAIM_LOSS`, the fatal class where a claim identity vanishes.
- `POINTER_ROT` and `STALE_CARRY`: these are Mode B classes, invisible to version-vs-version diff. A receipt byte-identical across versions can still be false because the path it cites moved or the count it froze aged out. The census patrol is the estate's working proof that the B-mode comparator is buildable.

The Myers O(ND) algorithm (Myers, Algorithmica 1986) and its Hunt-McIlroy ancestor (1976) remain the correct layer 0: git keeps doing bytes. The Semantic Line Breaks convention (one clause per line) is the cheap authoring law that makes line diff approximate claim diff; the estate's JSONL ledgers already obey it and its markdown receipts do not, which is why ledgers diff cleanly and receipts do not.

## 4. Python modules: surface, body, debt, and the cross-media join

Live probe this session (exact output in section 8): an AST inventory of `mag/prose_census.py` HEAD vs worktree found functions `['_age_days', 'run_census']` on both sides, `added: []`, `removed: []`, `signature_changed: []`, `body_changed: ['run_census']`. Thirty-odd changed lines reduce, in about forty lines of stdlib Python, to: surface stable, one body changed. That is the difference between a diff and a verdict.

Classes, cheapest to most expensive to verify:

- `FORMAT_ONLY` / `SEMANTICALLY_IDENTICAL`: same `ast.dump` modulo naming; comment and receipt edits classify here for free.
- `CONSTANT_FLIP_ONLY`: same shape, new literals. In `tools/` gate scripts this is exactly the debt class the ratchet requires accepted BY NAME (AGENTS.md build discipline: "Accept debt by NAME ... or fix it").
- `BODY_CHANGED`: behavior candidate; demands a test run. This is verification budgeting, the equivalence-testing school's actual contribution: semantic diff decides where expensive behavioral evidence gets spent.
- `SIGNATURE_CHANGED`: caller risk; needs the import graph (blast radius), one step beyond the probe.
- `API_SURFACE_CHANGE`: functions added or removed; the manual ancestor is SemVer.
- Estate-native classes: `DEBT_REGISTERED` (a `configs/violation_baseline.json` row is itself a semantic event), `GUARD_BRANCH_ADDED` (the build-discipline law bans fallback-branch creep; detectable as a new branch whose join reaches no state change), `RECEIPT_COMMENT_LOST` (fix comments must carry the receipt, so a deleted evidence comment is a class, not formatting), and `FILE_BAR_CROSSED` (the ratchet's 400-line bar, cited in census_drift_patrol.py:40-44).

The one class that cannot exist in any single grammar: `SPEC_ORPHAN` / `BEHAVIOR_ORPHAN`. "Spec before behavior change" (AGENTS.md build discipline) means a lawful python diff must co-occur with a markdown diff owning the spec. The class exists only in the JOIN of the markdown grammar and the python grammar, which is the structural argument for one differ over four media rather than four tools.

Literature anchors: ChangeDistiller (Fluri et al., IEEE TSE 2007) maps fine-grained AST edits to named change types, which is this taxonomy's academic form; GumTree (Falleri et al., FSE 2014) is the matching substrate; RefactoringMiner (Tsantalis et al., 2018) detects the semantics-preserving subset so `BODY_CHANGED` can be downgraded honestly; difftastic and tree-sitter are the production substrates if coverage ever needs to exceed stdlib `ast`.

## 5. JSONL ledgers: the key law is part of the artifact, and hashes have instruments too

Live check this session on `memory/burns/LEDGER.jsonl`: HEAD holds 654 rows, the worktree 693. The naive O(1) classifier, sha256 of the first 654 worktree rows against sha256 of the HEAD blob, returned **PREFIX_STABLE no** (hashes `352bc396...` vs `9341e6a6...`). After stripping carriage returns on both sides, both hashes are `9341e6a6a64d...` byte-identical: **PREFIX_STABLE yes**. Cause, measured: this clone has `core.autocrlf=true`, so worktree rows are CRLF while `git show` emits LF. The ledger was lawful all along; the raw-hash instrument fabricated a `PREFIX_MUTATION` verdict out of representation noise.

This is B2-216's denominator law applied to hashes: same bytes, different instrument, different verdict, and the instrument must be named. It also refines the sibling card's finding (its v1 slug-keyed probe lied, its v2 parsed-row probe was immune): the parsed-row form is noise-immune but O(n); the hash-prefix form is the O(1) production shape a daily patrol needs, and it is safe **only after canonicalization** (CR strip, or re-serialize each row to canonical JSON). A differ that skips canonicalization is itself a fabricator.

Classes under a declared key law: `APPEND` (lawful everywhere; the +39 tail rows here), `PREFIX_MUTATION` (any history row changed at its index: the fabrication class), `REORDER` (set-equal, position-changed; lawful only under a declared compaction contract), `DUPLICATE_KEY` (lawful for this ledger's re-verdicts: my `comm` count found 4 of the 39 appended rows re-verdicting a slug already in HEAD; the remainder are new slugs), `SCHEMA_EVOLUTION` (new keys in rows), `UNPARSEABLE_ROW` (tail poison, exit 2 even when the byte diff looks clean), and `COMPACTION` (a sanctioned rewrite under a verkle-style commitment, per the estate's own compaction lane).

The key law differs per ledger, read this session: `memory/burns/LEDGER.jsonl` is positional append (verdict vocabulary {steal, green, built, vacuous} in the sampled head rows); `memory/workflows/REGISTRY.jsonl` is keyed by (name, digest) with a verdict and per-check booleans in each row; `catalog/junctions.jsonl` is id-keyed with self-remediation fields (`"action": "pruned"`, `"violation": false`). A ledger handed to the differ with no declared key law is exit 2, not a guessed key. The estate's receipts-to-ledger direction also runs the other way: the session's own git status snapshot shows dozens of JSONL trails and ledgers modified per wave (dashboard/static/trails/*.jsonl, memory/game/FLOW_LEDGER.jsonl, memory/burns/LEDGER.jsonl), which is why the daily form must be the canonicalized prefix hash, not a full row walk.

Literature: Kreps, "The Log" (2013) and Fowler's event-sourcing pattern define the append-only contract; Kafka log compaction is the sanctioned-rewrite contract; RFC 6902 (JSON Patch) and RFC 7396 (JSON Merge Patch) assume random-access mutation and are the wrong default for append-mostly ledgers; CRDTs (Shapiro et al., SSS 2011) govern concurrent append merge, which is the fleet's real topology: many lanes appending to one ledger.

## 6. Lua scripts: two trees, manifests, hidden thresholds, and schema migration

The estate has **two** Lua trees, measured this session: `game_roblox/` (6 tracked `.lua` files, 11 `.luau`, last commit 2026-09-25 23:42:10 -0400) and `roblox/` (51 tracked `.luau` files, last commit 2026-09-28 14:51:31 -0400, the active port, `--!strict` 51/51 per flash50/luau-census.md:16). Any differ design that treats "the Lua" as one corpus is already wrong; the trees differ in dialect, strictness, and verification depth (luau-census.md:76-78: 2 of 51 files have executable checks, 0 have a playtest receipt).

Reading the legacy tree grounds four classes the port's manifest grading does not cover:

- `MANIFEST_TUNING` vs `MECHANICS_CHANGE`: `GameConfig.lua` is a named-constant manifest (CHAIR_COUNT 6 at :16, boss phases :19-30, realm unlock thresholds :70-76). A value change inside a declared law class is tuning; a class change is mechanics and goes spec-first per build discipline. The port's own law is receipted in the Q-032 commit message I pulled this session (scale law documented one place, composition order load-bearing, `POP_CAP 45 stays a cap`).
- `HIDDEN_THRESHOLD_CHANGE`: `ShadowLedger.lua:67-75` branches player disposition on comparison constants (`counted > ignored * 2`, `ignored > counted * 2`) that appear in no manifest. Manifest diffing is structurally blind to these; the differ needs body-constant extraction over comparison nodes with integer literals. This is the class most likely to silently rebalance a game while every manifest-oriented check stays green.
- `SCHEMA_ENUM_CHANGE`: `GameConfig.SHADOW_LEDGER.ENTRY_TYPES` (:40-47) feeds `ShadowLedger.countType` and `getDisposition` (:48-76), and entries persist to a DataStore literally named `"ShadowLedger_v1"` (:12). An enum value change is not a rename; persisted rows carry the old string forever, so it is a data migration whose only existing marker is the version suffix in the store name. The differ class: any change under an enum feeding a versioned store is `SCHEMA_ENUM_CHANGE` and demands a store version bump.
- `NARRATIVE_TEXT_CHANGE`: the hint strings (:24-29, :59-67) are content, not mechanics; the header law "Never state the truth. Hint." (:5) makes their register itself a contract, which is a grammar question, not a constant question.

For the port, the estate already owns the end-state loop: the Q-032 machinery pins module bytes by sha256 and refuses blind check regeneration, and its own commit records the differ catching a real bug mid-pass (a method-call Trail on plain-table state, replaced by a strict-clean free-function API). The design is to make that loop mechanical: any Lua edit mints or refreshes a sha-pinned executable check, because with 49 of 51 files having no other semantic witness, **the differ is not an aid on this surface, it is the only automated truth**. Blast radius comes from the require graph (luau-census.md:90-94: SeedRng required by 10 files), so a `SIGNATURE_CHANGED` in SeedRng is a ten-file class.

## 7. The unified verdict, its hooks, and its own history

All four media share: extract, canonicalize, key, classify, verdict; exit 0/1/2; signed classes with the over-claim direction worse; fail-close on grammar break, undeclared key law, or unparseable row. Hooks at the surfaces that already gate: pre-push (alongside the ratchet and the scenario suite) for py and jsonl, the daily patrol cadence for markdown carriers, day-end pile for receipt directories, and the Lua check-minting loop per module edit. The differ's own verdict history must itself be an append-only, slug-keyed JSONL subject to its own prefix law, or the estate has built an unaccountable judge. Two laws inside the asks bind the differ's outputs too: the no-fabrication law (an unverifiable state is reported as unverifiable, which the exit-2 convention already encodes) and the em-dash law (this file obeys it).
