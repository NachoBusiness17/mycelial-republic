## 2. The lattice at rest: six genres on a warrant axis

Order the genres by warrant strength, the load a genre's claims may bear downstream:

```
W0 shitpost (phatic)  <  W1 finding (sensed)  <  W2 brief (situational)
      <  W3 receipt (evidential)  <  W4 done-work (verified)
      <  W5 law (binding)  ->  W6 canon (verkle-knotted)
```

Each genre is fixed by five coordinates: authority locus (who may write it), warrant (what backs its claims), decay class (how it ages), location grammar (where it legally lives), and counterparty (who consumes it).

- Shitpost. Authority: any ractor mask drafts, the operator holds the trigger finger (shitpost-desk-workflow.md:12). Warrant: none as claim; its warrant is craft, and even craft is bounded (TAKE_BOARD.md:21 "no invented facts"). Decay: none; it is conversation. Location: queue/shitpost/TAKE_BOARD.md, watch/room.jsonl (4.69 MB and growing today), SHITPOST_DESK_* inbox receipts for filed slates. Counterparty: the public feed, via the operator only.
- Finding. Authority: any seat, but fenced by funding: free-lane sensing is "banked as findings, never as done-work" (RIB_DRIVING_LADDER invariant 2). Warrant: a hedge; the estate's own vocabulary encodes it (UNPROVEN, PARTIAL, EVIDENCE-MISSING). Decay: until verified or refuted. Location: watch/inbox, unclassified by default. Counterparty: the next rung of the ladder.
- Brief. Authority: regenerator tools. Warrant: recency; a brief asserts the world NOW and therefore carries a clock. Decay: hard, 7 days while the repo has heartbeat (freshness_check.py:53-54). Location: memory/briefs/, state/. Counterparty: the booting seat.
- Receipt. Authority: any seat, but revision is constrained: the inbox is derived from an append-only event log, nonce-gapped and warning on gaps (INDEX.json fold_warnings). Warrant: bytes, hashes, named commands. Decay: none; a receipt only gets VOIDed cross-sign or sealed, never quietly edited. Location: watch/inbox canonical paths. Counterparty: every later genre that cites it.
- Done-work. Authority: the funded tier or whoever ran the bytes ("Trust bytes, not reports"). Warrant: a receipt plus a verification act. This is not a file genre; it is a claim genre - the property a claim acquires after T3 below.
- Law. Authority: operator, or the gated promotion pipeline. Warrant: enforcement, either code (a gate that exits nonzero) or ritual (boot-order). The machine-readable registry is precise about this: a law row is trigger/condition/action/guardrail plus a source pointer into a session transcript (registry.json LAW-1 source `[763e2ef0:19]`), and the enforcement trail is the receipt stream of its firings. A law with no executor is a visible species: LAW-10 sits in the trail with applied:false, "no executor" - registered, dormant, honest about it.
- Canon. The chain. Terminal because cold: "amend cannot strip core" (DNA.md:42). Entry is gated by FILE decision; the shitpost law forbids auto-compiling play knots onto the chain ("Promote to Verkle only when FILE says so", SHITPOST_SCALAR_KNOTS:21).

Two boundary decisions deserve to be called design, not accident. First, receipt is separated from fact by acceptance, not by truth: the classification enum puts RECEIPT in the same five-way set as FACT (contract laws), and INDEX authority stays `untrusted_data_until_classified` even after hashing - a receipt is a record of an act, not a truth token, and conflating the two is exactly the FALSE-RECEIPT attack of section 4. Second, law is separated from rib by enforcement, not by content: the same invariant text can exist as both an AGENTS.md bullet and a rib (the driving ladder is both), because what differs is not the words but the teeth. A rib injects (its force is placement at decision time, via the boot ritual "load ribs, load state, then act"); a law gates (its force is an exit code or a named sanction, with last_enforced_ts and a trail). Ribs are norms; laws are Lessig's law; the pre-push hook is Lessig's architecture. The registry says this out loud: LAW-1's own source string is "we lessig it".

Read the table as a type system and three properties pop out. Demotion is append-shaped and unauthenticated (T7, and the auto-demote inside T3): any witness can add a contest row; nothing is deleted, a later witnessed post upgrades the record. Promotion is gate-shaped and authenticated: every upward edge names a payer (bytes run, funded rung, operator GO, FILE decision). And one edge is involuntary: T5 fires on nobody's action at all. Briefs are the only genre whose decay is a clock rather than a critic.

## 5. Four structural findings

F1 - The estate type-checks genres at edges, not interiors. Document interiors are free-form; every gate sits at a handoff: intake (T2), cite-gate before rightsizing (paste_pipeline STEPS 10), pre-push, promote, freeze, knot. There is exactly one interior grammar police, the census carrier line, and the exception proves the rule: that interior string is itself an interface consumed by a machine reader (parse_carrier), so the estate promoted its grammar into law. Generalization: whenever a document's interior becomes another program's input, its grammar becomes law; otherwise prose interiors stay unpoliced and all checking concentrates at transitions.

F2 - Trust is ratcheted. Demotion moves are cheap, append-only, and need no authority; promotion moves are gated and always name a payer. The violation ratchet is the same shape one level up (debt accepted by NAME, fixes recover, "never by loosening this hook"). Consequence: the lattice's entropy flows toward skepticism. Trust has no default state; it exists only where someone paid for it.

F3 - The bottom type is UNVERIFIABLE, not FALSE. The code distinguishes at least four epistemic values: SUPPORTED (witnessed), DISPUTED (counter-evidence, cache_identity.py:34, contest rows), UNPROVEN (no or non-anchoring evidence, deterministic in cite_gate), and UNVERIFIABLE (the exit-2 family: "cannot-verify condition", "refusing to guess", "no parsable claim... never a guess"). This is a real four-valued logic, and mapping UNVERIFIABLE onto FALSE would itself be an illegal transition: it would let a dead instrument demote a live claim. The estate keeps the fourth value because instrument death must be visible as a distinct state.

F4 - The lattice is closed under one law. No-fabrication binds every node including W0: the shitpost desk inherits sourcing discipline and even the em-dash ban (an AI-tell rule verified by grep in shitpost copy), and workflow gate G7 requires both laws inside every ask, which is how they reached this item. Evidence that closure is deliberate, not incidental: the estate wrote law ABOUT play in exactly the same form as law about routing - SHITPOST_SCALAR_KNOTS has "## Law" and "## Falsifier" sections, and its falsifier names the exact illegal transition ("auto-amending the session tip from /chan replies"). A genre system where the lowest genre carries the top genre's invariant is a lattice, not an archipelago.

## 7. Design: what would make the lattice machine-checkable

(a) A genre header on new inbox artifacts: `g: shitpost|finding|brief|receipt|law-claim`, plus `until:` for briefs and a hash pointer for receipts. Contract law already demands classification (T2); today compliance is social. The INDEX derivation could require the header the way G6_STAMP_RE requires dated stamps, as a soft-warn first (the WARN-ONLY landing convention).
(b) A checked transition table: the T1-T7 and X1-X8 rows, each naming its gate path, with a drift test that asserts each named gate still exists and still exits nonzero where the table says it does. The estate already learned this lesson the hard way once: the mcp-security census (commit 92f154cff in this session's git snapshot) found mcp_pin's check_drift has zero code callers - a rug-pull gate gone dormant. A transition table with an existence test is the general cure for dormant gates.
(c) A phatic class in the intake enum. The five classes (FACT/INFERENCE/PROPOSAL/UNPROVEN/RECEIPT) have no home for a shitpost; an unclassified POST risks being filed as INFERENCE at intake. One more enum value closes X6 at the boundary instead of by desk discipline.
(d) One supersession grammar for all decay. Briefs (FROZEN banner), ribs (RIB_FREE_USAGE_POLICY updated by a later rib's lineage section), and docs (BOOT_4_7 SUPERSEDED in FROZEN_OK) each reinvent the same move. A shared header - `superseded_by: <path> <date> <reason>` - would let one checker police all three decay lanes and would make T5'' self-declaring everywhere, not just in freshness-critical docs.
