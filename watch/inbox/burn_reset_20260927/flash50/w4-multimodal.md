## 2. Thesis: the estate's memory is already modality-unified, at the wrong layer

The unified memory is `catalog/catalog.jsonl`, walked by `mag/catalog_scan.py` over the whole projects parent, and it is perfectly modality-agnostic because it indexes names, not content. The FTS5 index built by `tools/corpus_fts_rebuild.py:75-79` is an external-content fts5 table over `crows(path, title, ...)` - the indexed TEXT is the path and the title, and for a binary the title IS the filename (`mag/catalog_tags.py` never reads bytes either; `classify_kind(path, ext)` at :58-87 routes `.png` etc. to kind `image` at :81-82 purely by extension). So "unified multimodal memory" already exists as a pointer lattice: every pixel, sample, and frame has a row, an id (sha256 of path, first 12 hex), a zone, and a full-text hit on its name tokens.

What does NOT exist is a unified modality-aware READ path. `tools/corpus.py:302-321` (`corpus_get`) refuses binaries outright: `"binary refused", ... "hint": "read binary through a domain tool, not the corpus surface"`. This refusal is the load-bearing design decision, and it is correct. The estate's own law, `tools/corpus.py:8-11`: "our estimation of the thing must not replace the thing. Every byte-serving tool echoes the sha256 of exactly the bytes served." A model's embedding of a photo is an estimation; the estate's constitution forbids promoting estimations to quotable fact. So the architecture question is not "should we add a joint embedding space" but "which cross-modal conversions are legal, and where do their receipts live."

Name the existing pattern precisely: **transcription-gated memory**. A modality becomes memorable to the degree some organ has converted it into the text spine; the binary itself stays on disk as a hash-verifiable artifact that memory can point at but never quote. This is serial coding, not dual coding. Where Paivio (1971) proposes imagery is remembered in TWO code systems (verbal plus imagens) with referential connections between them, the estate keeps exactly one code system (text) and treats the binary as evidence, not as recall substrate. The image is the witness; the transcript is the testimony; memory cites testimony and can subpoena the witness by hash.

P2 - the keyed-decode channel. `mag/whisper_image.py:1-30` implements LSB steganography: `encode_image(payload, secret)` hides whisper bytes in a PNG's least-significant bits; `decode_image(path, secret)` recovers them; Pillow+numpy, deterministic, no LLM, no network. `mag/archetype_image.py:267-286` builds the research-artifact form: a visible Jungian-archetype layer plus a hidden LSB whisper layer, "same payload -> same seed -> byte-identical artifact". This is the estate's ONLY true image-to-text READ path, and it is cryptographic, not semantic: retrieval succeeds with the private map and fails cleanly without it. Note the memory-theoretic elegance: these images are write-once capsules whose content is recoverable but not inferable - the inverse of a caption.

P3 - the rendered-memory channel. Structured state rendered as pixels for the operator's eyes: `mag/session_dossier.py:5-9` emits `memory/biography/<id>/assets/` charts (the census shows 332 images there, `themes.png` and `pipeline.png` repeated across session ids); `mag/art_forge.py:1-24` is a queue-driven image GENERATION lane (grok-2-image primary, cogview-4 fallback, `dashboard/static/art/<id>.png`, forge_log receipt, spend throttle 3/cycle); `mag/df_tileset.py:1-11` is a cross-modal DICTIONARY, mapping map glyphs to CP437 code points into a 16x16 tile sheet - characters rendered as pixels by a fixed decode table. These images are memory OUTPUT, not memory input; they must never be re-ingested as perception, or the estate starts remembering its own diagrams as if they were the world.

## 5. The design: the Bridge Law and the four-channel lattice

Bridge Law (extends the estimation law, does not amend it): **no binary artifact becomes quotable memory until a transcript sidecar exists beside its pointer, and the sidecar is a labeled instrument, never a truth.** Sidecar grammar: `<artifact-path>.card.md` carrying schema `modality_card.v1` = {source_path, sha256_of_binary, modality, instrument (tool+model+version), moment (UTC), confidence or UNKNOWN, text}. This satisfies the estate's two deepest laws at once: "estimation must not replace the thing" (the card never replaces the binary; the binary's sha256 is stored IN the card, and quoting still requires serving bytes) and the census denominator law's spirit (every derived count names instrument and moment; every transcription names its instrument). The V1 voice corpse heals by one line in `voice_stt.py`: after `transcribe_file`, write `path + ".card.md"` before returning. The V3 archaeology heals by one offline batch job. Nothing new is invented; the card is just the companion-card channel (P1) made mandatory and schema'd.

Four retrieval channels, three of which already exist and one of which is a daily task, not an index:

1. Name channel (live): FTS5 path+title, unchanged. Improves automatically as sidecar filenames ride the same index (a `.card.md` is just another text row).
2. Card channel (live, hardened by the Bridge Law): companion cards, thread_eye cards, dossier narratives. This is where cross-modal RECALL actually happens today and where it should be concentrated.
3. Decode channel (live): keyed stego decode via whisper_image as the image-domain read tool, exactly as corpus_get's refusal hint prescribes ("read binary through a domain tool"). Wrap it as `corpus_decode` with the same sha256-echo receipt contract. Crucially, carrier images (stego-bearing, identifiable by their forge/archetype provenance rows) are EXEMPT from automatic captioning - captioning a whisper carrier would leak a secret-keyed payload into a plaintext sidecar. The kind taxonomy in `catalog_tags.py` should grow a `carrier` kind so the exclusion is enforceable.
4. Percept channel (new, batch, budgeted): a MagVisionIndexDaily modeled on the existing MagFtsIndexDaily pattern (AGENTS.md B2-465 bullet: daily task, one sanctioned writer, rebuild-on-exit-2, alert only on surviving failure) that captions NEW watch/inbox intake images (the 7,412 own-zone drops; NOT corpus/library's 16,820 foreign ones - nobody will ever retrieve those semantically) through the funded tier per the driving ladder, writing schema'd sidecars. After captioning, retrieval rides channel 1 and 2 with ZERO index changes, because the caption is a text file the existing FTS5 already indexes on its next rebuild (12.35s full build per `tools/corpus_fts_rebuild.py:8-9`).

The audio policy falls out of the same law: voice stays ephemeral working memory (voice_handoff's own framing: "Local/voice stays the continuous mind", `mag/voice_handoff.py:1-7`; the durable artifact is the filed brief+pack card), but every persisted capture MUST get its card at capture time. Persisting audio without its transcript is persisting a memory you have chosen never to read again.

## 6. Why not a vector store (the counter-case, argued from the estate's own receipts)

The textbook answer is CLIP (Radford et al., ICML 2021) or ImageBind (Girdhar et al., CVPR 2023): one joint embedding space across modalities, nearest-neighbor retrieval across them. Against this estate, the sidecar design wins on five measured grounds. (a) Scale: own-zone images are 7,412 rows, 4.10 GB across all 31,942; a vector index solves a problem an order of magnitude bigger than the one that exists. (b) Staleness: the estate already needed a bytes+mtime+sha256 meta contract to keep ONE index honest against catalog drift (B2-102, `tools/corpus_fts_rebuild.py:11-15`), and still caught C6 serving a week-old estate (`tools/corpus.py:44-52`). An embedding index adds a second drift surface (map staleness, index staleness, embedding-model staleness) - three-headed C6. (c) The no-fabrication law: a nearest-neighbor hit on an embedding is an estimation with no receipt; the sidecar carries instrument+moment+sha256 and remains pointer-plus-testimony. (d) The decode channel is cryptographic and categorically cannot be replaced by similarity search: you cannot embed your way to an LSB payload. (e) Retrieval-augmented generation practice (Lewis et al., NeurIPS 2020) only requires that retrieved evidence be verifiable; late-interaction and reranking tricks (ColBERT, Khattab and Zaharia, SIGIR 2020) are optimizations of recall the estate does not need at n=7k. The genuine loss is semantic image search by CONTENT with no caption ("find the screenshot that looked like a chart") - the percept channel covers exactly that case for the only images that matter, at the cost of one daily task. Whisper (Radford et al., 2022) is already the estate's chosen audio-to-text bridge via faster-whisper; the design merely demands its output be filed, which is the whole of V1.

The multimodal design above is that sentence, systematized: every artifact carries a visible layer (the pointer, the name, the card any seat can read) and a hidden layer (the bytes, decodable only through a domain tool, sometimes only through a key). Pixels hold; only the reading is privileged.
