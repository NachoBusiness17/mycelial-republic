## 1. Diagnosis: the claim-carrier layer is already non-classical, it just has no algebra for it

The estate's classical story is: an effect happens, a receipt records it, the receipt is bytes, bytes are truth. Three probes in section 0 show the story fails in three distinct quantum ways, and the lived record (ladder-02) shows a fourth.

**1a. The superposition that is never persisted.** The broker's own docstring declares a four-state machine: `ENQUEUED -> RUNNING -> COMPLETED / FAILED -> RECEIPT_COMMITTED` (`mag/effect_broker.py:10-11`). But `ENQUEUED` and `RUNNING` exist only inside the `rec` dict in memory (`effect_broker.py:378`, `:404-405`); every path to disk goes through `_commit_receipt` (`:184-198`), which is only called at terminal states (`:385`, `:402`, `:412`, `:420`, `:434`). My tally is the empirical proof: 140 receipts on disk, all RECEIPT_COMMITTED, zero ENQUEUED, zero RUNNING. So an effect that dies between "side effect done" and "receipt written" leaves a world that was changed and a record that says nothing. That window is not hypothetical: the width law has workflow children dying on their first 429/1302 as designed (AGENTS.md fan-out width law), the broker runs in-process, and `fs_write` writes bytes before any commit exists (`_broker_fs_write`, `:318-341`). From the record's point of view such an effect is in a superposition of happened and not-happened, and the estate's reader convention collapses it the worst way: `get_receipt` returning None (`:437-453`) is read as "never ran", when the truth is "ran, or did not, unobserved".

**1b. The verdict that depends on the reader's basis.** `split_rows` (`workflow_gate.py:140-144`) partitions gate rows into failed (not ok, not soft) and warned (soft). A soft row has `ok: false` yet is excluded from the verdict. The scenario suite ran live in section 0 and confirmed the design: fixture `soft_g6.dwf.ts` yields PASS at exit 0 while its G6 row reads ok=false with a reason. The live registry holds 7 such rows among 33. So the same receipt object supports two incompatible readings: `verdict` basis (PASS) and `checks` basis (a not-ok row with an explanation). Neither is false. The truth of the receipt is a superposition that resolves differently depending on which projection the reader applies, and nothing in the row format names the basis. The v3 FALSE-RECEIPT lesson (readers must quote the admission view, not bare PASS, per the sibling deep item) was learned on the chain; the same disease is latent here in the gate ledger and nobody has named it.

**1c. The receipt that measures a mention, not a world.** G6's check is the substring `watch/inbox` in the script text (`workflow_gate.py:71-74`); the dated stamp is a regex over the same text (`:86-88`). A PASS row therefore certifies "the script contains the phrase", and the registry row `G6-receipts: ok=true` reads, to any later consumer, like "a durable receipt landed". It did not land; it was promised in source. The gate ledger is thus a growing population of receipts-about-receipts whose measured observable is textual presence. This is the purest superposed claim in the estate: carried with amplitude 1.0, never observed once.

**1d. The clone that never disturbs its source.** Ladder-02 (git log, run in section 0) is the lived proof: `GENESIS-TESTIMONY adam-picked transcribed in commit a6d71c7f6 message but no watch/inbox receipt`, and the warm-at-boot clause `is fiction tonight - 30 steps.jsonl filename hits all directory listings, 12 transcript mentions all tool-result listings, zero content reads`. A claim was copied from a mouth into a commit message and survived every hop without disturbance, because classical bytes copy for free. Physics calls this the no-cloning problem and charges for it; the estate pays nothing, which is why it took an audit to notice the clone had no original. The no-fabrication law is disciplinary; nothing in the carrier layer makes an unoriginal claim ill-typed.

## 2. The design: a three-state algebra for the claim-carrier layer

The unit of design is not the chain row (sibling's turf) but the CLAIM CARRIER: any artifact that asserts something about the world. The algebra gives every carrier a state vector over two outcomes, {held, hollow}, held = the claim is backed by an observation record, hollow = it is not, plus three named dynamics.

**State 1, SUPERPOSED (carried).** A carrier is born superposed: an intent without an outcome. Concrete diff, smallest possible: `execute()` in `effect_broker.py` appends an INTENT receipt (event_id, effect, params hash, authority fingerprint) to RECEIPTS_DIR before the authority gate, and an IN_FLIGHT marker after the gate passes and before `broker(params, authority)` runs at `:415`. Both are appends of the existing `_receipt` shape with new status strings; the terminal commit stays as is. Cost: two small writes per effect. Payoff: the crash window of section 1a becomes legible. A reader who finds INTENT-with-no-terminal knows the effect was authorized and its outcome is unknown, which is a different fact from "no receipt, never ran". The pre_state/post_state pair the broker already captures (`:101-137`, my sample receipt in section 0: note_count 102 to 103) is exactly a two-measurement interference record; the missing piece is only that the measurements are written down in one atomic final commit instead of being staged. Append-only and cheap beats atomic and silent: this is the same judgment the estate already made when it chose delete-as-append for the wave tape.

The same state needs a reader-side rule: `get_receipt` (`:437-453`) silently returns the newest receipt for an event_id, collapsing a measurement history to its latest projection. The rule should be: return the history, take a basis argument (terminal-only, or all), and never silently drop IN_FLIGHT rows. Silent newest-wins is how a superposition gets collapsed by an accident of implementation rather than by an observer who knows they are measuring.

**State 2, ENTANGLED (correlated).** Three real entanglements already exist in the estate; the design makes them first-class instead of discovered by surprise.

(i) Budget entanglement. `check_budget(authority, effect, decrement=True)` (`effect_broker.py:397`) draws down one shared register per authority, and each receipt snapshots `budget_remaining` at its own moment. Every receipt under one authority is correlated with every other: sibling effects commit and the snapshot in an older receipt goes stale without a byte changing. These are local hidden variables, and the estate treats them as measurements. The design: key budget evidence to the authority register with a register generation number, so a reader can tell "4 calls remained when I measured" from "4 calls remained, full stop". The first is a receipt; the second is a claim pretending to be one.

(ii) Registry-card entanglement. `validate_card` (`workflow_gate.py:187-191`) requires a scenario card's `cited_fail_row` to resolve by (ts, digest) in REGISTRY.jsonl AND to still show the named gate failing. The estate has therefore already built a Bell test on its own receipts: card and row are one joint system, and editing the row collapses every citing card to `SCENARIOS ERROR` on the next run. Nobody wrote this down as a design; it is a emergent constraint waiting to be general: any carrier that cites another carrier by content address inherits its collapse. The rule worth minting: citation must be by (ts, digest) content pair, never by path or line, because paths and lines are the line-anchored defects the wave tape already suffered (rows keyed `line:{i}` per the sibling's census of `_admission`).

(iii) The shared-index collapse. The environment git log carries the receipt: f-24's lanes banked via `d70e5c360 through a shared-index race (my 6 paths staged, that commit swept them; blobs verified byte-identical)`. Two lanes held claims about their staged state; the states were individually undefined until one lane's commit collapsed the shared index for both. Classically each lane's staged set should have been a local fact; materially it was not, because staging is one register. The design is one field: a staging claim (a commit message, a receipt) records the tree or index state it was made against, so a collapse that swept foreign paths is detectable as a measurement against a stale basis instead of being noticed, or not, by a human diffing markdown two days later.

**State 3, COLLAPSED (observed).** Collapse must (a) append, (b) name its instrument, (c) be non-rewordable. The estate has already fought this battle on one front and built four specialized weapons: B2-216 (collected and executed are different denominators from different instruments; never difference two counts taken at different moments), B2-244 (`--collect` deep check), B2-246 (daily schedule), B2-249 (carrier shape law so the gate fail-closes on reworded grammar). That stack is a hand-built decoherence detector for exactly one line of AGENTS.md. The general form: a count carrier is ill-typed unless it names instrument, moment, and tree state; `pytest --collect-only -q` and `pytest -q` are non-commuting observables over `tests/`, and the law forbidding their difference is the estate's uncertainty principle, stated in prose because the carrier layer has no types. Under the algebra, B2-249's exact-grammar requirement is the correct and minimal collapse protocol: fix the record shape, or every reader re-collapses the state by paraphrasing it.

Collapse also needs its negative observable. `read_receipts.py` exists because the operator asked "are they using them?" and the answer was a corpus of write-only artifacts: 40 of 58 surfaces near-zero hits, 209 Unproven write-only research (module docstring, `mag/read_receipts.py:1-8`), and the standing rule the module itself prints: the signal is `CARDS THAT STAY AT ZERO: written, never read, never disproven` (`:114-116`). In this algebra, never-disproven is not true; it is uncollapsed. An observation-count (backrefs, hits) is part of a carrier's state, and a carrier that has stayed at zero for its whole life should be quoted at amplitude proportional to that zero, not read as established. The driving ladder's sensed-not-done law (stealth-lane outputs are findings, never done) is the same principle stated as policy; the algebra states it as a type.

## 3. The problem list, answered directly

Problems the three states solve that the current layer does not:

- P1, silent claim cloning (1d): GENESIS-TESTIMONY in a commit message with no receipt; a warm-at-boot clause with zero content reads. The G6 dated stamp (t69) is the embryo of the fix; under the algebra a quote must carry pointer plus observed_at or be ill-typed, which converts the no-fabrication law from disciplinary to structural.
- P2, unpersisted in-flight effects (1a): a dead child mid-effect changes the world and leaves no record; INTENT/IN_FLIGHT appends make the crash window legible instead of silent.
- P3, basis-dependent verdicts (1b): PASS verdicts over not-ok soft rows are sanctioned; typing the basis (verdict-basis vs row-basis) into the row and its quotation ends the two-readings disease before it produces its first v3-style incident on the gate ledger.
- P4, mention-certified receipts (1c): G6 rows that measure textual presence get downgraded to what they are, promises, distinguishable from landed receipts by state rather than by a soft warn nobody re-reads.
- P5, stale local hidden variables in budget evidence (2-i): budget_remaining snapshots become generation-keyed measurements instead of eternal facts.
- P6, cross-lane collapse surprises (2-ii, 2-iii): citation-by-content and basis-stamped staging claims turn the f-24 race and the card-row coupling from surprises into checked constraints.
- P7, write-only receipts (state 3, negative observable): the zero-backref population gets priced as uncollapsed instead of silently trusted; the 209 Unproven corpus becomes visible in every downstream quote.

## 4. What this deliberately does not solve

No physics is claimed and no speedup is available: the entire content is a type system and two extra appends, classical all the way down. The deepest limit the probes found is that no state algebra fixes evidence CONTENT: `_broker_model_call` returns `ok: True` with `"stub": True` and the string `[MODEL_STUB: not wired to seat_dispatch yet]` as its response (`effect_broker.py:285-292`), and `_postcondition_evidence` dutifully records `{"stub": true}` (`:158-159`). A receipt in any formalism can certify a stub; the algebra prices ignorance, it cannot create knowledge. (Honestly reported: 0 of the 140 persisted receipts carry stub evidence, so that path is live code, unexercised in the current corpus, a landmine rather than a wound.) Second limit: amplitudes here are binary (held/hollow), deliberately coarser than the sibling's derived probability vector, because the carrier layer has no measurement stream to derive amplitudes from; a finer vector would reintroduce the hand-set-number disease the sibling explicitly warns against. Third: not run, no tests written or executed for a diff that does not exist yet (this item is design-only per the ask); the gate scenario suite run in section 0 was a read-only probe of existing behavior, not a check of new code.
