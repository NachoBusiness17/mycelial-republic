## 2. The design: a lattice, not a ladder

**Core theorem, extracted from the code rather than imposed on it: age alone never demotes.** Every mature organ in the estate already agrees on this. The patrol requires growth AND age (census_drift_patrol.py:265). freshness_check requires staleness AND heartbeat (line 292: a dead repo demotes nothing, because with no heartbeat there is no "now" to be stale relative to). grave_classify refuses to treat age as a verdict. freshness_gate's 14-day bar can be beaten by a 20-day-old claim whose source hash still verifies, and a 1-hour-old claim whose source drifted fails (t37 binding cases, self-test lines 270-272). So the temporal type of an artifact is not a function of elapsed time; it is a relation between a claim and a world, with elapsed time only one of the inputs. Formally, type = f(observation_age, drift, declared_freeze, burial_act), where drift is hash-mismatch or the patrol's growth signal, and the demotion fires on whichever input trips first. This is also why the system must measure age against estate metabolism, not UTC alone: the heartbeat clause makes time estate-relative, which is Lamport's 1978 point ("Time, Clocks, and the Ordering of Events") made operational: timestamps order, but only causal contact with the world (a hash, a growth signal) promotes or demotes.

**The five types, each with its owning organ and its operational test:**

- **Fresh**: an observation with a live receipt: age within bar AND source hash verified on demand. Owning forms: freshness_check's fresh verdict; freshness_gate ok. The bar is per-class and carried in the artifact (receipt() stores max_age_seconds, freshness_check.py:131), 900s for tool results, 7d for boot docs, 14d for stamps, 7d for the census carrier.
- **Aging**: inside the window with movement noted: the patrol's ok-with-growth detail line (census_drift_patrol.py:280-287) is this state executed correctly. Consumable with disclosure; the disclosure is mandatory and adjacent (the print names the growth), the B2-338 lesson inverted: red channels that cry wolf train operators to dismiss them, so green-with-notes must stay green-with-notes, never silently downgraded to plain green.
- **Stale**: age beyond bar AND world moved. Unconsumable as a claim, visible as lineage. The patrol's STALE and freshness_check's STALE both land here. Fix is always re-observation, never editing the verdict.
- **Fossil**: beyond every bar, no longer even wrong-able: weight without authority. The tagger's >=64d band (live: 1,736 rows, 0.3 percent; the boundary is sharp because the catalog base rescans, so most bytes ride a 2026-09-26 rebirth). Fossils stay indexed and greppable; they just cannot be cited as current.
- **Dead**: terminal and navigationally unreachable: graveyard-moved (stale_sweep.py:62-69) or labelled SUPERSEDED-BY / ABSORBED-BY / DONE-ELSEWHERE (grave_classify.py:66-75). The estate already tests the consumption side of Dead: `mag/hero_simulation.py:106-121` keeps a GRAVE registry of what a fresh agent must never reach, and the verdict requires graves_reached == 0 (lines 334-343). Dead means the nav graph no longer serves it, not that bytes are destroyed; line 6 of stale_sweep: nothing is deleted, only filed.

**Demotion rules (automatic, monotone except through the re-observation door):** D1 Fresh to Aging fires at the artifact's own carried bar; this one is genuinely automatic and needs no world signal, because the receipt carries the bar and the clock is the only input. D2 Aging to Stale requires age AND drift (patrol law); without drift the artifact ages in place, forever Aging, which is correct: an unchanged world makes old observations true. D3 Stale to Fossil at the hard 64d band; past it the type no longer tracks drift, it only accumulates dust. D4 anything to Dead ONLY by named act: `--execute`, a canonical grave label, or FROZEN_OK deregistration. No silent demotion into Dead, ever; the move must log to the room (stale_sweep already does) because the chain sees it. Today's `tools/demote_candidates.py` is the pattern generalizing correctly: single writer, audit ledger, kill switch.

**Promotion rules (the only ones that exist, and the design ratifies them):** P1 re-observation: promotion is never time passing; it is `stale_claim(rec, source_path=...)` returning fresh because the bytes re-hash equal (freshness_check.py:185-192), or a new stamp binding the same source (freshness_gate t37). P2 refresh-with-attribution: the patrol's fix lines (census_drift_patrol.py:336-337) name the exact ritual: rerun the instrument, refresh the carrier with new counts and today's date. P3 freezing is not promotion: FROZEN_OK is an exempt type outside the lattice, and it costs a self-declaration header (freshness_check.py:12-14); the MICKEY17 V2 receipt (corpus/steal/MASTER_MICKEY17_V2.md:137) records the tier-2 violation when state/HANDOFF.md froze without declaring it. Exemption is granted, audited, and revocable; drift past it is not. P4 mechanical promotion takes the auto_promote shape: deterministic eligibility, a soak window (48h there; the Aging band is the corpus-level soak), fail-closed on any missing input. Note what is absent: no rule promotes Fossil back to Stale-by-decay. Resurrection is a new artifact with a new receipt, which is why grave_classify's ABSORBED-BY versus SUPERSEDED-BY distinction is human: the tool enforces the vocabulary, not the metaphysics.

**Consumption-time checker:** the checker runs where the claim is consumed, not where it is produced, because production-time gating is exactly what let the census carrier ride 12 days stale (B2-215 disease, census_drift_patrol.py:4-7) and DNA.md ride 53. Generalize `stale_claim()` into `class_of(receipt, source_path, now)` returning {fresh, aging, stale, fossil, dead, unverifiable}, and bind it at three consumption surfaces: (1) retrieval: every corpus_search served row carries its type computed at query time plus its bar (the age_class fix: persist the clock reading, never the verdict; mtime and observed_at are data, class is derived, B2-216's census denominator law generalized: a count is a snapshot of one tree at one moment, and so is a type); (2) boot: state/ reads pass through the checker, the pre-push gate is only the write-side shadow; (3) filing: any receipt citing a source carries the stamp grammar, and the gate's fabrication-smell conventions (future-dated beyond 1d skew is unverifiable, freshness_gate.py:151-159) apply unchanged. The exit-class table is inherited whole: unverifiable (missing, unparseable, future-dated) is exit 2 and blocks, because a blind checker is the B2-277 disease; stale is exit 1 and warns with the fix recipe inline; fresh/aging pass, aging printing its note. Channel discipline is part of the spec: first line lowercase-ok on green (B2-338, pre-push:67-75), uppercase tokens on red, or operators learn to dismiss the channel and the checker decays into decoration, the LANE2 F-8 finding.

## 3. Anchors outside the estate

These are connections, not estate claims. Lamport 1978: logical time and the insufficiency of timestamps without causal ordering; the hash binding is a happens-before witness. RFC 1035 DNS TTL (Mockapetris 1987): values carry their own lifetime and refresh by re-resolution, the oldest re-observation-promotion in production. RFC 9111 HTTP caching (2022): freshness_lifetime, stale-while-revalidate as the Aging band, ETag/If-None-Match as the source-hash recheck, must-revalidate as the consumption gate. Generational garbage collection (Jones, Hosking, Moss, 2012): most objects die young, so collection effort concentrates on the young; stale_sweep's 14d eligibility is GC policy, and the graveyard is mark-and-file, never sweep. Mills' NTP work is the standing answer to why CLOCK_SKEW_SECONDS=300 exists (freshness_check.py:86): every distributed freshness judgment needs a stated skew budget or it will fail-closed on nothing.
