## The gate, exactly

A candidate is eligible only when ALL hold (deterministic, fail-closed):

1. `local_feasible` true: ledger stores strings, so `"true"`/`"yes"` count and a
   real bool True counts; `"unknown"`/`"false"`/missing do not. (Ledger census
   run 2026-09-28: 106 "true" / 43 "unknown" / 42 "yes" / 1 "false" across 192 rows.)
2. `kind` in {practice, tesuji}. model/risk/runtime/census kinds keep the human
   gate (`python main.py promote --apply <id>`).
3. age >= 48h measured from `created` (ISO), falling back to the `date` day
   string at midnight UTC (42 of 192 rows carry no `created`). Unparseable or
   missing age = ineligible, never guessed.
4. `status` in {new, hold}: rejected rows are never resurrected, promoted rows
   never re-touched. (Added by design; the three named conditions alone would
   auto-promote rejected rows, which is a bug not a feature.)

Apply reuses `mag.improve.promote_apply`, so the mirror-lens verdict, the
practice playbook append, and the promote training event keep a single writer.
Every applied or mirror-lens-blocked decision appends one audit row to
`memory/improve/auto_promote.jsonl`. The 48h soak is the design: a candidate
gets two days of cooling before any automatic status change.

  MagImproveDaily), not `run_improve_cycle` (the fast queue cycle): 48h-aging
