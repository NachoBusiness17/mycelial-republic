# Q-008 Spider blindspot: detection thresholds vs FKB failure patterns

Item: investigate `mag/spider.py` detection thresholds vs
`memory/failure_kb/signatures.json`; explain why the spider misses failures
the FKB catches; fix the thresholds; prove with real data.
Executor: queue-gopher Q-008, 2026-09-28.

## Origin (real bytes)

`mag/governor_autorun.py:546-547` (PIPE 4) appends the janitor todo
"[janitor] Spider is blind but FKB has clear failure patterns. Investigate
spider detection thresholds." when `ghost.sense()` reports `spider_blind`
and `fkb_signals >= 3`. `mag/ghost.py:570` computes `spider_blind` from the
spider trail: `spider_signals == 0 and len(spider) > 0`, where
`spider_signals` sums `n_signals` over the last 5 trail rows.

## Root cause: two threshold mechanisms in `_check_fkb_repeat`

Old code (`mag/spider.py:111-129` before this fix):

1. **Flat count bar of 3, applied twice.** It called
   `recurring_patterns()` with the default `min_count=3` and then re-checked
   `count >= FKB_REPEAT_THRESHOLD` (3). One policy, stated twice, and both
   statements too coarse.
2. **A `[:5]` rank slice on top.** `recurring_patterns()` sorts by count
   descending; the slice kept only the 5 biggest. Any count>=3 signature
   ranked 6th or lower was silently dropped even though it had already
   passed the count bar.

The severity dimension was ignored entirely: the FKB `kind` taxonomy
(`tool_fail`, `http_tool_fail`, `collapse`, `fake_success`,
`guard_registry`, `amd_window_guard`) was not read by the spider, so the
worst "lying agent" kinds were held to the same recurrence bar as ordinary
tool noise.

## The fix (`mag/spider.py`, this commit)

- `FKB_REPEAT_THRESHOLD = 3 -> 2`: ordinary kinds surface at count>=2, the
  same bar `mag/failure_kb.py` `surface_hits` already uses for agent-facing
  tips (failure_kb.py:511 skips cnt<2), and the same floor the index itself
  keeps (rebuild_index's recurring-class policy, min_count=2).
- New `FKB_SEVERE_KINDS = ("collapse", "fake_success")` with
  `FKB_SEVERE_REPEAT_THRESHOLD = 1`: one occurrence of a lying-agent kind is
  already verdict-grade (claimed edits with nothing on disk), so it
  surfaces immediately with `severity: "error"`.
- Rank slice `[:5]` **removed**: the count floors are the only bar; the
  index is bounded by the FKB's own rebuild policy so signal volume stays
  bounded by design.
- `recurring_patterns(min_count=1)` call: the spider now owns the whole
  threshold policy in one place instead of leaning on the KB default and
  re-checking it.
- New signal field `fkb_kind` carries the FKB kind; severity is `error`
  for severe kinds, `warn` otherwise. No consumer switches on spider
  severity values (checked `mag/ghost.py`, `mag/ops_graph.py`,
  `mag/training_events.py`, `mag/improve_loop.py`, `main.py`; signals flow
  into `training_events` emits and the trail only).

Count-1 ordinary sigs stay hidden on purpose: the spider detects
*recurrence*, and the FKB's own law keeps count-1 sigs log-only
(`mag/failure_kb.py` `rebuild_index` docstring, "Count-1 sigs stay log-only
by design"). This is documented in the new constants comment.
