## What I built (the wire)

`mag/router.py`, one rule applied in every branch that picks a provider:

- `_COMMS_SEAT_LANES` (after `mag/router.py:165`): explicit seat-name-token -> provider-lane map,
  provider-name tokens BEFORE generic family tokens (a seat like "deepseek_swarm" must map to
  deepseek, not the generic swarm->ollama alias; this bug was caught by my own prototype run and
  is regression-tested). Grounded aliases: grok->xai, cheap/swarm/local->ollama, plus
  deepseek/openrouter/groq/nous/z_ai identity tokens.
- `_proven_comms_lanes()` + `_comms_lane_boost(base_prefer, cc)`: promotes lanes matched from
  proven seats within a branch's existing prefer order. Guards: never ADDS a lane the branch did
  not allow; the free local lane (ollama) is NEVER displaced (AGENTS.md tier ladder: local
  janitor first); stable order both groups; identity (no why-noise) when nothing moves.
- Hooks: local-janitor branch (after the existing ctc flip), heavy branch (after the vast
  rental check), remote/default branch (reads the configured routing order, boosts it, passes
  `prefer`; empty config falls back to `prefer=None`, the exact pre-wire path). Movement is
  visible: `why` gains `comms_lane_boost=<lanes>`.

The spec this code implements already existed: `mag/comms_trail.py:191-199` states the router
consumes per-seat proven records to route "with confidence". Spec before behavior holds.
