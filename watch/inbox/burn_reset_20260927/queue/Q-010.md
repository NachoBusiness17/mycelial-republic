## Real-byte finding: the hash families do NOT cross-link by hash today

`dossier_commit` on verkle rows (3,576 distinct values) is content-hash
shaped, not git-shaped: 0 of 3,576 are 40-hex; most are 64-hex sha256-style,
some are short tokens (`t30fbf98`, `t89bd0a0`). Probe run this session:
`git cat-file -t 8ae1eb6b229a5344f3d9ee3331fc168bdc3e8f2b662914970fe925196d831716`
-> `fatal: Not a valid object name`. So no verkle->git hash edges exist in
this estate's bytes, and the tool emits none (no-fabrication law). Cross-
family traversal in the index today rides session groups only. If a future
writer wants verkle->git edges, it must start recording real git SHAs on
chain rows; that is a source-side change, not an index-side guess.
