Spec (written into the module docstring before the behavior change,
mag/catalog_tags.py): rows in catalog/tags.jsonl gain an "owner" field,
the owning top-level surface of the stored path:

- The map walks the projects parent, so repo files carry the
  local_sovereign_agent/ prefix (the same strip classify_kind does).
  owner = the first path segment after that strip (mag, watch, docs, ...).
- Estate files outside the repo: owner = the sibling project name
  (hermes-agent, azerothcore-wow, ...), untruncated. This is the point of
  difference from zone: zone_of (mag/catalog_scan.py:99) buckets
  watch/inbox into "intake" and mag/tests/scripts/configs into "code", and
  masks non-repo tops as "ext:" + top[:16]; owner is the exact join key.
- A file at the top level with no owning directory owns "root"
  (e.g. AGENTS.md).
- Prefix strip is case-insensitive; the owner value keeps stored case.
- Kind rules (salon Appendix B) untouched; owner is purely additive.

## 2. Held-out 50-question retrieval eval

Script: watch/inbox/burn_reset_20260927/queue/Q_031_retrieval_eval.py
(results: Q_031_retrieval_eval_results.json next to it; auto-sealed into
index_events.jsonl by the md-record-seal hook).

Protocol (held-out, published so it can be attacked):

- Surface under test: tools/corpus.py corpus_search, the sanctioned
  read-only catalog retrieval surface, unchanged since its 2026-09-26
  landing; the owner column is outside the query path (corpus_search reads
  tags.jsonl only when a kind filter is passed; none was).
- Gold set: random.Random(20260928).sample over the 581,477 catalog rows
  carrying a path; draw made after both surfaces were frozen; zero
  per-question tuning; all 50 gold ids published in the results JSON.
- Questions: built only from the gold row's own stored fields (title if it
  differs from the basename, else the basename stem), tokenized to
  [a-z0-9]{3,}, deduped. This scores lexical name/title lookup, what a
  catalog map actually promises; not semantic retrieval.
- Engine semantics scored: AND of quoted prefix terms over path+title,
  hits in catalog line order. accuracy@1 = first hit is the gold id;
  accuracy@10 = gold id within the first 10 hits.
- "Held out" means seeded draw after code freeze + no tuning + full gold
  publication. It is not a human-written query set; relevance is id
  equality only.

Command:

    .venv/Scripts/python.exe watch/inbox/burn_reset_20260927/queue/Q_031_retrieval_eval.py

Result (ran 2026-09-28T16:49:16Z):

- 50/50 answerable; every query rode engine=fts5, index_state=fresh
  (the B2-102 freshness gate passed on all 50).
- accuracy@1 = 0.48 (24/50)
- accuracy@10 = 0.76 (38/50)  <-- headline accuracy
- Of the 38 top-10 hits, 23 had a catalog-unique basename, 15 shared.

Failure modes (all 12 misses inspected in the results JSON): every miss is
a question whose terms are non-distinctive, so earlier catalog lines
matching the same AND-prefix terms outrank the gold in the engine's
catalog-order return. Examples: terms "agent" (mine/raw tree),
"auth" (zep legacy api), "2024" / "2023" (azerothcore archived SQL dumps),
"templates", "sealb", "extension webpack config". The catalog surface is
an exact-ish lexical map: distinctive names retrieve, generic tokens do
not. No query erroring, no scan fallback, no index staleness.
