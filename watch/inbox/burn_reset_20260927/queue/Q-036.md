Date: 2026-09-28. Lane: queue-gopher-Q-036 (Mickey17 gopher fan-out).

## Ask

Implement a per-lane reasoning-effort policy in the stealth driver. Free lanes
get effort=low, judgment lanes get effort=max. Wire it into the dispatch
config. One test.

## Wire-shape grounding (why per-family)

- OpenRouter chat completions: reasoning is controlled via the `reasoning`
  object with `effort` allowed values "max", "xhigh", "high", "medium", "low",
  "minimal", "none" ("low" and "max" both documented). Fetched this session
  from https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
  (the page states there is no top-level Chat Completions `reasoning_effort`
  param; provider translation is OpenRouter's job).
- z.ai/Nous 5.3 lane (`z-ai/glm-5.3-prime` on the SDD lane): top-level
  `reasoning_effort`, 5.3 accepts max/high/low ONLY (other values 1210),
  default max. Grounded in the repo's own reference,
  `docs/ref/ZAI_API_EXPERT_REFERENCE.md:66` and the 10.2 table at
  `docs/ref/ZAI_API_EXPERT_REFERENCE.md:262-267`. scarce5 = max is also the
  5.3 documented default, so if the Nous pass-through drops the param the
  effective behavior is unchanged.
- llm7 (`gpt-4o-mini`): not a reasoning model; knob withheld on the wire,
  policy value still stamped at config level. NOT live-verified against llm7
  (we never send the knob there; nothing to verify).
- hermes: headless CLI transport (`hermes.cmd -z`), no request body, so the
  dial is config-only on that lane.
- OWED (not verified live): whether inference-api.nousresearch.com passes
  `reasoning_effort` through to the z.ai backend. No live dispatch was run
  against any lane this ask (the work queue was not consumed).
