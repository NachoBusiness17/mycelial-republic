## 1. GnomeCode streamed sections for maze zones (ARCHITECTURE_NEXT move 1)

New `roblox/src/shared/SectionStream.luau`: the Doors ep.1 pattern (the world
materializes ahead of the walker instead of all at boot). A stream holds
one-shot build closures with a center; `poll(positions)` builds unbuilt
sections within `radius` of any position, at most `budget` per poll.
`ordered = true` builds strictly in insertion order, which is the property
seeded builds need: insertion order equals rng draw order, so a streamed
world is byte-identical to the eager one, only later in time.

- **OssuaryZone** (`roblox/src/server/OssuaryZone.luau`): the per-floor body
  of the old eager loop moved verbatim into `buildFloorSection` (same
  buildFloor + sentinels + braziers + lever + Vogel candy + court order, same
  shared `SeedRng(20261031)`). Floor 1 (the arrival floor) still builds
  eagerly at boot; floors 2-3 ride an ordered stream, radius 55 vs the
  46-stud floor drop = one floor of lookahead (standing on floor N
  materializes N+1; N+2 stays dark). `tick` polls with player root
  positions. The floor-2 boulder clock is now gated on `floorsBuilt >= 2`:
  a boulder rolled into a not-yet-built floor would drop into the dark every
  20s. Boot cost drops from 3 full grids to 1.
- **RiddleMazeZone** (`roblox/src/server/zones_extra/RiddleMazeZone.luau`):
  the ~1,400-part wall grid now streams in 8x8-cell chunks (radius 120,
  budget 4 per poll, unordered). genMaze runs eagerly at boot and wall parts
  are anonymous geometry no other system looks up, so deferral changes
  nothing observable except when the rock appears; floor, chamber tiles,
  prism, pads and the whole field remain eager. The RIDDLE MAZE portal lands
  about 100 studs south of the maze, so the grid manifests on approach and
  boot builds nothing of it.
- Judged too small to stream (stated in the spec doc): SpectralMazeZone
  (7 doors, 1 hall part), MazeArenaZone (10 fixed walls).

## 2. Trove cleanup on wave tick loops (ARCHITECTURE_NEXT move 3)

New `roblox/src/shared/Trove.luau`: the Sleitnick/RbxUtil Trove shape
(Add / Connect / AttachToInstance / Clean / Destroy, same cleanup dispatch:
Instance Destroy, connection Disconnect, thread cancel, function call, table
method) plus one local extension `Loop(interval, fn)`: a repeating thread the
trove owns, body runs immediately then every interval, and returning exactly
`false` ends the thread. Clean's thread cancel is pcall'd, so a Clean
triggered synchronously from Destroy inside a running body is a no-op and the
body's false return is the real exit: both paths terminate, nothing spins.
The full RbxUtil package is not vendored (no Packages tree in this repo);
this is the minimal in-repo implementation, documented as such in the header.

All six hand-rolled `task.spawn` loops converted (the six the doc named):

| loop | file | ownership now |
|---|---|---|
| soul flush | `src/server/HeadMuseum.luau` (was :198) | `AttachToInstance(museum)`; cadence identical (dirty starts empty, so the Loop body's immediate first run is a no-op like the old wait-first cycle) |
| artifact conveyor | `src/server/LedgerExchange.luau` (was :119) | `AttachToInstance(a)`; body ends itself past the rail or when bought (destroy fires Destroying, Clean cancels) |
| flicker-tower wisp | `src/server/LightMazeZone.luau` (was :116) | `AttachToInstance(w)`; 60s cap stays as game behavior but enforces itself by destroying the wisp; early destroy cancels immediately instead of polling parent up to a minute |
| night-terror hunt | `src/server/MudBasecamp.luau` (was :227) | `AttachToInstance(body)`; same shape, 30s cap |
| swarm enemy chase | `src/server/SwarmZone.luau` (was :148) | `AttachToInstance(enemy)`; same shape, 25s cap; the Touched kill cancels the chase now |
| THE ANSWER fight | `src/server/TheAnswerBoss.luau` (was :80) | raw thread tracked by a trove attached to `boss` (NOT Loop: a phase paces with two different waits, 3s telegraph then 2s strike, which a fixed-interval Loop cannot express); a boss destroyed mid-fight ends the encounter instead of a loop dying by error at a corpse |

Age caps remain as game behavior everywhere; what changed is that destruction
of the subject now terminates the loop by ownership instead of the loop
polling `.Parent` or waiting out its age. When nothing is destroyed early the
behavior is identical (same intervals, same caps, same chase math).

## 3. Cooldown chips UI (ADOPT table UI row)

`roblox/src/client/init.client.luau`, the existing bottom-right cluster
upgraded from plain text labels to skill-slot panels: key/name label, a
cooldown fill bar draining across the mirrored cd (amber on the panel's
bottom edge), an active-window UIStroke glow plus gold text while the
ability attribute is still true, ready state tinted green, and a
cluster-wide dim (text + fill faded, stroke hidden) while the server has
abilities disabled (`Carrying`, the Steal-a penalty: the server reads the
same attribute to refuse every fire, the chips only paint it). Courier law
unchanged: clock start is the replicated attribute flip, the drain is local
math, no new remotes, no client-side authority. The text countdown is kept.
Fusion was NOT adopted (no vendor step in this repo yet); that stays an open
move in the spec doc, and the landed chips are plain Instances.
