## Work done

1. Recounted raw.jsonl from bytes (numbers in Evidence), cross-checked the
   ALERT row, the queue id set, and the driver source; attributed the duplicate
   completions to the recorded mid-batch crash window.
2. Filed the DRIVER V2 RESILIENCE SPEC (the deliverable; maps the five SWARM
   rows onto the union driver):

   S1 FULL JITTER BACKOFF (XIDIG-SWARM-AWS-JITTER). Before every retry, sleep
   uniform(0, min(cap, base * 2**attempt)) with base 2 s, cap 60 s, per AWS
   "The solution isn't to remove backoff. It's to add jitter." v1 has no sleep
   at all between a failure and the next attempt, the exact no-jitter loser
   shape AWS measures (call count more than halved with 100 contending clients
   under full jitter; contention work grows with N^2 without it).

   S2 PROCESS RETRY BUDGET (XIDIG-SWARM-SRE-RETRY-BUDGET). Token bucket of 60
   retries per minute per driver process (SRE: "only allow 60 retries per
   minute in a process"); successes deposit, retries withdraw, empty bucket
   fails fast and leaves the item for the next run (the queue is durable, so a
   dropped retry is a deferred dig, not a lost one). Plus SRE
   retryable-classification: retry only 429/5xx/timeouts/empty_content; never
   400/404 ("Don't retry permanent errors or malformed requests in a client,
   because neither will ever succeed") and never stack per-layer retries beyond
   the 2-attempt cap (SRE layered-retry product law). Bytes: 6 HTTP 400 rows on
   together-llama and 11 HTTP 404 rows are the permanent class; 7 HTTP 429 the
   budgeted class.

   S3 PER-LANE HALF-OPEN BREAKER (XIDIG-SWARM-CIRCUIT-BREAKER). State machine
   per lane id: closed (normal), open (3 consecutive retryable failures or any
   404 window-death body: no network call for a 10 min cooldown), half-open
   (cooldown elapsed: admit at most 2 probes; any success closes, any retryable
   failure reopens). Retry patience and provider protection stay distinct
   mechanisms per Azure ("The Circuit Breaker pattern prevents an application
   from performing an operation that's likely to fail"); half-open exists so a
   recovering lane is not reflooded ("The Half-Open state helps prevent a
   recovering service from suddenly being flooded with requests"). Honor
   Retry-After on 429/503 when present (accelerated opening). Bytes: the four
   dead lanes spent 14 attempts for zero answers; a breaker redirects that
   traffic after 3 failures each.

   S4 RUN-LEVEL 15x TOKEN ENVELOPE (XIDIG-SWARM-TOKEN-COST +
   XIDIG-SWARM-ANTHROPIC-15X). Each run carries a spend envelope of 15x the
   single-chat baseline for its class mix, accumulated from usage.total_tokens
   as rows land; a batch item that would cross the envelope defers to the next
   run. This is an envelope over completed calls, NEVER a per-call max_tokens:
   the operator correction of 2026-09-17 x2 (driver docstring) proved per-call
   caps starve reasoning models into empty_content, and that correction stands.
   Byte check: observed worst dig 7,950 tokens vs 1,355.7 mean = 5.9x, so the
   live fleet sits under the 15x Vercel/Anthropic figure; the ceiling is
   headroom law ("task value has to justify the added complexity"), not a
   straitjacket.

   S5 COST-PER-COMPLETED-DIG DENOMINATOR LAW (XIDIG-SWARM-DENOMINATOR-DRIFT).
   A dig is a queue id, not a raw row. Pins for this drive, from bytes:
   attempts 184, ok rows 156 (row ratio 0.8478), unique completed ids 128 of
   131 touched (completion ratio 0.9771), attempts per completed dig 1.438.
   All-in recorded spend 211,484 tokens over 128 completed digs = 1,652.2
   tokens per completed dig (all-in keeps the 34,050 refire tokens in the
   numerator because the spend was real); first-completion-only floor is
   177,434 tokens = 1,386.2 per dig. Reported ratio must always name which
   numerator and denominator it uses, and any prose citing the drive
   (143/88.8 percent is the current offender) is superseded by a byte recount
   at citation time, trust bytes not reports.

   S6 DENOMINATOR INTEGRITY (drive scar, required by S5). The crash window
   that minted 28 duplicate completions is a denominator attack: ok row
   appended, state save skipped. v2 order: state.done advance and raw append
   commit under one lock step per item (write state before unlock, or derive
   done from raw by id at boot so a crash replays idempotently), so a completed
   id can never refire. Boot-time id dedupe against raw.jsonl is the cheap
   invariant; the 34,050 wasted tokens are the cost of not having it.

## Falsifier

This spec dies if: (a) any recount of raw.jsonl by id yields a completed-dig
count other than 128, or an attempt count other than 184; (b) an implementation
lands the 15x ceiling as a per-call max_tokens (the 2026-09-17 empty_content
scar reopens; the envelope must be run-level over completed calls); (c) the
breaker opens but never half-opens, or half-open admits unbounded probes (a
permanently open lane is v1's dead-lane routing under another name); (d) the
"jitter" is a fixed sleep (AWS names that the loser under contention); (e) the
retry budget exceeds 60 retries per minute per process or budgets per item
instead of per process; (f) any future prose cites the drive with 143 or 88.8
percent without a fresh byte recount; (g) an implementation records usage on
ok rows only and still claims a true cost-per-completed-dig (28 of 28 failure
rows carry usage None today).
