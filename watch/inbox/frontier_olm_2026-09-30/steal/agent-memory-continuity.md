## S1. Curate Before You Connect (2608.10644) -> knowledge-graph organ

**Mechanism.** Write-time identity discipline for any store that links records: decide sameness from identifier columns, name columns, display names and type-scoped position, never from name similarity; merges are destructive ("two records merged under one identity cannot be separated once their properties have been combined, and the merge leaves no error behind"); after a real over-merge deleted 8 entities, entity resolution only ever FLAGS candidates into a curation queue (48,403 pending vs 775 human decisions). Source: https://arxiv.org/abs/2608.10644 (2026-08-11, 20 days outside window, marked).

**Estate map.** The knowledge-graph organ is the exact patient: 823 of 825 edges dangle on id-format mismatches between writer and reader (`lens/graph.md:13`), with three writer defects: 300 case_law nodes collapse to one literal `law:` id because ledger rows carry empty ids sliced `[:12]` (`mag/knowledge_graph.py:123`), invariant edges target 40-char truncated virtual ids (`mag/knowledge_graph.py:165`), and maps_to free text is embedded into ids that never resolve against the `module:{p.name}` convention (`mag/knowledge_graph.py:172` vs `:85`). Port move: adopt the ladder BEFORE the three-fix list (`lens/graph.md:37`) so the fixes write identities, not new collisions: fix (1) is the identifier-column rung (real ledger ids so the 300 stop collapsing); fix (2) writes invariant nodes under their FULL canonical text id; fix (3) normalizes maps_to to the exact node-id convention and only auto-merges on exact canonical-key equality, flagging the rest to the curation queue the estate already runs as `promote --apply`. The ladder's destructive-merge law is also the discipline the 9 modules citing an empty `invariant:law ` need (`lens/graph.md:25`).

**Probe P1 (falsifiable, half a session).** Port fix (2) alone: emit invariant nodes whose ids are the full normalized law text instead of the `[:40]` truncation at `mag/knowledge_graph.py:165`, run the builder's `build()` (`mag/knowledge_graph.py:435`), and recount id-resolvable edges with the lens method. Status: OWED, not run.

## S2. EngramRAG (2609.32049) -> percolator organ + the B2-465 FTS heal loop

**Mechanism.** Id integrity enforced at write plus consolidation off the read path: on ingest, a nearest-vector cosine above 0.95 increments the existing node's access count instead of duplicating it; database uniqueness constraints enforce "uniqueness across entity identifiers and fact hashes"; contradictions are never merged, they get a directed SUPERSEDES edge that traversal filters (split-brain 70.0% to 0.0% over 50 mutation episodes); consolidation runs OFF the read path on a ~6h cycle, and eviction is conjunctive: ALL of confidence <= 0.10, dormancy > 4 cycles, degree <= 1, type not identity/preference, plus a cold-start grace period (grace 1: 42.0% survival; grace 4: 96.0%; "CATD achieves 100.0% scaffolding retention where baseline temporal decay degrades to 60.0%"). Source: https://arxiv.org/abs/2609.32049 (2026-09-25, in window; registered feed-level 09-28, first full read 09-30).

**Estate map.** Two organs. (a) The B2-465 FTS heal loop is already the off-read-path consolidation shape: `tools/corpus_fts_rebuild.py --check --deep` (gate state at `tools/corpus_fts_rebuild.py:126`, exit-code house pattern at `:23`) driven by the MagFtsIndexDaily cron. What EngramRAG adds is usage-weighted retention instead of pure recency, and the conjunctive eviction rule so a decay decision can never fire on one weak signal. (b) The percolator currently decays on time alone (half-life `_decay_count`, `mag/percolator.py:140`); the port move is to widen `maintenance(dry=True)` (`mag/percolator.py:477`) with the conjunctive rule so prunes require multiple weak signals. The SUPERSEDES-not-overwrite law also lands on the fold path (`mag/knowledge_graph.py:498`): a superseded invariant appends a directed edge rather than silently overwriting, keeping amend-never-erase true in the graph layer.

**Probe P2 (falsifiable, one dry run).** Implement the conjunctive eviction rule beside the current single-signal decay inside `maintenance(dry=True)` (`mag/percolator.py:477`) and run both variants dry over the live percolator registry. Falsifier: if the two orderings prune identical sets, the conjunctive rule adds nothing to this organ and the steal is rejected for the percolator (it may still hold for the FTS cron). Status: OWED, not run.

## S3. RoutePrism (2609.34160) -> water-graph / cathedral-world organ

**Mechanism.** Construction order is a measured property of memory, not a doctrine: rebuilding from the same record pool forward vs reversed changes what survives ("Processing the same records in a different order can discard different evidence"); source overlap falls to Jaccard 0.057 for one compactor, LongMemEval-S accuracy moves 0.206 vs 0.081, and the direction of the advantage is policy-dependent. Its discipline is not a canonical order but paired forward/reverse construction as "a regression test for new order sensitivity", with record-level provenance retained through merging. Source: https://arxiv.org/abs/2609.34160 (2026-09-28, in window; genuinely new).

**Estate map.** The cathedral-world contested tie is pending a third-model tiebreak: "descent order (Grok hub-first vs DeepSeek water-first-descent)" at `memory/rib/RIB_CATHEDRAL_WORLD_V1_20260921.md:14-17`, surfaced as open item 13 at `lens/laws.md:70`. Port move: replace the tiebreak with the RoutePrism discipline. The rib's own filing line already allows "third-model tiebreak ... if the operator orders it"; the steal says the cheaper settlement is measurement, because even frontier-grade pipelines silently flip outcomes on order, so a third model's preference is the wrong instrument.

**Probe P3 (falsifiable, one build pair).** Build the cathedral descent twice from the same frozen scene pool, hub-first and water-first, holding content fixed, and diff the two final world states on a fixed oracle. If bit-identical, the tie is moot locally and either order ships (RoutePrism's flip does not transfer at this scale, a real result). If divergent, order is a load-bearing property: pin it in the rib as a measured fact instead of a doctrine, and add the paired build as a regression test. Status: OWED, not run.

## S4. UpliftMem (2609.36805) -> corpus_search surface + FTS freshness gate

**Mechanism.** Score a retrieved memory SET by set-level uplift, "the expected utility difference between execution with complete memory and execution without memory under the same executor", trained on paired executions with EVSI-targeted probing of under-tested sets (decision accuracy 41.7% to 66.5% on a fixed store, 4B model). Source: https://arxiv.org/abs/2609.36805 (2026-09-29, in window; genuinely new).

**Estate map.** The estate's retrieval quality on its own catalog is unmeasured in utility terms; the FTS5 layer already degrades honestly but silently in effect: `corpus_search` prefers the index and falls back to scan with a different engine label (`tools/corpus.py:14-15`, scan return at `:295`), and freshness is watched only by mtime/sha (`_fts_state`, `tools/corpus.py:140`; deep check `tools/corpus_fts_rebuild.py:126`; the B2-465 cron heals but nothing behavioral verifies the answers got better). Port move: a frozen 20-query battery over `corpus_search` (`tools/corpus.py:226`) becomes the paired-execution harness; the fresh-FTS vs degraded-store delta is the behavioral quality number a later uplift scorer hangs on, a second tripwire beside the mtime/deep-sha gate.

## S5. Scope Before You Persist (2609.29144) -> percolator persistence + context-pack doctrine surfaces

**Mechanism.** Certification and scope are different axes: "certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use." Source: https://arxiv.org/abs/2609.29144 (2026-09-24, in window; registered feed-level 09-28, first full read 09-30).

**Estate map.** The estate's ribs are family-scoped files by construction, so the danger is not today's gates but any future cross-lane doctrine sharing over the rib bus (`lens/laws.md:37` holds "one bus"; sharing is the temptation). The compile path already carries a domain tag (`_compile_invariant(..., domain=...)`, `mag/percolator.py:353`); the audit targets are the surfaces that aggregate across families: the context pack's rib-doctrine and quantized-laws loaders (`mag/context_pack.py:339` `_rib_doctrine`, `:377` `_quantized_laws`) and hand-folded doctrine nodes in the graph (`mag/knowledge_graph.py:498`). Port move: every persisted doctrine/skill edit keeps its family scope as data, and every cross-family retrieval surface filters by it; a certified-but-global application is prohibited the way the paper measured it.

**Probe P5 (falsifiable, read-only, half a session).** Walk every compiled invariant and doctrine node to its consumption surfaces and check whether any crosses families without its domain scope attached (compile-time domain at `mag/percolator.py:353` vs the aggregating loaders at `mag/context_pack.py:339,377`).
