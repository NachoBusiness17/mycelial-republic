## Answers to the five research questions

### Q1. Id-resolution and edge-integrity discipline for the 823/825 dangling-edge defect (graph.md:13-19) before the three-fix list (graph.md:37)

Yes: two published disciplines, and both say the SAME thing the three-fix list implies. Identity is decided at WRITE time, and merge is destructive.

- **2608.10644, Curate Before You Connect (2026-08-11, 20 days outside window, marked; abs-level verbatim read):** a production KG of 537,157 entities / 2,198,567 relationships from 98,795 documents whose ingestion layer carries a **record-identity ladder** that "decides sameness from identifier columns, name columns, display names and type-scoped position rather than from name similarity". The paper's governing incident is our defect in miniature: two surface forms of one name were merged, "corrupting a correct record and deleting eight entities from an unrelated document", after which the policy became **entity resolution only ever flags candidates** (a curation queue of 48,403 pending proposals against 775 human decisions). Estate mapping: apply the ladder BEFORE the three fixes. Fix (1), real ledger ids (graph.md:37 / mag/knowledge_graph.py:123), is the identifier-column rung. Fix (2), emitting invariant nodes (mag/knowledge_graph.py:165), should write the invariant node with its FULL text id, never a 40-char truncated virtual id. Fix (3), maps_to normalization (mag/knowledge_graph.py:172 vs :85), should normalize to the exact node-id convention and only auto-merge on exact canonical-key equality, flagging everything else for the curation-style queue the estate already runs as promote --apply. The ladder's destructive-merge law is the discipline the 9 modules citing an empty `invariant:law ` (graph.md:25) need.
- **2609.32049, EngramRAG (2026-09-25, in window, full text read; registered feed-level by the 09-28 sweep, first read now):** the write-path id discipline in operation: at ingestion, if the nearest existing vector's "cosine similarity exceeds 0.95, the system increments the existing node's access count rather than creating duplicate nodes"; offline consolidation merges clusters into a winner node by access count + PageRank, with database uniqueness constraints enforcing "uniqueness across entity identifiers and fact hashes"; contradictions are never merged, they get a directed SUPERSEDES edge that traversal filters out. Measured payoff for our dangling-edge disease: the SUPERSEDES DAG cut split-brain hallucinations from 70.0% to 0.0% over 50 mutation episodes. This is exactly the invariant-node emission pattern fix (2) wants: real nodes under a uniqueness constraint, supersession instead of silent overwrite.
- **2609.29695, EvLink (2026-08-31, in window, abs-level read; EMNLP 2026 main):** edge-integrity as a first-class property: "graph reachability often captures semantic association rather than evidence support, so a reachable passage may still fail to justify a required cross-passage transition". Its links exist only when justified by explicit source relations, with source-bounded fallback links. Estate mapping: an edge should be WRITTEN only when its target id resolves at write time (which would have prevented all 823 dangling edges), and relation-specific edges need their endpoint kind to exist first.

### Q2. The world-rib contract (laws.md:61): published lowering contracts, and the contested cathedral ties (laws.md:70)

- **Descent order (Grok hub-first vs DeepSeek water-first-descent):** the literature's answer is that there IS no canonical order to steal; order is a measured property, not a doctrine. **2609.34160, RoutePrism (2026-09-28, in window, full text read):** builds memory twice from the same pool, forward and reversed, holding everything else fixed, and finds "Processing the same records in a different order can discard different evidence". Source overlap collapses to Jaccard 0.057 for one compactor, and on LongMemEval-S forward vs reverse moved accuracy 0.206 vs 0.081, with the direction of advantage policy-dependent (last-arrival retention punishes forward processing, first-arrival reverses the asymmetry). Its recommendation is NOT a canonical descent but a discipline: retain record-level provenance through merging, log which fields retrieval consumes, and run paired forward/reverse construction as "a regression test for new order sensitivity". Estate translation for laws.md:70: settle the descent-order tie by MEASUREMENT (build the cathedral world both ways, compare on a fixed oracle), not by a third-model tiebreak, because the paper shows even frontier-quality pipelines silently flip outcomes on order.
- **Gate style (valve heights vs computed-water flag):** **2609.31874, COUNTERMEM (2026-09-25, in window, abs-level read; registered feed-level 09-28, first read now)** is the closest published world-model contract: memory is written only after an executable world model ("tests, proof checkers, and solvers") verifies the counterfactual outcome, and the stored item carries the checked outcome plus reuse conditions; +12.6 points averaged over 12 settings. That is evidence for the computed-flag side of the tie: gates that COMPUTE their state from an executable check beat gates whose heights are set narratively. No paper found defines a full memory-to-world lowering contract (schema-first RIB-to-field-to-world compilation); the nearest shapes are COUNTERMEM's verify-before-store contract and post-graph-rag 2608.24921 (2026-08-14, outside window, feed-level only, unbanked) which lowers memory to typed bi-temporal PostgreSQL rows with temporal grounding at synthesis. That bi-temporal typed-row shape is the lowering-target pattern the dead-drop rib asks for, worth a deep read before any renderer is built.

### Q3. Does SubtleMemory exist beyond the cold claim edge (laws.md:71)?

**Yes: verified REAL, and stronger than the cold edge claimed.** 2606.05761, "SubtleMemory: A Benchmark for Fine-Grained Relational Memory Discrimination in Long-Horizon AI Agents" (v1 2026-06-04, v2 2026-06-05, 48 pages; outside the 30-day window, marked). It is exactly the instrument laws.md:71 describes, and more: 1,522 evaluation instances over 10 long histories from 1,090 relation-controlled memory-variant sets, three relation types (complementary / nuanced-temporal-contextual / contradictory), and a waterfall diagnostic that decomposes failure into preservation (P_reserve), retrieval (P_retrieve), and answer generation: the preservation-vs-retrieval-vs-reasoning discrimination the cold edge asked for, per stage, per system. Headline: best system (A-Mem) 70.0% vs oracle 85.4%; contradictory relations hardest (best 50.4% vs oracle 68.7%; MIRIX 14.6%). Findings the estate's own harness already predicted: systems that preserve raw sessions discriminate best; compression loses the fine cues; and frontier models "struggle to appropriately recognize unresolved conflict and abstain from unsupported resolution when memory evidence remains inconsistent". Estate status: the estate independently folded REL-MEM-1 and built mag/rel_mem_eval.py (memory/design/rel-mem-discrimination-foundation.md:61-81; lexical scorer 33%) BEFORE knowing the paper's numbers. SubtleMemory now (a) upgrades the cold claim edge to REAL, (b) offers its waterfall as the extension path for rel_mem_eval (per-stage P_reserve/P_retrieve diagnosis), and (c) supplies published failure baselines to calibrate against. It was already catalog'd (2 rows) and verified REAL 2026-07-31 in ARXIV_REGISTER; what is new this session is the full-text read with the stage decomposition and numbers.

### Q4. Keeping 350k+ row own-memory corpora queryable without index decay (the B2-465 disease)

The strongest in-window pattern is EngramRAG's two-state split, which is the delta-only hot path in biological clothing: a low-latency Waking State serves reads off the current index while a Dreaming State runs consolidation OFF the read path roughly every 6 hours (HNSW-accelerated DBSCAN dedup, community detection, PageRank recompute, topology-aware decay). Its decay discipline is directly anti-B2-465: retention follows "retention half-life by topological load-bearing weight"; eviction requires ALL of (confidence <= 0.10, dormancy > 4 cycles, degree <= 1, type not identity/preference) plus a cold-start grace period. Ablation: grace 1 gives 42.0% survival, grace 4 gives 96.0%, and "CATD achieves 100.0% scaffolding retention where baseline temporal decay degrades to 60.0%". Estate mapping: the FTS heal loop (tools/corpus_fts_rebuild.py) already detects-and-rebuilds; what EngramRAG adds is (a) consolidation as a scheduled OFF-path job (the MagFtsIndexDaily cron is already that shape), (b) usage-weighted hot sets rather than pure recency, and (c) the multi-condition eviction rule so a decay decision can never fire on one weak signal. Second find: **2609.36805, UpliftMem (2026-09-29, in window, full text read)** attacks the retrieval side: it learns a set-level scorer for "the expected utility difference between execution with complete memory and execution without memory under the same executor", trained on paired executions plus EVSI-targeted probes for under-tested memory sets (decision accuracy 41.7% to 66.5% on a fixed-store benchmark with a 4B model). Estate mapping: the estate's retrieval quality on its own 581k-row catalog is currently unmeasured in utility terms; an uplift-style paired-run scorer over the FTS index would give corpus_search a quality number that moves when the index decays, a second behavioral tripwire alongside the mtime/deep-sha gate. Also relevant, registered-only from 09-28 and still unbanked there: 2609.32256 LAM (lossy compaction with a retrieval-score error bound) and 2609.32521 MemAgent (routing across heterogeneous memory providers).

### Q5. Cross-session continuity with measured benchmarks (warm boot evaluation)

No paper found that benchmarks "warm boot" (chain-tip load at session start) as such; the estate's warm boot remains assertable-only from the literature's standpoint. The three closest measured instruments:

- **2609.34422, CAMG / Coding Agent Memory Post-training (2026-09-28, in window, abs-level read):** a gym of long-horizon agentic-RL environments "spanning Shop, Coding, DeepResearch, and AutoResearch", each with "executable shell access and an episode-persistent workspace" so agents can "create, revise, search, and reuse files as memory throughout an episode"; RL-trained 4B/9B policies become competitive with 35B/122B general models on SWE-bench Verified and MLE-bench Lite. This is the published instrument closest to the estate's file-based memory organs (warm_state.json, session freeze files): a harness where memory BEHAVIOR is scored by downstream task reward across a persistent workspace.
- **2609.29144, Scope Before You Persist (2026-09-24, in window, full text read; registered feed-level 09-28, first read now):** the measured case for scoping persistent memory by task family: "certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use". Per-family skill slots raised mean trajectory utility 0.713 to 0.816 and cut harmful deployments 6/8 to 0, while one global skill made the updating agent WORSE than no updating at all (0.713 vs 0.775 static). Estate mapping: the estate's ribs and lane surfaces are already family-scoped by construction; the steal is the finding that the danger is not bad gates but GLOBAL application of locally certified edits, which lands on any future cross-lane doctrine sharing over the rib bus.
- **Audience-Bound Persistent Memory (2609.36373, 2026-09-28, in window, abs-level read):** authorization enforced across the whole memory lifecycle, admission failing closed, validated on 10,000 frozen multi-party histories: 0 forbidden items entered context vs 82% exposure under unscoped retrieval, at EQUAL entitled recall (+0.30 Recall@5 over unscoped). Estate mapping: supports extending the shared-surface contract's classification-before-reuse rule from files to assembled context.

Also noted, prior-sweep overlap: DreamBench-SWE (2608.20664) already banked 09-28 covers the multi-session carry-forward benchmark half of this question; do not re-derive it.
