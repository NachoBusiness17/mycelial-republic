## Answers to the five research questions

**Q1 (id-resolution / edge-integrity discipline before applying graph.md:37):** Found, and it is the strongest steal of the sweep: post-graph-rag (Postgres + pgvector GraphRAG, Apache-2.0) publishes the exact discipline class. Canonical entity keys are `unique per (realm, space, lower(name))`; alias surface forms converge on one vertex with the fuller name canonical; pronouns and relative references are rejected outright at extraction; repeated triples from multiple chunks MERGE into one edge with an incrementing weight instead of duplicating; edges carry `valid_from/to` + `t_created/expired` and a later document CLOSES an earlier edge (supersession at write time, append-only `{table}_data` history, `as_of` query filters); deletion makes entities/relations dormant (excluded from retrieval, auto-revive on re-mention) instead of dangling; `sweep_orphaned_relations` repairs pre-provenance graphs idempotently ("Nothing is deleted, and it is safe to re-run"); extraction failures raise `ExtractionError` because "placeholders would be indistinguishable from real graph data" - which is precisely the failure mode of the estate's 300 case_law nodes sharing the literal id `law:` (graph.md:19) and the 40-char truncated virtual invariant ids (graph.md:17). Mapping to the three-fix list at graph.md:37: fix (1) ledger ids = post-graph-rag's canonical-key uniqueness; fix (2) emit invariant nodes = its no-placeholder rule (never emit a target id that was not created as a node); fix (3) maps_to normalization = its lower(name) canonicalization + free-text rejection. Add what the fix list lacks: supersession columns, dormant-not-deleted, and an idempotent orphan sweep tool. Counter-canon read from the memoryfields thread: flat files + semantic search beats graphs because graphs raise "the chance of the agent simply not being able to find a memory (or inserting duplicate memories)" - and gimalay's rule: "link traversal is an N+1 problem a tool should resolve deterministically rather than the agent". Steal both: fix the ids AND keep BM25/text as the first-class access path (the estate already learned this at B2-465).

**Q4 (350k+ rows queryable without index decay):** Three measured/implemented answers. (a) The OKF thread's independent benchmark (vshulcz): six memory tools over 19k LongMemEval sessions in real ~/.claude/~/.codex layouts - hit@1 14-18/100 for the tools, BM25 "basically ties embeddings here at 1/100th the cost", and the real difficulty is "reranking (found@50 67 vs hit@5 35) and staleness" - direct evidence the estate's FTS5/BM25 hot path (B2-465) is the right horse and that reranking + supersession, not the lexer, are the frontier. (b) The memoryfields thread's operational pattern: git repo of markdown with the sqlite vector DB gitignored as "a rebuildable cache" - identical in shape to the corpus_fts_rebuild heal loop; the index is a cache, the corpus is the truth. (c) okf-agent-memory: no rebuild procedure at all, but lifecycle metadata (`stale_after`) plus a drift validator ("okf validate knowledge --strict --drift") and a write-side dedup law: "Search-Before-Write Principle: Mandates querying existing memory before authoring, preventing concept duplication and hallucinated divergence" - the write-side complement to the B2-465 read-side heal. Corroborating failure data: in the same 19k-session benchmark CASS failed every query on the release build and funes indexed only 189 sessions - index coverage decay at scale is real and common.

**Q5 (cross-session continuity with published measurements):** compaction-measured is the instrument. Method: grow sessions to full, force compaction, run a 178-question closed-book exam whose answers exist only in prior context, with decoy questions that have no true answer to catch guessing. Results: recall FutureOS 147/178 (83%), its deterministic mode 127 (71%), OpenCode 83 (47%), Codex 68 (38%); tool output was 96.1% of context characters but only 10% of follow-up question targets; open-book retrieval changed nothing (0 tool calls) until forced verification lifted recall to 93.3% - "retrieval can't close a retention-scope gap". Transfer: this is a ready-made protocol to MEASURE mag/hermes_warm_boot.py instead of asserting it - freeze a chain-tip exam, warm-boot from it, score recall with decoys. Second continuity data point (OKF thread): OpenAI's Astra for Codex "keeps notes across context windows and leaves earlier windows searchable, reducing reliance on compaction". Third: AML Cycle 2 (open now, materials due 2026-10-31) is a hosted Add/Search benchmark with platform-controlled scoring the estate could enter or mine - including a Coding Memory track (retrieval/reuse of engineering experience in-repo, 150 tasks x 2 conditions).
