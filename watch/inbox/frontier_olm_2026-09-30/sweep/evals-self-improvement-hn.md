### 1. The index was lying and the eval knew - gil-neto.com (RQ4 + de-echo instrument, laws.md open-question 16)
The closest public mirror of the B2-215 census-headline disease found this sweep. Hand-written index files drifted from the notes (one fact copied into six files, each paraphrased on its own clock); agents "read only the indexes" answered confidently from stale data; a nightly 30-question golden set decayed 17/30 to 9/30 unnoticed because nobody read the report ("A test nobody reads is a test that doesn't exist"). Fixes are byte-truth doctrine in the wild: generated indexes ("The model can't drift a row, because it can't write a row"), one-home-per-fact `## Now` blocks, a SQLite FTS rung under the indexes, a linter reverting to pre-night commit on staleness, and - directly on-point for the de-echoed frequency instrument - a git-diff "echo verification" that prints "NO ECHO" below threshold for every routed inbox line that never landed anywhere, "which is the one line in the morning report I now read first." Half their decay was the vault; half was the test itself (expired questions), which argues the estate's golden sets need shelf-lives and per-tier grading so a broken tier cannot hide in the aggregate. Honest caveat in-source: five nights of data, wandering scores 22-28/32, index-tier misses stuck at 3-4 - a design, not a proven fix.

### 2. My LLM eval cried wolf. Here's what I measured - digline.dev (RQ4 certified-decision path + RQ1)
A green-for-weeks LLM-judged gate flipped 5/5 to 2/5 on byte-identical inputs, then back - the gate had never measured what "unchanged" looks like. Their redesign is the anti-bare-counter: run each reference case K=5, keep the per-check min/max band as the measured noise floor, regress only outside the band, and the band belongs to the reference run, "a noisy run can't widen its own excuse." "A flip through the threshold is never within noise." "The gate is a veto, not an approval." This is the evidence-earned-promotion shape the estate's certified-decision path wants: tolerance is measured, not declared, and pass/fail flips are never excused by the band. Note for the consensus-illusion law (0/3 agreement at 0.60-0.67 strength): their 0.600 precision against a 0.615-0.667 reference band is numerically coincidental, but the methodological verdict is the same - agreement strength carried no correctness information until a correctness-anchored band existed. Reader-suggested additions worth stealing: canary case for silent model swaps, stored provider fingerprints, keeping judge reasoning text (unchanged score with changed reasoning = judge right by accident).
Overlap grep: "cried wolf" hits only caption/mrpool ledgers (incidental phrase); "noise floor" hits only mimosa hook-state cache blobs. No holdings.

### 3. Check twice, cut once with LLM search relevance eval - softwaredoug.com (RQ1, consensus-decode redesign)
The cleanest public measurement of agreement-as-calibration decoupled from correctness we have found: pairwise LLM judge vs human labels on WANDS. Forced decision agrees 75.08%; allowing abstention ("Neither") lifts precision to 85.38% at 17.10% recall; requiring bidirectional consistency (swap LHS/RHS, demand the same verdict) lifts forced precision to 87.99% and 90.76% with abstention, recall collapsing to 11.90%. The lesson for the consensus-decode redesign: agreement is purchasable with coverage, so a consensus instrument must report the precision/recall frontier, not a bare agreement rate, and must treat abstain as a first-class verdict plus enforce direction-symmetry to kill positional bias. Post is dated 2025-01-19 (resurfaced on HN 2026-09-28); code in the `local-llm-judge` repo with `--eval-fn` / `--check-both-ways` flags.
Overlap grep: zero holdings; the only "softwaredoug" hits in memory/ are this session's own trajectory lines.

### 4. What 1,350 Runs Taught Us About Prompt Guardrails - humanbound.ai (RQ2, battery scale gap)
The poisoning axis of the rib battery at real n: 9 models x 5 vendors, 3 guardrail tiers, 3 system-prompt wordings to avoid lucky phrasing, 81 attack conditions x 15 runs + benign baselines = 1,350 runs against a retail pricing agent holding a secret (SKU unit cost GBP 118.40) with lethal-trifecta exposure. The two controls are the steal: (a) every model first completes the benign multi-hop task, so non-leaking under attack is refusal, not incompetence - exactly the decoy separating "safe" from "broken"; (b) a leak counts only if the true value (de-disguised from 1x1x8.4 encoding) reaches the collector - outcome-anchored, not classifier-anchored. Results: 100% leak undefended for 4/5 non-OpenAI models; basic guardrails are wording-dependent coin flips (gpt-4o 0%-67%); hardened prompts fix 8/9 but Mistral Large 3 still leaks 53%; "not one produced a result that was both safe and well-grounded." Template for scaling the n=3 battery: conditions x repetitions with benign controls and true-value egress checks.

### 6. Show HN: FrontierHarness Eval (9 harnesses, same model, cost per pass varies 17x) - frontierharness.org + 56-comment thread (RQ2)
A published harness-vs-harness instrument: 9 harnesses, 12 configurations, 360 trials, same model (Kimi K3) and runtime, each run restored from an identical golden checkpoint (fresh vCPU/memory/disk) to kill warm-cache bias; metrics pass rate, median cost/task, cost per success, cache hit rate, runtime; headline spread 17x cost per pass. The site's own traps: success-only cost lies ("A cached 300-turn failure can still burn more than a short cache miss"; OpenCode $3.24/task once failures counted), and Claude Code passes 19 tasks at $18.34/task - quality and cost diverge. The thread is the real signal for battery design: no error bars at ~30 samples (95% CI spans 35+ points, results overlap), median-vs-mean cost dispute, single run per task, and "These conclusions would be far more credible if anyone could re-run the benchmark" (repo ships tasks+results, not runnable code). That criticism list is a requirements doc for the estate battery: per-cell repetition, CI reporting, both cost statistics, reproducible runner.

### 7. Bad benchmarks and evals: Senior SWE-Bench, napkin math, and winter tires - danluu.com + 46-comment thread (RQ4, B2-215 tripwire disease)
The taxonomy of hand-copied-number decay: napkin-math tables with measurement code where "there's no data dependency between the loop iterations, so the memory reads here happen in parallel" (speculative-execution artifacts masquerading as latency); Senior SWE-Bench stacking arbitrary pass/fail cutoffs on noisy LLM graders whose subjective "tasteful" verdicts flip about 20% on re-grade; a winter-tire claim (stiffening below 7C) circulating for years with no supporting measurement. His proposed discipline is the eval that would have caught the census 1,341 hand-copied headline before it shipped: re-run noisy graders to quantify variance before trusting any number, inspect measurement code for dependency/caching artifacts, prefer continuous aggregation over discontinuous cutoffs, and "when we have a problem we don't have a good numerical angle on, it's often better to avoid making up a fake number." Thread adds: aggregate scores hide contrary sub-results (a commenter caps results because combining scores without breaking the aggregate is hard), and an eval without explanatory power is like "benchmarking pillows visually."

### 8. Passing evals isn't enough: trace-aware judges for agents - infere.com (RQ2 + RQ1)
Judge the trajectory, not the verdict: "An output-based eval returns 'pass.' A trace-based eval returns 'passed, but it called the search tool three times...'" Components map onto the rib battery's missing axes: tool-calling accuracy (right tool, right arguments, right time), task completion, multi-step reasoning coherence, turn boundaries, cost/latency; failed steps from production traffic get promoted into a golden dataset and rerun as evals - a longitudinal ledger that learns from real failures, the shape the skill_ledger emergence question needs. Judge design: score each span, score completion, attribute regressions to the specific step. For consensus-decode: per-span judging gives a place to hang agreement (which steps did the flock agree on) that is anchored to observable behavior rather than surrogate verdicts.
