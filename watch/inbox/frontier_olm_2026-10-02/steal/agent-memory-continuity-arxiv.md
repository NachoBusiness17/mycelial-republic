## The steal (mechanism, rev 2)

Port DerivAudit's write-time support audit as a three-sided gate on the knowledge graph:

1. WRITE side: every node carries evidence_scope (hash of the source bytes at write time: for knots, the chain row's leaf_hash plus ts; for hand-folds, sha256 of the source file at fold moment) and admission_verdict (covered / unsupported / unresolvable). Placement is dictated by the collector-kind law: knot verdicts must be emitted inside _nodes_verkle(), the generator that rebuilds knot nodes from verkle_chain.jsonl each build(), because a verdict stored only on the persisted node dies at the next build() (mag/knowledge_graph.py:52, :440). Hand-fold kinds carry theirs from fold() at append time (:504-506). Dedupe consequence, stated: because of the already_present early-return (:502-503), re-folding never refreshes a verdict; the 400 existing knots get verdicts only via the generator/heal side, never via fold().
2. SCHEMA handling: additive per-node keys do not bump SCHEMA. SCHEMA = "knowledge_graph.v2" (:47) labels the graph envelope {schema, ts, nodes, edges} (:446) and envelope dicts; node records are consumed by key presence (n.get(...) at :492 and throughout known()), so unknown keys are ignored by current readers and nothing breaks. SCHEMA bumps to v3 only when a reader starts REQUIRING the new keys; per spec-before-behavior-change, that reader change and the SCHEMA bump land in one spec'd commit, never the fields alone.
3. AUDIT side: the knot audit walks the verified three-hop chain (graph node hash -> verkle_chain.jsonl row -> memory/biography/knots/<row.filename> payload) and adjudicates coverage from the payload's scalar evidence (dominant_theme, theme_basis, tension_index, inspiration), never from the node's own citations. The rev-1 lexical support check is retracted: there are no payload tokens to compare (0/10 payloads carry prose over 80 chars), so the check is coverage-style: payload exists, leaf_hash matches the node hash, at least one theme field non-empty, tension_index present.
4. CONSUMER side: context() marks nodes with an unsupported or unresolvable verdict instead of injecting them silently (mag/knowledge_graph.py:491-493).
5. Verdict grammar reuses the estate's existing accept-debt-by-NAME law rather than inventing a bypass story: tools/citation_lint.py already implements baseline acceptance by fingerprint (--baseline PATH, default configs/citation_lint_baseline.json; findings filtered by fingerprint membership; tools/citation_lint.py:41-42, :231, :279). An unsupported-verdict node stays demoted/hidden until its fingerprint lands in the baseline by name, or the payload heals.

The paper's warning ships with the port: no aggregation rule eliminates the recall/precision trade (Gemma 93.3% to 2.6%), so verdicts are advisory-at-boot, gate-at-heal.

## Probe (primary, AUDIT side; cheap, this week, zero model calls)

Sample the first 20 knot nodes from memory/knowledge_graph.json. Per node: hop 1, resolve the hash prefix against memory/biography/verkle_chain.jsonl (expect exactly 1 row); hop 2, open memory/biography/knots/<row.filename>; hop 3, coverage check: leaf_hash equals the node hash AND at least one of dominant_theme/theme_basis/inspiration is a non-empty string AND tension_index is present. Classify each node: covered, unsupported (resolves but fails coverage), or unresolvable (no unique row or missing payload). Pre-registered, exhaustive, disjoint branches on (unresolvable, unsupported) counts:

- PASS (port proceeds): unresolvable <= 5 AND unsupported in [1,4]. This is DerivAudit's residue class (17-21%): the store is auditable and a small unsupported tail exists; the tail list becomes graph_heal's first triage queue.
- ADJUST (port reshaped): unresolvable in [6,14] (the join is partial: port narrows to the resolvable class and reruns), OR unresolvable <= 5 AND unsupported >= 5 (residue exceeds the paper's class: re-register thresholds on the measured base rate before any gate code). Every composition not covered by PASS or FAIL lands here by construction.
- FAIL (port rejected): unresolvable >= 15 (the chain/payload join is broken: the repair is a rebuild, not an audit), OR unsupported == 0 with unresolvable <= 5 (every knot fully covered: no admission gate is needed; the paradox does not bite this store).

Cost: one local Python script over two files, minutes, no API spend. Falsifying numbers named before running.

## Probe (secondary, WRITE side; added per critique)

On a temp copy of the graph file (never the live one): fold one scratch node of a hand-fold kind (doctrine) with evidence_scope = sha256 of its source bytes at fold time, then mutate the source bytes and rerun the audit. Expected: the scratch node's verdict flips to unsupported with a fingerprint that names the mutation. Then rerun build() against the copy and confirm the persisted scratch verdict survives (non-collector kind) while a collector-kind node's stored verdict is wiped by regeneration unless emitted by the generator: the probe doubles as a falsifier of the SCHEMA/placement analysis above. If the generator-emitted verdict does not survive a build() rerun, the port's placement claim is wrong and must be redone.
