### RQ1: tokens/sec + cost for speculative decoding / continuous batching on 2-8B, consumer GPUs

Janitor-fleet read: on 2-8B targets, spec decoding is NOT free; per-model, per-workload N tuning is mandatory.
- Thread 49596054 carries the consumer numbers: lrvick "I have 4x r9700s as my coding daily drivers running qwen 3.8 27b at 80tps each"; naasking "I average 75 toks/s on code, 45 tok/s on prose with MTP"; pyrolistical's bandwidth math caps a single R9700 (637 GB/s) at ~33 tok/s for qwen 3.8 27b q4 before MTP. Mechanism named in-thread: single-stream LLM decode is memory-bound, so parallel draft verification amortizes weight loads; daemonologist: "If you have some other source of parallel data (lots of users, many separate tasks) then speculative decoding might not provide any benefit." Janitor fleet = single-stream janitors, so the single-stream case is ours.
- Mozilla benchmark (M4 Max / Steam Deck OLED / Xeon+L40S): engines land "within a few percent on prompt processing once weights and environment are held fixed"; config is the lever (CUDA graphs +16.8% decode on 0.8B; newer Vulkan toolchain +63% PP on 9B); and the spec-decode trap: with Ollama's library default draft of 4, 27B decode "is actually worse than no speculation at all (~15 vs 23.4 tok/s)", draft 2 rises to 24-25.
