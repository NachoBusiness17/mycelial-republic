## Answers to the four research questions

**RQ1 (releases beating gemma:2b / gemma3-4b at janitor tasks, equal or lower RAM, named benchmarks).** The strongest in-window janitor-class release found is MiMo-V2.6-Distill-Qwen-9B (Sep 21, 18.8 GB, 9.4B dense, license listed "n/a" on the tracker), but 9.4B dense is roughly 2-3x the RAM of gemma3-4b, so it does NOT meet the equal-or-lower-RAM bar; no in-window sub-4B release with named benchmark wins over gemma-class surfaced on any door I read. NV-Reason-CT (Sep 8, 5.3B dense, openmdw-1.1) is a CT-scan VLM and is ALREADY cataloged by the estate (catalog title "NV-Reason-CT: 3D Visual Language Model for CT Analysis", mtime 2026-09-24). The honest verdict: RQ1 is UNRESOLVED this window for the sub-4B janitor slot; the window's action was at 9B+ and at the scaffold layer (XGrammar-2) instead. The 2609.07370 evidence (already held, pulled by the 20260928 sweep: catalog id 950502f1ca97, full_2609.07370.txt) says raw sub-2B tool calling fails without recovery parsing (only 5 of 1,000 responses parsed as JSON), which is the benchmark-shaped reason the sub-4B slot has no winner.

**RQ2 (free-tier rate-limit mechanics: width vs rolling throughput vs both).** Two primary provider docs read today settle the mechanism question: it is BOTH, first-threshold-wins. Groq: limits are per organization, per model, across RPM, RPD, TPM, TPD (some orgs get split ITPM/OTPM), "You can hit any limit type depending on which threshold you reach first", exceedance returns HTTP 429 with retry-after only on 429, and cached tokens are excluded from the counts. Gemini: limits span RPM + input-TPM + RPD, are applied per project not per key, RPD resets at midnight Pacific, and the docs page no longer publishes per-model numbers at all (they moved into AI Studio) with the disclaimer "Specified rate limits are not guaranteed and actual capacity may vary". This bears directly on the estate's OPEN contradiction (watch/inbox/frontier_olm_2026-10-03/lens/laws.md:69, memory/rib/RIB_MODEL_GARDEN_ROUTING.md stealth row "459 rows, ZERO 429, 69h+ sustained forced mining, CONTRADICTION OPEN vs RIB_FREE_USAGE_POLICY_20260823" which says forcing free lanes throttles them into 429, memory/rib/RIB_FREE_USAGE_POLICY_20260823.md:3-5): the provider-side mechanism is multi-dimensional and provider-discretionary, so a zero-429 streak is compatible with the policy rib if the lane stayed under the narrowest dimension (e.g. RPD/TPD daily caps at mining-shaped request sizes); resolving it with instruments means probing each dimension separately, not one more width test. Community side: the June 24 tweet claiming "1m tokens per minute free" on Gemini versus today's numbers-off-the-docs page is one documented instance of free-tier floors moving under feet; the Sep 24 "Gemini Pro restricted to paid subscriptions" service-update snippet (UNVERIFIED, snippet only) points the same direction. The X search door produced no in-window post with primary rate-limit mechanics; that part stays snippet-grade.

**RQ3 (Apache/MIT 7-14B with native tool-calling, no community-license friction).** No new in-window 7-14B Apache/MIT release with tool-calling claims surfaced on the doors read. The tracker's in-window 7-14B-adjacent rows are MiMo-V2.6-Distill-Qwen-9B (license "n/a" on the tracker page; the MiMo family is MIT per search snippets and the estate's AC3 census already covers MiMo-V2.6-RL-oss, catalog title "AC3 - XiaomiMiMo/MiMo-V2.6-RL-oss census") and NVIDIA quantization re-ships of larger models. Nearest Apache-2.0 27B is Qwen3.8-27B (Aug 5, out of window by four weeks), which the estate already targets (catalog title "Plan: a bigger Kev - Qwen3.8-27B, question-side LoRA, long documents"). The Tom's Hardware piece confirms Qwen3.5-9B exists and runs on home PCs, but its headline use was abliteration via Heretic, which is community-license friction by definition, not a clean Apache handoff. Verdict: the clean-license janitor-to-specialist handoff slot stays with what the estate already holds (Qwen3.8-27B Apache, gpt-oss-20b Apache per the Groq table being served at 30 RPM dev tier); no upgrade event this window.

**RQ4 (do sub-8B models clear judgment bars, or does the tier ladder hold).** The tier ladder holds. Two independent reads this window: (a) already-held 2609.07370 shows sub-2B models at 0-7% raw MCP tool-call reliability except Qwen2.5-1.5B (75-79%) with sampling fragility (0.5B drops 72% to 32% under sampling), and its own conclusion demands schema validation, constrained generation, least-privilege execution, human escalation; (b) new 2610.00954 shows the winning small-model shape is an ENSEMBLE with a judge loop (97.34% IFEval strict, +5.81pp over gpt-5.4) bought with extra tokens and orchestration, i.e. judgment is purchased with structure and spend, not with a bigger janitor. XGrammar-2 independently reports the largest output-quality gains from constrained decoding on the SMALLEST models (BFCL-V3, four model scales). Nothing read this window supports handing solo judgment to a sub-8B; everything supports the estate's existing shape: local janitors + constrained decoding scaffold + premium judges (memory/rib/RIB_DRIVING_LADDER_20260928.md).
