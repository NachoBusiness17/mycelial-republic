context size increases. There has been
<a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://www.trychroma.com/research/context-rot#limitations--future-work">some</a>
prior work in trying to quantify the performance loss but it’s been focused on
simpler tasks, like needle in a haystack. We ran a study to quantify the
performance degradation in challenging agentic coding tasks. We found that
GPT-5.6 Sol degrades significantly whether or not the context is related to
the task, while Claude Opus 5 is only affected when it is.</p>
<p class="text-zinc-900 mb-4 leading-relaxed">For performance evaluation, we use a subset of 20 tasks from <a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://github.com/harbor-framework/terminal-bench">terminal-bench
v4</a>. We run the eval with
prefill context at 0k, 250k, and 500k tokens. Both models offer a 1M context
window [<a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://developers.openai.com/api/docs/models/gpt-5.6-sol">1</a>,
<a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://platform.claude.com/docs/en/models/opus-5/overview">2</a>] but on the
harness level, Claude Code defaults to 1M context but Codex limits to 400k
context by default. For this experiment, we configure Codex’s context window
to 1M with the flags Tibo
<a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://x.com/thsottiaux/status/2089082893804896524?lang=en">suggests</a>.</p>
<h2 id="unrelated-context" class="group scroll-mt-24 font-semibold text-2xl mt-10 mb-4">Unrelated Context<a href="#unrelated-context" aria-label="Copy link to this section" class="ml-2 inline-block align-middle text-zinc-400 no-underline opacity-0 transition-opacity group-hover:opacity-100 focus-visible:opacity-100 hover:text-zinc-600"><svg aria-hidden="true" class="size-4" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p class="text-zinc-900 mb-4 leading-relaxed">In this setting, we generated unrelated prefill context by doing multi-turn
Q&amp;A with the model on the <a class="text-primary underline decoration-primary/40 underline-offset-2 hover:decoration-primary/80" href="https://spark.apache.org/">Apache Spark</a> project,
which is not related to any of the tasks that we tested the models on.</p>

<h2 id="related-context" class="group scroll-mt-24 font-semibold text-2xl mt-10 mb-4">Related Context<a href="#related-context" aria-label="Copy link to this section" class="ml-2 inline-block align-middle text-zinc-400 no-underline opacity-0 transition-opacity group-hover:opacity-100 focus-visible:opacity-100 hover:text-zinc-600"><svg aria-hidden="true" class="size-4" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p class="text-zinc-900 mb-4 leading-relaxed">We then asked if context-rot depends on whether the earlier text is related or
unrelated to the task at hand. In this setting we created the prefill with
multi-turn Q&amp;A related to the task’s own environment and asked questions about
tools, library, and code the task depends on. Unlike the Spark prefill, these
prefills are task-specific. So one prefill per task, per model, per context
size. As before, the model being evaluated also generated the prefill, to
better simulate a real user-model interaction and to avoid off-policy
prefills. In this setting we made sure that the harness only took read-only
action during the Q&amp;A phase and rejected transcripts that took any write
actions.</p>
<p class="text-zinc-900 mb-4 leading-relaxed">GPT-5.6 Sol loses the same amount of performance regardless of whether the
context is about the task at hand or about an unrelated repo. Claude Opus 5,
which was flat under unrelated context, now drops from 50% pass rate to 40%
pass rate, when the context is related to task. Opus 5 is good at ignoring
irrelevant context, but relevant context degrades both models.</p>

<h2 id="different-tokenizers" class="group scroll-mt-24 font-semibold text-2xl mt-10 mb-4">Different Tokenizers<a href="#different-tokenizers" aria-label="Copy link to this section" class="ml-2 inline-block align-middle text-zinc-400 no-underline opacity-0 transition-opacity group-hover:opacity-100 focus-visible:opacity-100 hover:text-zinc-600"><svg aria-hidden="true" class="size-4" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p class="text-zinc-900 mb-4 leading-relaxed">An important mitigating factor for the above result is that GPT and Claude
models use different tokenizers, so measuring loss on fixed token thresholds
would bias towards the model that has a tokenizer that encodes the same
information in more tokens. Based on our data corpus, we find that 1 GPT token
= ~1.7 Claude tokens or 1 Claude token = ~0.58 GPT tokens.</p>
<p class="text-zinc-900 mb-4 leading-relaxed">To account for this, we re-plot both charts with the context in MBs of UTF-8
text. For unrelated context this mitigates the result to some extent but the
drop in performance is still significant in this view: at over 1 MB of data
Claude’s performance degradation is minimal while GPT shows a significant
regression. For related context this view doesn&#x27;t change much as both models
degrade, and per byte of context Opus 5 degrades at least as fast as GPT-5.6
Sol.</p>

<p class="text-zinc-900 mb-4 leading-relaxed">There is a quantifiable degradation in task performance as context size
increases. Both models degrade with context, but differently. GPT-5.6 Sol
loses about 25% of its solved tasks by 250k tokens of context regardless of
whether the context was related to or unrelated to the task. We also see a
catastrophic failures in GPT 5.6-Sol where it reverts to answering questions
asked in prior turns at 250k and higher context. Claude Opus 5 is very good at
ignoring unrelated context but loses 15% of solved tasks at 250k tokens of
context relevant to the task at hand. In some preliminary findings, we do see
that compaction can recover some of the performance degradation loss that we
observe at longer context. Given these learnings, the takeaway would be to use
new sessions or compact whenever possible to maintain model performance,
especially when working with GPT-5.6 or if the context is related to what you
