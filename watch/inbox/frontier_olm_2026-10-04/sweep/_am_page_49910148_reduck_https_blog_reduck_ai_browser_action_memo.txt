		<div class="prose"><h2 id="reliable-and-fast-browser-use-is-still-a-challenge">Reliable and fast browser use is still a challenge</h2>

<p>2026 has been the year for coding, cyber and math agents, but broader B2B work (finance, ops, growth, etc.) and B2C automation (e-commerce, travel, etc.) haven’t been as impacted yet.</p>

<p>One of the key reason is simple: Agents simply do not have an easy to use APIs to integrate these systems.</p>

<p>Today, even if agents can use <a href="https://claude.com/blog/dispatch-and-computer-use">Computer Use</a> to automate sites with no API (Amazon, Reddit, your custom ERP), Computer Use is inadequate for complex and heavy workloads because it’s:</p>

<ul>
  <li><strong>Slow</strong>: every click is a loop (screenshot, think, click, screenshot again)</li>
  <li><strong>Expensive</strong>: screenshots and page snapshots go into context at every step, so a task burns tokens and hits rate limits</li>
  <li><strong>Flaky</strong>: results vary from run to run and get worse as the context grows</li>
</ul>

<h2 id="agents-have-no-memory-layer-for-the-browser">Agents have no memory layer for the browser</h2>

<figure>
	<img src="agent-relearns-notion.gif" alt="Claude, asked to list Notion invoices with its browser, opens notion.so, reads the page text, captures the page, opens notion.so again, searches for Settings, clicks and waits: 32 seconds in, still no invoice" />
	<figcaption>Agents have to manually discover and navigate each time</figcaption>
</figure>

<p>At the heart of it, agents are slow and unreliable at Computer Use because they:</p>

<ul>
  <li><strong>Waste time learning how a website works</strong>: e.g. that invoices are found by clicking “Settings” and not on “Profile”, scrolling all the way down, and clicking “Billing”.</li>
  <li><strong>Waste time redoing the action</strong>: even with a Skill that stores how to navigate, the agent still operates in a loop to click and type, check new state, think and act again, which floods its context.</li>
</ul>

<h2 id="introducing-reduck-mcp">Introducing Reduck MCP</h2>

<p><img src="one-integration-every-website.png" alt="Reduck architecture: AI agents connect through Reduck's MCP and extension to reach any website" /></p>

<p>That’s why we built Reduck MCP, the memory layer for browser actions.</p>

<p>Instead of browsing from scratch or performing manual actions, Agents can now write scripts + metadata on how to use it and then use it for faster future navigation.</p>

<p>To solve the cold start problem we maintain a library of <a href="https://reduck.ai/explore/scripts?utm_source=blog&amp;utm_medium=referral&amp;utm_campaign=browser-action-memory-layer-for-faster-agents&amp;utm_content=catalogue">official scripts</a> for the most used sites, such as LinkedIn, Google Maps, Instagram and Stripe.</p>

<figure>
	<img src="script-catalogue.png" alt="The official scripts library on reduck.ai: search LinkedIn people, get an Instagram profile, get a YC company profile, search Google Maps places, download a Stripe invoice" />
	<figcaption>The official scripts, ready for your agent</figcaption>
</figure>

<p>Here is an example of script with <a href="https://reduck.ai/explore/scripts/reduck/console.anthropic.com/list_invoices?utm_source=blog&amp;utm_medium=referral&amp;utm_campaign=browser-action-memory-layer-for-faster-agents&amp;utm_content=anthropic-invoices">“List Anthropic Console invoices”</a>. It states the input it takes (none) and the output it returns (every invoice of the organization), so an agent calls it the way it calls any other tool, <strong>but also can know how to chain them</strong>.</p>

<figure>
	<img src="script-page.png" alt="The page of the List Anthropic Console invoices script: what it does, no input, and an output of count, invoices, organizationId and pages" />
	<figcaption>A script states what it does, what it takes and what it returns</figcaption>
</figure>

<p>If no script matches, agents can write one with Reduck MCP and use it later.</p>

<p>So how is Reduck 3.6x faster here?</p>

<ul>
  <li><strong>Scripts that already know the site</strong>: the catalogue has an <a href="https://reduck.ai/explore/scripts?q=invoices&amp;utm_source=blog&amp;utm_medium=referral&amp;utm_campaign=browser-action-memory-layer-for-faster-agents&amp;utm_content=invoices">invoice script</a> for each of the five providers, so the agent calls <code class="language-plaintext highlighter-rouge">run_script</code> instead of finding its way around each billing page. This means that there is no need to do the loop with read state, think, atc, read again.</li>
  <li><strong>Parallel execution</strong>: <code class="language-plaintext highlighter-rouge">run_script</code> takes a batch of args, so scripts run in parallel on several tabs.</li>
</ul>

<h2 id="faster-on-every-task-we-ran">Faster on every task we ran</h2>

<p>The invoices are one task of three. We gave Claude two more, each with the same prompt once per tool: find this week’s viral founder posts on X, and find a Reddit post from a vague memory. With Reduck MCP, Claude finished all three first, 2.5x faster overall:</p>

<figure>
	<img src="time-per-task.png" alt="Time per task, Claude with Reduck MCP against Claude with Chrome MCP: 132 s against 472 s to download 20 invoices (3.6x faster), 216 s against 441 s to find viral founder posts on X (2.0x faster), 34 s against 60 s to find a Reddit post (1.8x faster)" />
	<figcaption>Time per task: Claude with Reduck MCP against Claude with Chrome MCP</figcaption>
</figure>

<p>The time difference comes from not having to loop on the UI: with Chrome, every screenshot, click and page read is a tool call, and Claude thinks before each one. With a script, one call does the whole job on a site, so Claude made 4.2x fewer tool calls over the three tasks:</p>

<figure>
	<img src="tool-calls-per-task.png" alt="Tool calls per task, Claude with Reduck MCP against Claude with Chrome MCP: 20 against 132 to download 20 invoices (6.6x fewer), 18 against 31 to find viral founder posts on X (1.7x fewer), 6 against 20 to find a Reddit post (3.3x fewer)" />
	<figcaption>Tool calls per task: each one is a step Claude has to think about</figcaption>
</figure>

<h2 id="create-your-own-evals-with-reduck-voyager">Create your own evals with Reduck Voyager</h2>

<p>To produce such evaluations and their 1:1 comparison, we wrote <a href="https://github.com/reduck-ai/reduck-voyager">Reduck Voyager</a>, our open-source eval framework for web agents. Other examples are at <a href="https://voyager.reduck.ai/">voyager.reduck.ai</a>.</p>

<p>It wraps the Claude Code SDK to launch agents on exactly the same prompts, except that “Use Reduck MCP” becomes “Use Claude for Chrome MCP”.</p>

<p>Evaluation is done with deterministic code when possible, or with custom labels from a human or an AI.</p>

<p>Our sample is small, so feel free to contribute your own data!</p>
