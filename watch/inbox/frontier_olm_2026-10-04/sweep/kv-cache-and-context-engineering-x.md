## Answers to the five research questions

**Q1 (unwired lmcache features + upstream delta).** Unwired is nearly everything: the serving path is Ollama janitors, and the snapshot's v1/ tree carries blend (CacheBlend), kv_codec (asym_k16_v8), ec_engine, gpu_connector, offload_server, cache_controller (Kafka event sink at tip #5285), mp_coordinator, lazy-offload in integration/vllm (lazy_offload_manager.py, lazy_offload_policy), sglang and tensorrt_llm connectors: none of it executes in the estate's path (module listing run this sitting). The nearest wiring point is a vLLM sidecar for the batch lanes, where the InferenceX agentic optimizations (chunked external-cache loading, hybrid-group partial storage, DCP-aware CPU offload) are the features with measured payoffs, and all predate the snapshot tip by PR number (all < #5285). Upstream delta beyond the snapshot: the sibling lane's releases fetch reads v0.5.6rc2 (2026-09-28) whose only changelog line is a Dynamo integration guide, plus nightlies (CUDA 12.9/13.0, ROCm 7.2, MUSA) (sweep/kv-cache-and-context-engineering-arxiv.md:9). Commit-level delta 09-21..10-04 not enumerated (shallow clone, no git fetch; stated as not run). Verdict: the estate does not need a newer shelf; it needs one wire.

**Q2 (compression-rate-vs-quality curves for context_compression.py).** From the X-side sweep, three curve sources to benchmark against: (a) the trevin RTK measurements: savings are per-command and bimodal (-71.9 percent to 0 to negative), so a single headline compression rate is meaningless without the hit-rate denominator (13.2 percent here); (b) SOMA's two-axis validator framing (saved vs preserved), which matches the already-banked PAIR counterfactual-continuations design (sibling lane, sweep/kv-cache-and-context-engineering-arxiv.md:37); (c) the LLMLingua lineage numbers that keep surfacing (LLMLingua 9.8x latency vs LLMLingua-2 0.67x in third-party tables) as the classical baseline row. Combined with the sibling's banked curves (Beyond Token Savings 35,000-run dataset), the benchmark design is: sweep ratio, score reliability interventionally per compression event, report net on real traffic, never a single aggregate rate.

**Q3 (seven unwired carriers: which are KV/context-shaped, what wires them free).** The carriers (stealth_driver, duel_harness, tesuji_fire, lane_runner, lite_scale, wave_fire, ds_workhorse; lens/laws.md:75 citing memory/rib/RIB_INFERENCE_BUDGET_20261001.md:100-114) are all context-shaped in the same way: they hand-roll long frozen prefixes (estate-law blocks, rib chains) whose re-prefill dominates their token bill, and 2605.26297's finding (most input reused with effective caching) says that bill is mostly cache-miss waste, not model work. Wiring without paid dispatch, three moves from this sweep: (1) byte-stable prefixes with append-at-end evolution, already estate law (memory/research_polished/kv_cache_compaction.md:9, DeepSeek 50x hit/miss), which makes every provider-side prompt cache a ~10x discount on the frozen prefix; (2) source-side output shaping per trevin (lossless tool-output densification measured at net on real traffic; never marker-and-fetch); (3) if a vLLM sidecar is ever stood up, the shelf's own prefix-hash reuse plus CacheBlend is the local version of the same discount. The class-kill (EMPTY_REASONING) and the cache contract live in the same bytes: freeze them and both improve.

**Q4 (packing-density floor for context-pack).** The floor dropped this week. Vendor-side: Google's own BFS F1 falls 99.7 -> 84.2 leaving the 128k band (Fei2411, above), and frontier harnesses cap at 256k-500k in practice. Field-side: visible degradation from ~500k, non-functional near 700k. Combined with the sibling lane's banks (compression degrades reliability before solvability, 2609.36526; episodic retrieval beats recency by query-evidence distance, 2610.00562), the working floor for context-pack: treat the reliable packing region as ending near the vendor caps (128-256k), not near the nominal window; past that, retrieve. Any density threshold computed from solvability alone will be set too low because reliability dies first.

**Q5 (KV quantization x the reasoning-quant ladder).** Yes, and the interaction is asymmetric: K and V are different rungs. sergiob's KL table (above): K below 8 bits costs reasoning (logic loops at Q5_0, destruction at Q4_0) while V is nearly free at 4 bits; the safe combined configuration for reasoning workloads on the janitor fleet is weight-quant per the ladder plus K=Q8_0/V=Q4_1 (or Q4_0) KV, flash attention on (the V-cache quant requirement per the llama.cpp behavior this sweep corroborated in search results), with long reasoning chains as the acceptance test rather than perplexity. The estate's own banked rows already agree from the weight side (ternary PQ2: 3.02x slower, 3.10x more tokens, burns.md:93-94); the KV side adds the K/V split, and lmcache's in-tree kv_codec asym_k16_v8.py shows upstream made the same asymmetric bet (16-bit K class, 8-bit V class) in the serving engine. Falsifier for the probe: run the ladder's reasoning set at fixed weights across KV (K8/V4 vs K8/V8 vs K5/V4) and measure loop-rate, not just accuracy.
