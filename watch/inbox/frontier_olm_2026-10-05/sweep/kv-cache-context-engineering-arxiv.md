## Pass 2: deep reads (9 full texts, fetched 2026-10-05)

1. **KVTether** (2609.39819, 09-30, cs.DC). The semantic-gap paper: harnesses see message-level operations, serving stacks see only pages and access events, so LRU evicts the wrong KV in ReAct loops. Eight lifecycle primitives (append/replace/remove, fork/spawn, one_off/pin/unpin) exported asynchronously from the harness; per-context-per-version states Pinned/Active/Suspended/Expired/Temporary; Suspended tier uses MRU. vs LMCache: latency -16.5% avg (to -26.3%), price -40.0% avg (to -53.6%), hit ratio +33.3% abs; zombie KV up to 36.3% of LMCache capacity; 71.0-95.0% of LRU evictions wrong-direction; even agent-aware MORI peaks 49.7% zombie. Integration 26-216 lines/harness, ~2.0% overhead, SGLang + GLM-4.7 on 12x GB200. Read against our compact-anchor design: this is the harness-side half we never specified - the design doc (`memory/design/compact-anchor-context-mechanism.md`) handles stable-prefix reuse but says nothing about dead-KV reclamation when a trail rewrites a section.
2. **CADOC** (2609.37012, 09-29, cs.AI). The compact-anchor design, published: structured objects externalized with immutable versioned IDs; replaced in-prompt by deterministic metadata Cards (no LLM synopsis); `retrieve_object` returns exact original bytes (SHA-256-verified in their eval: 9,925 bytes matching); protected hot tail (h blocks / 12,800 tokens); and the new half - COMMIT TIMING: an EOQ-style online rule `W_t + w_r*G_t >= Q_t` batches replacements so one edit costs one cache break. Immediate-replacement raises cost 3.67% despite cutting tokens 55.93% (cache-break economics); CADOC cuts input cost 34.12-47.13% on Terminal-Bench/SWE-bench/LongMemEval chains at <=4pp completion loss. This is validation + a refinement our design doc lacks (the batch-commit scheduler).
3. **ReCAP / Persistent Context Graphs** (2609.40118, 09-30, cs.AI). Attention recorded during ordinary inference becomes a persistent importance+dependency graph; selection at each new request is graph traversal + IDF-weighted identifier overlap, reversible (archive persists, omitted blocks revive - 70% of turns revive at least one). Compaction/cold-restore latency -95% vs Codex-style summarization; LiC accuracy +19.8/+41.2 pts vs full-history; ~half the historical context on SWE-Together at HIGHER accuracy. Tool-call fidelity answer: a node is "an assistant message that issues tool calls together with their results" - call and output never separated; user messages and latest-edit nodes are a protected set. Cold fact for our warm-boot design: "requests after hour-long gaps almost always miss the serving cache" (4,300 Claude Code/Codex sessions).
4. **Provenance in Shared KV Caches** (2609.38706, 09-30, cs.DC). Audited connectors (LMCache, vLLM filesystem/Mooncake, SGLang HiCache): keys are token IDs + model name + TP + rank + sometimes KV dtype - nothing else. Identical tokens under different LoRA adapter / precision / weight version / salt derive the same key: cross-adapter collisions 0.94 to 0.64 accuracy; wrong-dtype KV drives reasoning to 0; salt omission = 93% prompt identification from timing. Fix: canonical provenance descriptor digested once and folded into the native key; <=0.34ms hit-path cost. Directly extends Q4: even where keying IS token-exact, token-exactness is not a correctness contract.
5. **MORSE** (2609.27380, 09-23, cs.CL). In sequential likelihood-based compression, the ORDER of contexts decides which evidence survives: one pair-swap moved gold evidence from deleted-at-all-ratios to preserved (SF-R 0.5 to 1.0); compression-order-only changes (Original to Reverse) gained +9.58 SF-R mean across 12/12 settings, while presentation-order-only changes moved F1 by +0.05. Mechanism named: information preemption - an earlier partially-relevant context absorbs credit for shared information. Q2 answer, sharpened: order matters where it changes WHAT IS COMPRESSED, and is nearly irrelevant where it only changes presentation of fixed content.
6. **Words Speak Louder Than Order** (2609.30716, 09-25, cs.CL). Gemma 4, counterbalanced 4-way design separating framing, position, vocabulary bias: framing beats position ~4:1 (+1.054 vs -0.265 nats); primacy magnitude varies ~5x on wording alone; "Position matters; framing matters more."; the value of an ordering effect "belongs to the prompt template, not to the model". Authority headers attenuate primacy (+0.315 nats) - and are a hijack surface. Q2 answer for prompt-shape work: ordering levers are real but template-local and unstable under paraphrase; header/section labels are the stronger, more predictable lever.

## Answers to the four research questions

**RQ1 (KV-reuse / prefix-caching best practice for multi-turn agent sessions, LMCache lineage).** Three new results past the sibling sweep: (a) KVTether names the structural cause of LMCache's losses in agent loops (lifecycle blindness; zombie KV 36.3% of capacity) and the fix shape (harness exports message-level primitives; cache engine is state-guided, Suspended-tier MRU) at 26-216 integration lines per harness; (b) CADOC prices the interaction of context editing WITH prefix caching - immediate compaction can RAISE cost 3.67% while cutting tokens 55.93%, and batched commit timing recovers 34-47% - which is the quantitative version of our compact-anchor invariant; (c) Provenance shows the LMCache-lineage shared tier keys are token-plus-metadata only, so cross-variant reuse is a correctness hazard, not just a perf question. Estate tie: the B4 KV sweep instrument and lmcache-src shelf should record KVTether's eight primitives as the interface our lane-runner/trail events would need to export if we ever run a local tiered cache; the compact-anchor design doc gains CADOC's EOQ commit rule as section 3 material.

**RQ2 (context ordering and section structure vs long-context agent accuracy, 2026 evidence).** The window's measured answer is "it depends on WHICH stage the order touches": MORSE shows ordering under likelihood-based compression swings evidence retention enormously (single swap: SF-R 0.5 to 1.0; compression-order-only +9.58 SF-R mean) while presentation-order-only changes are noise (+0.05 F1); Words Speak Louder shows, for fixed content, framing and section labels dominate order ~4:1 and the positional effect is template-specific (~5x variance under paraphrase) on Gemma 4. For the descent protocol's prompt-shape leg (mag/claritas.py + estate-law block): spend prompt-shape effort on section labels/authority headers and on compression-time ordering (what we fold FIRST), not on micro-arranging presentation of fixed text.

**RQ3 (compaction preserving tool-call fidelity).** ReCAP's node rule is the direct answer: keep each tool call PAIRED with its result as one atomic node; protect user messages and the latest-edit node per file; make selection reversible (archive persists, 70% of turns revive omitted blocks) - beats summarization on accuracy while halving history. CADOC's version is stronger for cache: do not summarize at all - externalize the object, leave a deterministic card in the prompt, retrieve exact bytes back (SHA-256-verified), and batch the rewrites. Both agree the fidelity mechanism is identity-plus-retrieval, not prose compression; this matches EfficientAgent App G (sibling sweep) showing history-rewriting condensers collapse prefix hit rate 96.5% to 50.8-60.85%.

**RQ4 (do provider prompt caches key on byte-identity, per current docs?).** YES for keying, with four documented caveats our playbook/design doc omit. Anthropic (fetched 2026-10-05, platform.claude.com/docs/en/docs/build-with-claude/prompt-caching): "Exact matching: Cache hits require 100% identical prompt segments"; "changing any block at or before the breakpoint produces a different hash on the next request"; "Modifying tool definitions ... invalidates the entire cache"; writes happen only at your breakpoints; default 5-minute TTL (1-hour paid), workspace isolation, min 512-2,048 tokens by model. OpenAI (fetched 2026-10-05, developers.openai.com/api/docs/guides/prompt-caching): "Cache reuse requires the entire rendered prefix to match."; the key is "A hash of the initial tokens after the hidden OpenAI content, including tool definitions when present" (hidden-prefix tokens vary by model and do NOT count toward the 1,024-token minimum); and hit-or-not is also a ROUTING event: "A request can reuse a cached prefix only if it reaches a machine holding a matching entry that has not expired." (30-minute default TTL; org-scoped). Verdict for our docs: `memory/design/compact-anchor-context-mechanism.md:11-15` ("key on exact token sequences") is correct on keying but incomplete - add cumulative-hash invalidation cascade, breakpoint-scoped writes, hidden/tool-def prefix inclusion, min-length floors, TTL, and routing non-determinism (ReCAP: hour-gap requests almost always miss). The playbook's byte-identical-amend-cache claim (`corpus/steal/ZCODE_OPERATING_PLAYBOOK_20260925.md:10-11`) is about the harness's own FNV-1a amend-cache, which is byte-identical by construction and unaffected.
