## Findings against the four research questions

Q4 (do provider caches key on byte-identity?) - YES with documented nuance. OpenAI's current guide states the matching rule verbatim: "Cache reuse requires the entire rendered prefix to match. If content or a relevant setting changes before a breakpoint, the prefix after that change cannot match the existing cache entry." The unit is the rendered prefix - content, ordering, AND settings (model, tools, structured-output schema, reasoning effort) - stored as KV tensors, not tokens. Routing within org+region keys on "a hash of the initial tokens after the hidden OpenAI content, including tool definitions" plus an optional prompt_cache_key; keys bias routing but never guarantee hits. Numbers: 1,024 visible-token minimum on GPT-5.6+; writes 1.25x, reads 0.1x (0.05x on GPT-6.1 Sol); TTL options "30m" or prompt_cache_retention "in_memory" (~5-10 min) / "24h"; compaction and history rewrites reset reuse. This validates the ZCODE_OPERATING_PLAYBOOK byte-identity assumption at the rendered-prefix level and sharpens it: byte-identity of your messages is insufficient - tool-list changes and setting changes break the prefix even when message bytes are identical. Replay Doctor independently field-measures the failure mode: 106.7M tokens re-billed ($631.77, 4% of $16,078.68 total) on one machine, attributed to tool-list mutations, TTL expiry, and re-renders ("A re-render is frequent and small; a TTL expiry is rare and enormous"), and finds 39 compactions with median retention 2.55% - compaction is simultaneously a Q3 failure mode and a Q4 cache-breaker. The truth-auditor post (already-held percolator row) adds the epistemics: engine attestation alone is not proof; require an independent token oracle + observed prompt work + output identity, verdicts typed verified_hit / partial_reuse / verified_miss / evicted.

Q1 (KV reuse / prefix-cache designs for multi-turn agents). doug.sh gives the self-hosted vLLM recipe with hard numbers: automatic prefix caching matches per-block cumulative hashes walking from the start ("It matches a prefix rather than diffing two prompts"); the CPU-tier OffloadingConnector restores evicted blocks (42k tokens in under 0.5 s vs 24 s cold); deterministic serialization + sorting JSON keys + placing volatile content last took cached tokens 55% to 95% (78% to 95% from the template key-sort alone) and first-token wait 26-28 s down to 7.3 s; and, directly relevant to our harness, mcp-go/Bifrost randomized tool-schema JSON key order (Go map iteration), silently breaking prefixes near the top of the prompt; the fix merged (bifrost#7170, mcp-go#984; template fix `tojson(sort_keys=True)`). "Hosted APIs match a byte-identical prefix that includes the tools block too." Per-agent text before shared text caps sibling-agent prefix sharing at 60-70%. j9s.io gives the agentic-serving state of the art: FP8 KV quantization halving 256 KiB/token, CPU offload breakeven ~43,270 tokens at PCIe 5.0, madvise-style eviction hinting (dontneed/pageout/willneed_soon/willneed_later) driven by EWMA inter-turn gap durations per tool type, priority admission scheduling; median agent inter-turn gap 0.18 s vs 96.24 s chat; 120 GB offload kept prefix reuse near 100% across the sweep. It names the LMCache-lineage successors worth pulling next: Continuum (1.10-3.22x), TokenCake, CacheWise (2-2.6x fewer evictions), KVFlow (up to 2.19x), Autellix (up to 8x vs vanilla vLLM), Mooncake. Magnitude (YC S25 launch, top-of-window) productizes the SGLang radix idea for local agents: hybrid paged attention letting concurrent sessions share prefix caches, 8-bit key / 4-bit value KV quantization (TurboQuant-inspired) with RULER-based retrieval checks, prefix-tree endpoint reuse; commenters supply the skeptical baseline (llama.cpp/MLX comparisons, missing spec decode, degradation claims at 100-200K context).

Q3 (compaction preserving tool-call fidelity). swarmagent.dev argues compaction is the wrong primitive: "LLMs summarize concepts, not invariants" - exact commit SHAs, line numbers, race-condition edge cases smooth away, so agents re-hallucinate fixed bugs; the replacement is plans as typed JSON runtime state with bounded checkpoints ending in ~350-token structured handoffs (changed files, validation commands, impact bullets), plus schema validation and independent test-run verification; Century Run benchmark: 100 agents, 100 deliverables, 7.89M prompt tokens, $9.97 total, claimed 80.2-92.4% cache hit ratio. Replay Doctor's field data (median compaction retention 2.55%) independently quantifies how little compaction preserves. Tool-call-specific fidelity: doug.sh shows the tool block itself must be byte-stable (schema key order, the mcp-go shuffle) - a compaction that re-renders tools at all breaks the shared prefix; Replay Doctor's worst example break was a 3-tools-added/1-removed mutation re-billing 157,080 tokens.

Q2 (context ordering / structure vs measured accuracy). Thinner door, one solid item: PARSER (arXiv 2609.06702) decouples reading from reasoning - frozen subagents read chunks in parallel, an RL-trained lead agent runs scatter-gather - and reports robustness to evidence position/order/distance perturbations where sequential memory agents swing hard: 4B backbone beats the best sequential baseline by 5.7 points average on multi-hop QA at 7K-896K tokens (12.0 points at 896K), and cuts latency up to 11x. Ordering evidence on the cache side is much stronger than on the accuracy side this window: doug.sh's "put what changes most often last" is a cost law (prefix survival), and the OpenAI doc's static-first/dynamic-last guidance is the provider-documented shape. No 2026 item found that cleanly measures section structure against agent accuracy independent of cache economics - that gap is itself a finding.
