## The mechanism (one placement law, three ports)

Published systems converged this window on a single law the estate's own measurements independently convict it of violating: **all rewriting of memory happens on the archive, at window close or on a schedule; the live (boot) prefix is append-only and byte-stable.** The three finds are three faces of that law:

1. **Dreaming = pruning placement.** The stale-record pass runs at night against the archive; the live window and the boot prefix are never edited mid-flight. The KV consequence: pruning that demotes (pointer) instead of rewriting (in-place) cannot move any leading byte of any durable record.
2. **Agent Memory Repo = archive schema.** Git+markdown, append-only historical records, commits after every edit, with a short always-loaded MEMORY.md entry point that "include[s] only what every session needs, plus links to everything else" (`agent-memory-continuity-hn.md:93-94`, quoting the spec). The KV consequence: a rendered entry point over an append-only store can keep a byte-identical leading block while the archive only grows.
3. **Pi Durable = resume placement.** Suspend and resume happen at task boundaries by serializing state through the harness's small workflow engine, not by keeping a window alive; the announce explicitly rejects heavyweight orchestrators (Temporal, Effect.ts) in favor of the file chassis. The KV consequence: a resumed session re-consumes only what a verified-prefix receipt proves it may skip.

## Estate map (organs, verified state THIS ask, port moves)

**Organ 1: Context pack / boot recap (zknot).** The disease is measured and banked: 171 zknot pairs, max stable-leading-block share 0.59 percent (`watch/inbox/frontier_olm_2026-10-05/steal/agent-memory-continuity.md:32`). The mechanical cause is visible in today's bytes, read this ask: `memory/zknot/LATEST.md` is 21,052 bytes and opens with the volatile elements - the METER self-steal line starts at byte 57 and the minute-stamped `_Written 2026-10-06 15:16 ET` line follows it - so the recap's most volatile bytes sit in the FIRST cache block of every boot prompt. The archives themselves are already append-only (23 .md files in `memory/zknot/` this ask, up from 20 at the 10-05 measurement, one file per session plus LATEST.md), so the estate already holds half of the AMR shape. Port move: make LATEST.md a RENDER over the append-only archives, AMR-style - a frozen leading block (seat-independent identity, demotion-register pointer, links) then a volatile tail (meter deltas, minute stamp, session rows) - so two rewrites inside one UTC day share a byte-identical prefix. This is executor arm (a) of the banked 2026-10-05 probe (`agent-memory-continuity.md:58`), made concrete by the AMR schema; the zknot writer is deterministic (`tools/zknot.py`, session exclusion at `tools/zknot.py:69-70`), so the render is a pure function and the assert needs no model.

**Organ 2: Water graph / forget ledger.** The estate's pruning primitive already exists and already obeys the demote-not-delete law: `memory/corpus/quantized_thought/graph_ghosts/forget_events.jsonl` carries `"event": "forget"` rows under `"law": "pointer-law: demoted-not-deleted (S9 ARC)"` with a pointer field to the demoted artifact's new home (head rows read this ask). Port move: the scheduled Dreaming pass (the HN sweep's missing half, `agent-memory-continuity-hn.md:104-105`) emits forget-ledger rows - demote with pointer, never rewrite in place - over the 648-row percolator registry (count verified by my parse this ask: `json.load` over `memory/percolator/invariants.json` = 648 invariant rows) and the graph's stale nodes, so a prune can never move a leading byte of any record a boot pack might carry. The KV half is what this card adds to the HN sweep's memory-continuity half: demotion-through-ledger is a prefix-stability mechanism, not only a hygiene mechanism.

**Organ 3: Gopher fleet / lane runner resume.** Pi Durable validates the estate's file chassis and names the missing wire. Today `mag/lane_runner.py` keeps per-lane state in `queue/lanes/<lane>/runner_state.json` (`:114-121` read, `:124-149` atomic tmp+replace write) but the fields are cycle bookkeeping only: `inbox_offset` (`:404`), `cluster_done`/`cluster_prev_keys` (`:652`), `escalated_sweep` (`:780`), `rotation_epoch` (`:797`). Pi Durable's rejected-alternatives note (Temporal, Effect.ts, `kv-context-engineering-x.md:176`) is external evidence the jsonl-file chassis is a deliberate, defensible choice - the estate does not need an orchestrator, it needs the boundary write.

Baseline to beat: max 0.59 percent / median 0.28 percent over 171 pairs (`watch/inbox/frontier_olm_2026-10-05/steal/agent-memory-continuity.md:32`). This is executor arm (a) of the banked probe, now pinned to a concrete schema by find 2. **Falsifier:** if any volatile byte (meter delta, minute stamp) drifts past the cut, or the two renders share under 1 percent leading bytes, the AMR-style render does not cure the re-tokenization disease on the estate's real zknot data and this card dies as decoration.
