## Answers to the five research questions

**Q1 write seams, who has a serializer.** The field converges on isolation-over-locking, with the lock parked only at the merge/fold point. Three independent confirmations: parallel-code gives each task "its own git branch and worktree automatically" and merges through a review sidebar; Cherny (creator of Claude Code) runs five tabs plus 5-10 web sessions where "Each tab runs in its own git checkout (worktree) so parallel work doesn't collide"; Mnemoverse's shared memory has NO lock at all and corrects by append ("correct a wrong or stale memory by writing a fresh one"). Map to the estate: the general contract is two-tier. Tier 1, a hard mutex only where runs truly cannot interleave (our fold phase; `tools/fold_gate.py:4-13` already holds this). Tier 2, everything else is per-seat isolation (worktree/branch per lane, file-scoped appends via `tools/ledger_lock.py`) plus an append-fresh correction record instead of in-place edits, which is also the cure shape for the LIVE_REPORT mtime inversion (regenerated pages should write-fresh under a name the reader resolves by mtime, never edit in place). The seams still WITHOUT a serializer after this sweep: tree-sweep/stash-class shared-tree mutations (R3's class, `burns.md:127-129`) and any two lanes appending to one registry at once; nothing found today contradicts extending fold_gate's acquire/stale-break pattern there.

**Q2 mesh/frontier boundary.** No direct widening evidence from X this sitting; the honest result is one mechanism plus one census-shaped confirmation. kasun.dev's role-split ("one expensive brain, many cheap hands" with explicit `model:` on every agent call) is the ROLE axis our question-CLASS law does not yet measure; it also contributes a skip rule for the cheap tier, delegate only "when the brief would be longer than the work itself" is the negative form (do it yourself then), and a SendMessage return-path so fix context is not paid for twice. The boundary census (17-question battery, `laws.md:87`) gains battery-extension candidates only indirectly (the HN sibling's Ask-HN finds); X itself yielded nothing measurable today.

**Q3 graph wiring.** Thinnest lane of the sweep, stated as such. The one transferable mechanism is Mnemoverse's outcome re-ranking: memory edges are not static, a Rescorla-Wagner prediction-error update raises a memory that helped and sinks one that misled. That is a wiring contract for the estate's 757 degree-0 nodes (`graph.md:25-29`): link at write time (each knot/doctrine/steal row names its target module at bank time) and weight the edge by later outcome feedback, so the graph grows edges as a side effect of use instead of by backfill batches. No second source found; treat as a lead, not a confirmed pattern.

**Q4 subagent rate-limit resets.** No new in-window vendor reset news surfaced on X; the ClaudeDevs primary (2026-06-01) stands and the HN sibling holds the agent-limit-retry instrumentation (resume-before-reset dies again). The one new cost mechanic is kasun.dev's inheritance fact: "every subagent you spawn inherits the parent's model unless you say otherwise", which makes fan-out width a premium-token multiplier by default. **Q5 planning-mode gate.** Strongest lane of the sweep, two in-window failure reports of exactly the gate we are ordered to build. t3code #15503 (2026-10-04): the auto branch of the approval dispatcher "returns allow without checking for plan mode", so plan-mode write requests executed with no prompt; reproduction via delegate_task with interactionMode "plan" and "Both writes ran with no prompt." anthropics/claude-code #94788 (2026-09-16): the ExitPlanMode dialog's "auto row displaces the acceptEdits row", so approving a plan silently moves the session off the configured default mode. Design laws for mag/plan.py + the dispatch gate, earned from both: (a) the plan state must be checked on EVERY write-authorization path, not only the interactive one (fail closed on the auto branch); (b) approving a plan must not silently change the permission mode it returns to; (c) the positive shape is NicerInPerson's swarm tweet: "When you approve a plan, it enters a new 'delegation mode'" - approval is the explicit transition event that unlocks delegation, which is exactly the operator-nods-the-plan gate the cold-seam tesuji orders (`laws.md:95`); (d) Cherny's practice shows the gate is cheap when plans are good ("Start in Plan Mode ... then switch to auto-accept and let Claude execute in one go").
