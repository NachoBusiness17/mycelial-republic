TITLE: Discussion Built an open-source hallucination detector that runs in 1.5ms on CPU (90,000x faster than Semantic Entropy)
POST: Hey everyone, If you’ve tried implementing hallucination detection in production, you’ve probably seen Semantic Entropy (Farquhar et al., Nature 2024). It works well, but it relies on clustering responses using a heavy DeBERTa model that takes 100+ seconds per query and eats up GPU VRAM. Myself Bhupen and i have built Spanda- (https://github.com/Adarshent/Spnda) a lightweight, zero-dependency alternative that runs in pure Python. How it works- Instead of running a second neural network to check your first neural network, Spanda samples $K$ outputs and computes a normalized lexical consensus ratio ($R_{sc}$): - Latency: ~1.5 ms on CPU (vs ~136 seconds for DeBERTa). - Cost: $0 in additional API calls or GPU VRAM. - Accuracy: Achieves 0.889 AUROC on math/reasoning tasks (GSM8K) for 7B–27B models, matching heavy NLI clustering. One major gotcha we found: If you are using heavily aligned frontier models (like 120B+), watch out for Confident Mode Collapse. Even with temperature set to 0.7, the model will sometimes repeat the exact same hallucinated answer across all seeds. When a model hallucinates with 100% agreement, self-consistency methods fail. - GitHub: https://github.com/Adarshent/Spnda (MIT License) - Install: `pip install spanda` Would love to hear how folks here handle real-time uncertainty scoring in your production pipelines!

  COMMENT: Spot on—you hit the exact operational boundary we discuss in the paper, and "gaslighting" is honestly the best description of what Confident Mode Collapse feels like in practice. Why this happens: Intense RLHF/DPO alignment rewards models for sounding helpful, authoritative, and confident, while penalizing hedging. At 120B scale, the probability distribution over tokens becomes hyper-peaked. The model loses entropy and sampling diversity on ungrounded facts. The scary takeaway for production: Any guardrail or verification pipeline that relies solely on do multiple samples agree? (Wang et al. self-consistency) will be structurally fooled by frontier models when they hallucinate. You need external retrieval (RAG) or logit-level probes to catch them. Preprint with the full scaling tables is here if you want to look at the curves: https://zenodo.org/records/22233648

  COMMENT: Consensus scoring is a solid cheap first layer, and the mode collapse note is the part people should copy down. Once a model is confidently wrong, every self-consistency method inherits that confidence, since all K samples come from the same prior. What helps is scoring agreement against something external instead of between samples. Entailment against the retrieved chunk, or against what the system already stores about that user, catches the stable hallucination that is grounded in nothing. Tiering keeps the latency sane too. Run the 1.5ms consensus check on everything, then spend the expensive grounded check only on responses that score low or touch an irreversible action.
