### 1. Stale, Misattributed, or Late: Where Personal Memory Fails Before Generation
- URL: https://arxiv.org/abs/2610.10265 · 2026-10-07 · cs.CL/cs.AI
- Quote: "That score hides errors that arise before generation"
- Why: This is the Q2 answer in one paper: facts carry an optional key naming a mutable slot and a keyed-supersession rule (from temporal databases) atomically closes the old active fact at commit; a keyless store exposes a superseded value on 70.3 percent of prompts, a correctly keyed store eliminates stale exposure (Wilson upper bound 0.005). Key GRANULARITY is a two-sided law: coarse (entity, slot) keys merge distinct facts (recall drops to 0.500), fine (entity, slot, noun) keys score 1.000. Key assignment is the bottleneck, not retrieval: four LLM assigners hit key recall 0.980 to 0.996 but clean retrieval only 0.560 to 0.644, versus 0.781 for a lower-recall rule extractor, because false merges silently delete current values and missed merges leave stale ones active. Bonus nails for the estate's GPS-embed verdict: dense retrieval 0.836 does not beat participant-aware BM25 0.873 (PFM 0.877, TOST-equivalent), and lexical retrieval costs about 0.25 ms versus about 18 ms dense.
- Overlap: zero hits for the ID and title fragments across all nine prior sweep dirs, memory/, corpus/, catalog. The ask-given estate condition (162 of 400 knots sharing one label, lens/graph.md:25) is exactly their keyless-store failure mode at the graph layer.

Knot labels should be minted as (seat, wave, subject) composite keys at write time, not free-text labels, and supersession should close intervals at commit the way ledger rows are supposed to.

### 2. AMBER: Training Long-Horizon Web Agents through Append-Only Memory
- URL: https://arxiv.org/abs/2610.07118 · 2026-10-05 · cs.CL/cs.AI
- Quote: "a simple and scalable framework where an agent jointly learns to reason, act, and write free-form memory, while an append-only rule guarantees retention by construction."
- Why: The Q3 build case, measured. The update rule is the cheapest possible writer, C_{t+1} = C_t concat [m_t], and it beats overwrite-style memory (MemAgent) by 4.09 points average success at 9B (36.85 vs 32.76) and 2.05 at 27B, with reliability gains (5-of-5 solving 20.5 vs 15.7 percent) and error-recovery gains (invalid-action re-issues 1.29 vs 1.95 per event; 6-plus repeats in 3.3 vs 15.4 percent). The mechanism they document is exactly our amend-never-rewrite law's justification: overwrite agents lose corrective feedback from memory within about 4 steps and exhibit recursive-compression loss. Linear context growth is their stated open problem at much longer horizons.
- Overlap: zero hits for "AMBER" as a paper title (all "amber" grep hits are color-word noise in corpus/df_mine and training text) or the ID anywhere in prior sweeps, memory/, corpus/.
- Estate hook: this is the writer half of the LEDGER incident answer: an append-only writer is viable AND measurably better than rewrite-style memory, and it composes with lens/laws.md:33-34 (corrections append, never rewrite). Build the writer; the reader problem is item 3.
