## Banked items (8, strongest first; all NEW, all fetched and read this session)

### 1. PatchKV: Efficient KV Cache Recovery for Dynamically Edited LLM Contexts (2609.26219, 2026-08-18, Yang, Guo, He, Chen, Hu, Li)
ABS-ONLY (html timed out twice; caveat stands). The engine-side physics of the xAI prefix-break grammar: any edit to prior context invalidates downstream KV because "altered causal histories and rotary positions prevent exact reuse of their offloaded key-value (KV) states", and the two naive cures are both wrong ("indiscriminate reuse propagates stale states and full-precision restoration adds data movement"). PatchKV "decomposes adjacent context versions into an exact prefix, an updated span, and an aligned suffix" and recovers the suffix cheaply: "2.51-3.85x speedup in mean resume time-to-first-token over full suffix recomputation and a 1.26-2.06x speedup over CacheBlend" while "matching or exceeding CacheBlend's F1 score in six of nine settings". Estate fit (Q1/Q3): this is the measured, engine-level version of the grammar the estate holds from xAI's vendor docs (edit/remove/reorder breaks the shared prefix). It proves the break is not a vendor quirk but causal-history + RoPE-position arithmetic, and it prices the repair: partial recomputation of an aligned suffix at 2.5-3.9x cheaper than cold recompute. The deliberate-ask law (lens/laws.md:75-77, frozen cache-shared prefix) stays the right default; PatchKV is what a serving layer would do the day the estate mutates mid-session history anyway. NOTE for future dedup: a DIFFERENT paper named "PatchKV: Weight-Space Compensation of KV Cache" (2609.39329) was raw-fetched 10-03 (catalog line 1073132); same nickname, different paper, different arXiv ID.

### 2. Exact Memory-Time Optimization for Prefix-Cached Language Model Serving (2610.02766, 2026-10-02, Shivam Gupta)
ABS-ONLY (html timed out). The retention-timeout question nobody in our holdings answers: how long should a cached prefix block live? "We introduce Prefix-Certificate Retention (PCR), an exact finite-trace formulation for static, grouped, reset-on-access timeouts", solved exactly: "The resulting maximum-weight closure reduces to one minimum cut, with graph size linear in the number of block lookups and timeout choices." Validated by "chronological replay of 39,632 public Mooncake requests" plus exhaustive small-instance checks; result shape: "Heterogeneous retention improves several held-out memory-time tradeoffs, but finer training optimization does not uniformly improve transfer." Code public (github.com/shi1720/prefix-certificate-retention). Estate fit (Q1): the estate side of the frozen-prefix law is "keep the boot block byte-stable"; the serving side is "how long does the provider keep it". This is the first paper in the holdings that formalizes TTL choice instead of asserting LRU (When Fancy Eviction Fails, banked 09-28, found LRU near-optimal for eviction ORDER; this is retention TIME). Feeds the per-family cache grammar rows: providers with explicit TTL knobs (xAI, DeepSeek context cache) can be reasoned about with this formulation.

### 3. SmoothAgent: Efficient Long-Horizon LLM-Based Agent Serving with Lookahead Context Engineering (2607.00151, 2026-06-30, Pan, Wang, Hu, Chen, Guan, Zhou, Swanson, Ding)
Outside the 30-day preference window (banked for fit, age flagged). The harness-side mirror of PatchKV: if context transformations (compaction, folding, world_state injection) must happen, do them BEFORE the ask so the transformed KV is prebuilt: "The runtime proactively executes these transformations and prepares transformed KV caches in advance, enabling direct context replacement without blocking", via "a lookahead programming model that allows agent frameworks to express context transformations as asynchronous operations". Gains: "effectively eliminates transformation overhead and reduces TTFT by up to 11.9x." Estate fit (Q1): names the exact defect the ask's first question hunts (ask paths that mutate the frozen prefix between asks): any mutation serialized on the ask path both breaks the shared prefix AND pays transformation latency on the critical path; moving mutations off-path (precompute between asks, swap the prepared block in) is the fix class. Zero mentions anywhere in the mines despite three months of daily runs, because it predates the lane's window; claimed here for the question fit.

### 4. Dual-QK: Sharp Queries and Flat Keys for Prunable 2-bit KV Caches (2610.09827, 2026-10-07, Whang et al.)
The KV-quantization frontier moves from "rotate then quantize" to jointly shaping Q and K with NON-orthogonal transforms: "Dual-QK, which uses paired non-orthogonal query and key transforms" combining "partial key whitening with a query-aligned basis" for INT2, plus dynamic query-channel pruning that "concentrate[s] query energy". Numbers: "6.8x KV-cache compression and an estimated 8.3x reduction in KV read volume relative to unpruned BF16", "SGLang implementation achieves up to 3.75x the decoding throughput of unpruned BF16", long-context retrieval held at 128K, beating OSCAR on most tasks at 40 percent channel sparsity across four models. Estate fit: today's sibling quant lane (2026-10-08) did not take it; banked here from the KV side. Direct relevance to the BreadthKV byte-budget axis (lens/burns.md:73-74): Dual-QK spends the budget on precision-and-channel shape instead of token count; the estate's quantizer-organ A/B (four pinned choices) gains a candidate axis. CUDA/SGLang only: not a local steal, a grammar row.

### 5. Fractal KV-Cache Archives: Lossless Symbolic Storage with In-Place Retrieval (2607.07144, v1 2026-07-08, v2 2026-08-05, Vladimir Gusev)
Outside the 30-day window (banked for Q4 fit, age flagged). The ONLY KV-storage paper in this sweep's offload query that is CPU-reproducible: "We release all code; every number reproduces on a laptop CPU." Storage shape: after per-head residual vector quantization to codebook indices, the symbol stream is archived losslessly with "O(1) random access and O(1) amortized append"; "per-head residual vector quantization reduces the archived cache by 36-54x relative to an fp16 cache at a perplexity cost of 11-15%." Estate fit (Q4): against the non-steal verdict for GPU offload stacks on this box (below), this is the lone idea whose evaluation environment matches ours (CPU, no CUDA, no Vulkan dependency stated). Still research code, not llama.cpp-integrated; a pointer, not a port.

### 6. DySCo: Dynamic Sharding for Collaborative Edge-Cloud LLM Inference with Depth-Synchronized Batching (2610.08268, 2026-10-06, Xu, Maliakel, Brandic, Ilager)
Layer-wise split of one model across a weak edge box and a cloud, with the runtime that "keeps KV caches local" on the edge while depth-synchronized batching fixes the idle gaps heterogeneous split points create. "At an average concurrency of eight, DSB improves throughput by 275% over FIFO, 48% over exact-match batching, and 79% over round-robin interleaving." Estate fit: the local-sovereignty architecture question (what stays local when remote primes do the judgment) has a measured shape here: KV residency local, weights split by layer. Catalog has only the unprocessed daily stub (state/arxiv/2026-10-07/2610.08268v1.txt, 2,050 bytes); this bank adds the read. The estate's Hermes-dispatch pattern (local janitors, remote primes) is the organizational analog; this is the inference-stack analog.

### 7. SPIN: Shadow Predictive Indexer for Sparse Attention (2610.09025, 2026-10-06, Fu, Chang, Zhao et al.)
Sparse-attention serving spends its budget rescoring the whole cache every decode step; SPIN replaces the scan with a learned-from-history predictor: "SPIN uses lightweight, history-based prediction to identify important KV blocks, avoiding the need to score the full KV cache at every decoding step", yielding "up to 14.9%" output throughput and "13.2%" median inter-token latency in vLLM. Estate fit: not a local steal (vLLM stack); the grammar row is that the frontier has moved from eviction policies to predict-then-verify indexers, which is the same shape as the estate's probe-monitors finding (97-99 percent recall beats judge 9, lens/burns.md:96-97): cheap predictors guarding expensive verifiers.

### 8. A Self-Pruning Transformer: Extreme KV-Cache Compression with Universal Attention (2610.09051, 2026-10-06, Wertheimer, Shen, Gupta, Liu, Lim, Srivatsa, Ganti, Zhang, Wang)
The training-side extreme: an architecture "whose composite decay mechanism acts as a natural, adaptive pruning criterion, removing tokens that contribute least to attention computation", reaching "state-of-the-art 10x compression on natural language and synthetic task data, while improving downstream performance." Estate fit: requires end-to-end training ("highly expressive and end-to-end trainable architecture"), so a non-steal on this box; banked because it bounds the frontier: learned decay now BEATS unpruned baselines at 10x, which sets the ceiling any training-free eviction the estate reads about must be compared against.
