## The steal (the mechanism, not the link)

Windows ML 2.7.2021-experimental (NuGet package Microsoft.Windows.AI.MachineLearning) plus winml-cli 0.3.1 via pip ship an experimental llama.cpp integration: `WinMLServer.exe model.gguf` stands up an OpenAI-compatible local endpoint (the devblog's example points the OpenAI SDK at http://127.0.0.1:8080/v1), serving GGUF pulled straight from Hugging Face through task-specific APIs whose Text Generation API auto-selects the execution engine (llama.cpp for GGUF, ONNX runtime otherwise), across "GPUs, NPUs, and CPUs from AMD, Intel, NVIDIA, and Qualcomm" (all devblog claims verified by WebFetch this ask; verbatim: "Windows adds experimental llama.cpp support to Windows ML so you can run GGUF models locally through new task-specific APIs").

The steal is NOT the engine (llama.cpp underneath, a class the estate already holds four ways) and NOT weight quant (the sweep's own classification: "is tooling (WinML) and KV-side compression, not weight quant", sweep/quantization-compression-hn.md:56). The steal is the SERVING SHAPE: a vendor-maintained, OS-distributed serving arm with a near-zero config surface (one exe, one model path) that speaks the OpenAI-compatible protocol the estate's clients already use. That converts "try a different local serving stack on this Windows box" from a build-and-tune project into a base-url swap.

Concrete port seam, verified in the estate this ask: the janitor lane defaults to gemma:2b on host ollama (mag/afk_loop.py:104 `def _ollama_ask(prompt, model="gemma:2b", ...)`; mag/cache_identity.py:78 `OLLAMA = "http://127.0.0.1:11434"`), and models/registry.py:85-96 (`ollama_base_url()`) already normalizes base urls and strips a trailing `/v1` because the OpenAI-compatible chat client shares OLLAMA_HOST (comment at models/registry.py:93-96: registry callers use native /api endpoints and must never construct /v1/api/tags). So the A/B must ride the OpenAI-compatible client half against WinML's /v1/chat/completions, not the registry's native /api probes. Wiring, IF it ever happens, is a connection-string change, no new client code.
