## Research question verdicts

RQ1 (what the owed kv-cache provenance re-audit needs; does lmcache-src hold it). The re-audit needs an instrument that catches healthy-hit-rate-plus-wrong-bytes, and this pass found the reference failure plus a ready-made gate. The LMCache hybrid-gdn bug (item 1): disk-tier store/restore of hybrid Mamba/GDN models silently saved only 1 of N kernel pages of full-attention KV; Mamba groups restored fine so hit rates looked great (98%) while full-attention KV was ~96% zeros with no exception, and restores returned wrong continuations. Root cause: _SubpagedAttentionViewEdit only matched the old 5-dim KV layout. Detection protocol (steal directly): bury a unique key sentence mid-context, store, fully kill/restart engine and cache server, restore from disk tier only, then demand the key back; pass requires exact character-for-character key AND hit rate >= 97% AND wall time well below cold prefill (their runs: 12/12 passes at 97-99% hit, 2.6x-7.6x speedup). Complements the banked LLMTraceFX fail-closed five-source attestation (10-09). Does the shelf hold prior art: yes, literally. Our lmcache-src snapshot carries the vulnerable matcher at kv_cache_group_edits.py:331 (kv_cache.ndim == 5), so the re-audit's first target is a line we already own, and the exact-answer restart gate is the missing instrument this bug report supplies.

RQ2 (long-session stall class: stalled compaction marks, overflow_reason). Partly addressed, never at the stall level. What the door offers on compaction is quality and cost work (sibling-banked: FutureOS 83% vs OpenCode 47% vs Codex 38% recall on 178 questions; 150k-tokens-deep recall-beats-compaction 8x/4x/3x; swarmagent Final Handoff) plus one new structural mitigation: Gobstopper (item 2) replaces the built-in compactor with a local no-extra-model-call proxy (threshold 128k estimated tokens), removing the compaction-call stall surface by construction and keeping system prompt + first task + newest turns verbatim. But nothing I read this pass or in the sibling banks observes the specific mechanism behind stalled compaction marks or overflow_reason (the 10-02 sibling recorded the same negative on the FutureOS post). The stall class remains OWED on public doors; the hermes relay-hardening day's overflow_reason port is still ahead of published literature.

RQ3 (frozen-prefix law to multi-turn; what breaks it). The law extends and the breaker list is now well-populated. Sibling-banked evidence: GPT-6 typed miss reasons (tools_changed) and prewarming; Forge canonical-request + sorted skills + journaled system-message replay, 99.60%/99.48% hit dropping to 94.80% when one early instruction changes (~30k uncached vs ~2.5k); doug.sh key-sort 78% to 95%, divergence at token 12,622. New this pass, three prefix-hygiene mechanisms: Gobstopper (savings came almost entirely from cache reads: 68.7M vs 102.6M cached tokens, same solve rate); Context Diet (rule-based tool-output digests, 15% token cut same accuracy, but the README is silent on KV/prefix effects; replacing output text can churn downstream prefix, untested, flagged); Skillzero (hides always-on skill metadata from the prefix, mechanism only, no numbers). What breaks it, consolidated: early-position edits (one line = whole-prefix loss), map-order serialization of tool schemas, regenerated system messages on resume, compaction rewrites (new cache epoch), per-agent text before shared text, and tool-result mutation.

RQ4 (prefix-cache rate vs answer quality for sticky routing). The direct measured curve still does not exist in what I read: arXiv 2601.06007 (banked 09-28, re-read this sitting) measures cost 41-80% and TTFT 13-31% only, no quality metric. New this pass, two partial instruments: Fathom (item 3) builds exactly a quality-vs-cache-read Pareto at the bit level (per-query bit budgets over offloaded key channels by reverse water-filling, scored by attention error, RULER-style accuracy, and step agreement on coding-agent sessions; honest caveat: no benefit when the index fits in GPU memory); Gobstopper supplies one weak quality-held point (61/89 vs 60/89 solved, one trial per arm). Sticky routing itself rides on sibling-banked GPT-6 prompt_cache_key + Forge workspace-path hashing. Adoption guidance stands as: adopt sticky routing with a quality tripwire, because no published curve yet guarantees neutrality; Fathom's step-agreement design is the cheapest tripwire pattern to copy. Adjacent unbanked candidate: auriko.ai cache-aware routing savings report (June 2026, out of window, not deep-read).
