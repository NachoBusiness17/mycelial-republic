## Answers to the five research questions

**Q1 (fold/commit bottleneck: work lands on disk, never folded).** The frontier has now named the failure class. 2610.03140 (Tracking State Footprints) argues the estate's exact disease: orchestrators track control flow (task done) not data flow (state written), so "every agent completes its subtask successfully, yet the merged code fails" and concurrency anomalies "manifest even in simple coding tasks". Its fix family is portable to the gate: each ask declares a state footprint (read set + write set, including files and carrier dirs), fold/commit becomes a conflict-ordered stage, and fold validity is checkable: "A task's result remains valid if no item in its read set changed since the result was produced" (their section 6.4, incremental-view-maintenance logic). WorkflowOps (2610.07860) attacks the same disease from the history side: orchestration is "largely memoryless", so fold collaboration priors from past workflows into future DAG construction (transition matrix + on-demand agent creation). Already-held corroboration: the estate's own STRUCK-receipted 2610.00905 study (944 MAS issues) ranks Orchestration and Execution the top issue class and Optimize Workflow the predominant solution; my fulltext re-read this session confirms those rankings as the paper states them (the 10-03 strike was against a mis-worded claim, not the rankings).

**Q2 (EWMA backoff 2610.09037 vs the HOLD envelope).** 2610.09037 stays the only in-window paper modeling dispatcher-side cost-aware backoff (day-9 banked; today's "backoff + agent" query returned nothing newer, matching day-9's own finding of a near-empty lane). New complement: 2610.11542 shows the other half of the retry strategy. For deadlock-class stalls (not induced 429s), deterministic recovery beats model-steered retries outright: atomic context purge plus a canonical recovery message escaped 5/5 vs LLM-only steering 0/5, Fisher p = 0.008, same call budget, and "Cost is bounded in every arm by deterministic stop rules; the stack adds recovery at no extra model cost". Composition for the gate: EWMA width multiplier for induced-failure storms (the day-9 steal card 6), deterministic stop rules plus canonical-restart for stuck-loop children, width never cut mid-flight. Honest boundary: the negotiation domain is not provider rate limiting; the transfer is by analogy and the day-9 replay probe stays the gate it must pass.

**Q3 (warm-then-fan-out + sticky routing + frozen prefix, cold-seat cost).** KVCMAS (2609.34060) models the estate's exact fan-out shape: shared spine context plus agent-specific prefixes. Finding: "agent-specific prefixes change the KV cache generated for the same shared context, causing each agent to repeatedly prefill the growing context and construct a separate cache". The fix composes directly with warm-then-fan-out: keep the exact first-agent (warm spine) cache, chain compact low-rank corrections to role-prefixed children: 2.0x TTFT speedup, peak GPU memory down up to 3.7x, accuracy matched or improved. Sticky routing (day-9 AgentX) maximizes hits on the warm seat; KVCMAS prices and covers the fan-out seats. Cold-seat floor from TCA (2609.23790): "written to cache and read zero times costs more than not caching it at all, so in a fan-out graph where each node carries distinct context, naive caching raises cost" (their argument, explicitly not a measurement). Net: warm-then-fan-out composes with the frozen-prefix law only with shared-context reuse machinery; on cold seats the first-agent prefill is the floor, and cross-family cold seats are the already-banked HeteroFold (10-03).

**Q4 (planning-gate wiring, laws lens open q7).** Local state verified this run: mag/plan.py exists and is live, should_plan fires on ambiguity/scope/expense/irreversible keyword classes plus >400-char goals with a skip-list for small tasks (mag/plan.py:55-79), and plan_gate persists an auditable plan object (goal, scope in/out, success checks, seat, est_tokens, status) to memory/plans/ then anchors one priority-store question (mag/plan.py:180-203). So the wiring exists; what is missing is pricing. Outside evidence: REVOIR (2609.37588) makes clarify-or-act a value-of-information decision and validates the estate's INTJ one-question design: "when the assistant can receive cheap user corrections after acting, REVOIR naturally infers that asking questions is not always efficient", with 13-15% better preference satisfaction at 5x fewer questions, and a caution: vanilla reasoning agents "request fewer clarifications as reasoning effort increases". DATS (2609.13890) generalizes gating to topology: select the shape "maximising predicted success minus cost", beating always-hierarchical by 4.1 points at 40% of its cost. Verdict: gate-on-size/ambiguity/expense with auditable plan objects is now converging practice (REVOIR, DATS, plus 2024's Ask-before-Plan as the named prior art), and the estate's gap is not wiring but the cost-adjusted scoring and the cheap-correction escape hatch, both portable into plan.py without new machinery. STEPGATE (2610.07816) prices the ladder's escalate rung the same way: score each local action, escalate only challenging steps (82.7% task success at 30.8% escalation vs 67.3% local-only).

**Q5 (4-agent 2x total / 0.5x per agent economics).** Outside replication says the shape is task-and-width dependent, not a constant. DATS: "the advantage of hierarchical collaboration over a single agent grows from 2.4 points of pass@1 on the easiest third of problems to 21.1 points on the hardest third, while its token cost stays about ten times higher" (same progression on 400 math problems, 2.5 to 20.9 points). So width buys capability only on hard tasks; on easy ones it spends 10x for ~2 points. The already-held Mechanics of a Swarm receipt (2609.12748, syllabus arc) adds the sober check: across 510 reconstructed cohorts, no robust positive association between measured coordination and documented progress. TCA (2609.23790) hands the estate the instrument to re-run its own claim honestly: a two-pass, non-billable token count (~10ms per node, provider's own tokenizer) separating injected from generated tokens; its numbers (injection 13.6% of optimizer-actionable variable cost, rising to 27.6% at workflow depth six, uncached) say per-agent token cost is depth-dependent, so the 0.5x per agent figure needs the depth axis attached. Recommended protocol before the day-9 shape hardens into law: DATS's budget-matched comparison (equal-spend routing vs fixed shape) over the estate's own logged fan-outs.

## Banked items (8, strongest first; quotes verbatim from pages fetched this session)

1. **Tracking State Footprints: How Agents Can Transact** (https://arxiv.org/abs/2610.03140, 2026-10-02). Quote: "most of today's orchestrators track control flow, i.e., which task runs after which, but not data flow, i.e., which state each task reads and writes". Why: names and formalizes the estate's fold/commit bottleneck (control flow tracked, write sets not) and ships the state-footprint fix with a released artifact (github.com/delftdata/agenti-ai-guarantees).

2. **Learning How Much to Collaborate: Difficulty-Aware Topology Selection for Multi-Agent Code Generation** (https://arxiv.org/abs/2609.13890, 2026-09-12). Quote: "the advantage of hierarchical collaboration over a single agent grows from 2.4 points of pass@1 on the easiest third of problems to 21.1 points on the hardest third, while its token cost stays about ten times higher". Why: directly answers the width-dependence question (Q5) and supplies the cost-adjusted gate objective plus the budget-matched protocol (Q4) the estate's own claims should be re-run under.

3. **KVCMAS: Efficient KV cache Correction for Shared Context in Multi-Agent Systems** (https://arxiv.org/abs/2609.34060, 2026-09-28). Quote: "agent-specific prefixes change the KV cache generated for the same shared context, causing each agent to repeatedly prefill the growing context and construct a separate cache". Why: the missing serving-side half of warm-then-fan-out (Q3): exact first-agent cache plus chained low-rank corrections, 2.0x TTFT, 3.7x peak memory down.

4. **Constitutional Gating and Deterministic Recovery for Multi-Agent LLM Negotiation** (https://arxiv.org/abs/2610.11542, 2026-10-08). Quote: "LLM-only steering escapes 0 of 5 times while atomic purge plus a canonical strike escapes 5 of 5 (Fisher p = 0.008) at the same call budget". Why: the deadlock-class complement to EWMA backoff for the gate's retry strategy (Q2): deterministic stop rules bound every arm; recovery adds no model cost.

5. **Total Cost of Agency: Exact Attribution of Memory Injection Cost in Multi-Agent LLM Workflows** (https://arxiv.org/abs/2609.23790, 2026-09-20). Quote: "memory injection accounts for 13.6 percent of the variable cost a compile-time optimizer can act on, about 12 percent of the full billed cost". Why: the burns-ledger instrument (two-pass non-billable token attribution, ~10ms per node) and the depth-dependence numbers that say the estate's 0.5x per agent figure needs a depth axis (Q5).

6. **Rational Clarification by Assistive Agents via Value-of-Information Reasoning** (https://arxiv.org/abs/2609.37588, 2026-09-29). Quote: "when the assistant can receive cheap user corrections after acting, REVOIR naturally infers that asking questions is not always efficient". Why: prices the planning gate's one question by value-of-information including the ask-vs-act cost and the cheap-correction escape (Q4), validating the estate's ask-once INTJ design with measured numbers.

7. **WorkflowOps: Learning Agent Collaboration Priors for Multi-Agent Workflow Orchestration** (https://arxiv.org/abs/2610.07860, 2026-10-06, abstract-level read, disclosed). Quote: "orchestration layers remain largely memoryless: each new task is decomposed, assigned, and executed from scratch with no benefit from prior successful executions". Why: the mechanical version of fold discipline (Q1): priors learned from historical workflows guide future DAG construction; claims 80%+ reduction in LLM routing calls via embedding-first matching.

8. **Do I Need the Cloud? Uncertainty-Aware Step-Level Handoff for Small Language Model Agents** (https://arxiv.org/abs/2610.07816, 2026-10-06, abstract-level read, disclosed). Quote: "We propose STEPGATE, an uncertainty-aware handoff framework that scores each local SLM action and selectively escalates challenging steps to a stronger model". Why: the tier ladder's escalate rung priced: step-level uncertainty gating hits 82.7% success at 30.8% escalation vs 67.3% local-only.
