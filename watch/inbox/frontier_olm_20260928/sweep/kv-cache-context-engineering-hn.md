## Answers to the five research questions

RQ1, patterns beyond the ZCode playbook with hit rates: the playbook (corpus/steal/ZCODE_OPERATING_PLAYBOOK_20260925.md:10-14) verifies byte-identical ask keying for the amend-cache. The window adds four verified beyond it: (a) volatility ordering with tail-mounted mutable context (revefi: 90% spend cut, 99% cache reads; arXiv 2601.06007: dynamic-at-end strategy beats full-context caching, which can paradoxically increase latency); (b) deterministic serialization of tool schemas, because gateway-side map randomization alone broke 8% of turns and cost 78%-to-95% of caching when fixed (doug.sh); (c) measured provider numbers to cite, 41-80% cost and 13-31% TTFT across three providers on 500+ sessions (2601.06007); (d) per-agent cache-read metering, since uncached agents hid below top-spend agents (revefi). Hit rates now on file: 55%-to-95% (doug.sh), 99% (revefi), 80.2-92.4% under handoff-based context discipline (swarmagent), 0.964 fleet-measured (already held).

RQ2, structure-not-prose (memweave): the only direct measured result in the window is SlopShape, and it is adjacent, not direct: structural features alone detect AI text at 97.0 macro-F1 and survive model rewording (96.1), so structure demonstrably carries the durable signal channel. No published test of structure-vs-prose effect on attention fidelity or cache behavior surfaced. Replication experiment estate-side, using instruments that already exist: take the gemma:2b 20-prompt scut battery (the 60-inference, x3 census instrument from the abliterate-p1 baseline), render each prompt twice, prose-blob vs memlang-structured, byte-identical content otherwise; measure task success, refusal-shaped rate, and cached-token share via the provider meter; then re-run the same pair on the DeepSeek lane and diff cache-read ratios. Success criterion: structure wins or ties on task metrics while raising cached-token share; a tie with equal cache share honestly kills the attention-fidelity claim for serving purposes.

RQ3, KV quantization/offload for llama.cpp/Ollama-class 2B-8B: the loud results are design-time, not retrofittable (FP4 QAT KV at 890 B/token on a 552B MoE; DeepSeek thread and zartbot read), and nothing in the window shows a llama.cpp/Ollama KV-quant or offload win for small models; the sibling inference-efficiency bank reached the same verdict for tok/s on Windows. What the window does offer local serving: the doug.sh CPU-tier result (42k-token context restored in under half a second from /dev/shm vs 24s cold prefill) and the cross-session n-gram dynamic cache. Verdict: no janitor-model-choice change and no context-budget change is evidenced this window; the actionable local piece is prefix-warmth discipline plus optional /dev/shm tiering, both config-level, not weight-level.

RQ4, mechanism for KV/ram-cache drift, and the rib: the rib open question is at memory/rib/RIB_RAM_CACHE_STALE_SNAPSHOT_20260825.md (NOT "lens laws.md", a file that does not exist; memory/lenses/ holds only three JSON index files) and its cause is already closed there by the estate itself: `ram_cache.load_corpus` caches at module level and `republic_loop.py` S0-ram-cache never passes refresh, so every pass after the first serves a frozen snapshot; the mtime-fingerprint auto-invalidation fix is specified in that rib with reproduced proofs. The published literature independently confirms the same shape of cause on the KV side, three mechanisms, all measured: (1) prefix-contiguous matching means any mid-prefix byte mutation orphans everything after it, the doug.sh diverged-at-token-12,622 case; (2) capacity, not decay: 88k-token tool-loop working sets against finite blocks cause most recompute, and smarter eviction cannot fix capacity (agentic-kv-cache census); (3) silent key-order mutation by intermediate layers (gateway-reserialized tool schemas). So the cited, publishable cause to attach to the rib: caches in long agent sessions drift because something MUTATES the prefix (tool schemas, mid-prompt status text, one-shot snapshots without invalidation) or EXHAUSTS capacity; time-based "drift" was the null hypothesis everywhere it was measured (TTL byte-identical to LRU in every run).

RQ5, context-window engineering at 100k-plus turns: published practice converges on exactly the estate's shape: bounded structured handoffs at phase boundaries injected into an unchanged static prefix (swarmagent's ~350-token schema-validated handoffs, 80.2-92.4% cache hit, $9.97 for 7.89M prompt tokens), never compacting mid-run (compaction = cold miss plus information loss, 35-50s each), volatile state tail-mounted, and plans as typed machine state rather than prose. What transfers to the estate's compaction-amend loop: make the fold/receipt the handoff artifact (schema-validated, ~350-token class, digest-complete), keep amend-not-rewrite as the cache law it already is, and cite the magic.dev 51 TB figure as the reason compaction-amend beats native long context locally. What does not transfer: LTM-style architectures and 100M-token native windows (hardware math forbids it at desk scale).
