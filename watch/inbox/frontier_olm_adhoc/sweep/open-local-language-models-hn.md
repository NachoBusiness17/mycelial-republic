## Research-question answers

**RQ1 (1-8B agent loops on 24GB, measured tok/s):** Honest negative on the dense class: no new dense 1-8B agent-focused open model surfaced on HN since the 2026-10-01 fold. The post-fold movement is MoE-with-small-active (Kolibri, banked below: 3.46B active/token, tool calling, 10-03 release) plus decision-model variants (Ollama 0.35 nimble 9B / tev1 4B / tev1:0.8B, sibling-banked 10-07) and sub-1B automation (Cactus Needle, sibling-banked). Measured 24GB datapoint banked from the Sunk Cost thread: 57 t/s Qwen 3.8 on a single RTX 3090 at 156k context (commenter-run, not a benchmark harness). OWED: Kolibri local tok/s on 24GB-class VRAM (not in the article; needs a bench once GGUF/quants ship).

**RQ2 (Ollama runtime since the 2026-07-20 basics pack):** Three changes touch the gemma:2b + gemma4 janitor lane. (1) The 10-07 sibling sweep already banked v0.35 + /v1/systemone decision models and later v0.35.1/v0.40.0 + the b11475 Metal probability-collapse bug (watch/inbox/frontier_olm_2026-10-07/sweep/open-local-language-models-x.md, reddit.md; nothing new added here, deliberately not re-banked). (2) New below: the Mozilla benchmark showing all four local servers converge on the shared llama.cpp core (Ollama 0.34.0 within a few percent on prompt processing once weights fixed; config flags drive up to 63%), so the janitor lane's lever is flags, not engine churn. (3) New below: the Return piece on Ollama 0.12+ cloud-suffix proxying through localhost:11434 (OLLAMA_NO_CLOUD / disable_ollama_cloud exist), which is the app-side twin of the fold's llama.cpp serving-host confidentiality row. Windows behavior: MS shipped experimental llama.cpp/GGUF support into Windows ML (banked below).

**RQ3 (auth-free surfaces replacing walled old.reddit.com):** Probed live this session with curl: HuggingFace model pages return 200 and carry discussion counts inline (the GSQ-RCO card shows 7 discussions; model cards carry r/LocalLLaMA-grade quant detail, two sibling 10-09 banks came from exactly that surface); lobste.rs /newest.json returns 200 JSON but /search.json 400s ("Unpermitted query or form parameter"), so lobste.rs is usable only as newest.json + client-side filter; Algolia HN items API returns full comment trees (used for all thread reads). Vendor blogs (ollama.com/blog, blog.mozilla.ai, devblogs.microsoft.com, testingcatalog.com) all fetch clean. Recommended replacement lane: HF model cards + discussions primary, lobste.rs newest.json secondary, HN threads as the argument layer.

**RQ4 (AirLLM-style disk streaming vs sub-4-bit on 24GB):** Honest negative first: zero HN hits for AirLLM in the window (raw/hn_AirLLM.json: nbHits 0), and no 2026 head-to-head of disk-streaming vs pure sub-4-bit surfaced. Closest 2026 measurement banked below: GSQ-RCO runs Qwen3.8-Flash-Next 180B on 2x RTX 3090 with embeddings mmap'd on disk, KV cache in RAM, and a 3.5-bit non-uniform quant; with BF16 embeddings it scores 2.85 points ABOVE the base model on MMLU-Pro at 1.72% higher perplexity. That is evidence the hybrid (disk-streamed cold tensors + non-uniform sub-4-bit hot weights) need not cost quality; it is NOT an AirLLM comparison and the card states no tok/s. The estate's own 24GB bench remains OWED.
