## Schema decisions (mag_gwap_payload.v1)

The paper schema `{scene_id, intent_struct, report_struct, agreement_score, blocker_taboo_list, witness_clue_chain, verdict}` extended with: `schema`, `participants` ([{anon_id, role}], roles robber/cop/witness/blocker), `consent` (required bool, no default), `meter_credit` `{artifact_rarity, byte_backed, receipt_sha256}`, `replay_tape_ref` `{sha256 (64-hex), engine_version}` (required, no default), `signature` placeholder `{"scheme": "unsigned-v0", "signed_by": []}`, `created_utc` (required ISO-8601, regex-enforced), plus two v0 additions of our own: `taboo_violations` (what the blocker caught, so BLOCKED rows are self-explaining) and `collusion_fingerprint` `{suspected_collusion, compared_claims, evidence}`.

1. **Dicts over dataclasses.** Payloads ARE json rows; dicts keep the canonical round-trip one layer thin and the ledger row self-describing. `canonical()` (sorted keys, compact separators) is the only serialization, exactly the `wow_player` house pattern.
2. **meter_credit.receipt_sha256 hashes the payload BODY** (every field except meter_credit itself), computed before meter_credit attaches: non-self-referential, so the credit is provably earned by exactly these bytes even quoted outside the ledger. `byte_backed: true` because a payload only becomes real when a hash-chained row carries it.
3. **Role wiring is validated, not assumed:** intent author must be a declared robber, report author a declared cop, every clue witness a declared witness (typed `ROLE_WIRING` error). Blocker participants are optional (they author no claims).
4. **Determinism:** claim normalization (lowercase, whitespace-folded, qualifier defaulted to "") means identical semantics produce identical payload bytes; `created_utc` is an explicit argument, so same inputs always hash identically (tested byte-for-byte, including ledger file bytes across independent stores).

## Engine decisions

- **Agreement = min/max weighted Jaccard over canonicalized claim triples** (subject, verb, object, qualifier). Side A = robber claims at weight 1.0; side B = cop claims at 1.0 with witness clue claims max-folded in at 0.5. Equal weights reduce to plain Jaccard; a witness can lift a cop-missed claim to half credit but never above the cop's own claim. Duplicate triples inside a side collapse via max, so claim stuffing is worthless before scoring even runs. Score rounded to 4 decimals; empty union scores 0.0 (no evidence, no agreement).
- **Blocker:** top-5 most common words over a scene's prior claims, pure frequency, ties broken alphabetically ((-count, word) sort), no RNG. Token-level matching (`[a-z0-9]+` tokens): "vault" does not fire on "vaulted". No stoplist and no stemming in v0 (a stoplist would have kept function words like "the"/"by" out of demo taboo lists; recorded as v1 debt instead of papering over it).
- **Verdict ladder per spec:** BLOCKED (blocker precedence over any agreement) > score >= 0.6 VERIFIED_AGREE > >= 0.3 CHALLENGE > else DISPUTE. Band edges tested with exact fractions (3/5 = 0.6 inclusive edge, 2/5 = 0.4, 0/5 = 0.0).
- **Collusion fingerprint:** fires only when authors differ, both sides hold >= 2 claims (one claim carries no order information; without this guard every honest single-claim match would false-positive), and the canonical triple sequences are exactly equal. Shuffled order never fires. **v0 leaves the verdict ladder untouched when the fingerprint fires** (the mission's ladder is the spec); the signal travels as `suspected_collusion: true` plus a downgraded artifact rarity (`tainted` instead of `rare`).
- **Artifact rarity is deterministic from (verdict, collusion):** rare / tainted / uncommon / common / void. The product of the round is the rarity the fleet banks.
- **Ledger:** append-only JSONL `memory/runs/gwap/<session_id>.jsonl`, rows `{seq, ts_utc, payload, prev_sha256, row_sha256}`, genesis prev = 64 zeros, row hash over the row minus its own hash field, exactly the `mag/wow_player.py` house pattern. Construction fails closed on a chain that does not verify; `append()` refuses to extend anything it cannot verify first; `verify_chain()` re-reads the FILE, never cached rows. Tamper detection returns `(ok, first_bad_row)` with a 1-based row index and catches edits without rehash, row deletion, seq rewrites, and unparseable lines.

## What v1 owes

1. **Auto-downgrade:** suspected_collusion should demote VERIFIED_AGREE to a judge-owed CHALLENGE instead of only tainting the rarity; needs a probability-aware threshold (2-claim copies match honest order 1/2 of the time by chance; 3 claims 1/6).
2. **Blocker stoplist + stemming** so function words and plurals stop leaking into taboo lists (token-level "vault" vs "vaults" is already spoofable).
3. **Real signature scheme** replacing the unsigned-v0 placeholder (participant key digests, scheme per participant).
4. **Replay tape binding beyond a hash reference:** engine-side tape recording so `replay_tape_ref.sha256` is byte-backed by an actual tape, not just asserted by the caller.
5. **Semantic agreement layer** (free-text intent/report fields scored beyond exact triples) and edit-distance/timestamp collusion signals (the design doc names both; v0 covers order identity only).
6. **MUD/relay integration:** the dashboard MUD and the 8766 presence relay do not yet emit these payloads; v0 is the standalone engine + ledger the game will call into.
7. **Challenge/judge queue consumer** for CHALLENGE rows (a judge is owed at 0.3-0.6; nothing consumes the debt yet).

## v1 change that amends v0 design decision 2 (collusion auto-downgrade, debt 1)

v0 decision 2 left the verdict ladder untouched when the order fingerprint fired; v1 now demotes VERIFIED_AGREE to CHALLENGE when `suspected_collusion` is true. Rationale: v0's rarity-only discount let a copied round still carry the VERIFIED_AGREE verdict, which is the row's headline credit signal; a tainted rarity string is too soft a brake once downstream consumers filter on verdict. Judgment is owed before credit, so the verdict itself must say CHALLENGE. Mechanics: `decide_verdict(score, taboo_violations, suspected_collusion=False)` (third arg defaults False, so all v0 two-argument calls keep byte-identical behavior); BLOCKED precedence and the 0.3/0.6 band edges unchanged; `default_artifact_rarity` now taints the CHALLENGE band (tainted instead of uncommon) so a judge-owed row can never bank as a clean uncommon.

## Signature scheme (debt 3, real ed25519)

- `author_keypair(seed)`: deterministic keypair, private seed = sha256("mag_gwap_payload.v1:ed25519:" + SECRET seed). No RNG (house law); the seed is a secret from the operator keychain, never a public anon_id.
- `sign_payload(payload, author, private_hex)`: signed deep copy; signature block `{algo: "ed25519-v1", pubkey, sig, signed_by}` replaces the unsigned-v0 placeholder. Signs canonical(payload minus its own signature field), so claims, score, verdict AND meter_credit (with its build-time receipt) are all committed; meter_credit.receipt_sha256 keeps its v0 semantics (body as built) and the signature then commits to that receipt, jointly identifying every byte with no circularity. The signer must be a declared participant (same ROLE wiring law as the claims). Ed25519 determinism (RFC 8032) means re-signing identical bytes yields the identical signature (tested).
- `verify_signature(payload)`: the public offline check anyone can run against the pubkey riding in the row; never raises; False on wrong shape, unsigned-v0 rows, swapped keys, or any post-signing byte change anywhere (tamper test covers scene_id, a claim object, agreement_score, verdict, meter_credit.receipt_sha256, pubkey swap, mangled sig).
- Dependency law: v0's stdlib-only law is amended to "stdlib plus exactly one package, `cryptography`, used solely for ed25519"; `HAS_CRYPTO` gates absence (signers raise NO_CRYPTO, verifiers return False) and the signature tests are skipif-gated honestly (zero skips in this venv today).

## MUD connector (debt 6, mag/gwap_mud.py)

One concrete scene adapter, no mud.html changes. Event shape `{"player": {"id","x","y"}, "action": move|attack|kill, "target"}` maps closed-set to verbs moved / attacked / killed, positions quantized to integer tiles (deterministic triples; sub-tile jitter invisible). Replay shape is the relay presence JSON `{id, name, x, y, hp, max_hp, state}` (mud_relay `_register_seen` schema; the /mud/state spectator `age` key tolerated and dropped): `from_replay_line(line, prev)` returns (snapshot, claims) where claims come from deltas against the same player's previous snapshot, fixed order moved / lost hp / died / won; first sightings yield nothing; `struct_from_replay` threads prev per player id. Honest limit, documented in-module and in the demo: presence is authority-free by design, an hp drop names the loser never the attacker, so replay claims never say "attacked" (attacker attribution needs richer frames; that is v0 debt 5, semantic layer, still owed). End-to-end tests run events -> intent, replay -> report, `build_payload`, sign, `SessionLedger.append`, chain verify.
