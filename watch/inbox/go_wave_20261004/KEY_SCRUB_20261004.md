# KEY SCRUB 2026-10-04: OpenRouter live key in elder lane surfaces (caught PRE-COMMIT)

Plain language first: one live OpenRouter key from .env leaked into four local
files through an error message. It never reached git, never left the machine,
and is now scrubbed everywhere plus fixed at the source. Rotation is NOT
required on current evidence, but the operator should eyeball the OpenRouter
usage page for the window 2026-10-03 evening to 2026-10-04 09:20Z as hygiene.

## WHERE-exactly map

The key (prefix sk-or-v1-41679b3f, 74 chars, byte-exact match to a live .env
value) appeared in exactly 4 files, 1 occurrence each, all in the elder lane
surfaces and their dashboard renders:

1. queue/lanes/elder/trail.jsonl (the origin write)
2. queue/lanes/elder/surface.md
3. dashboard/static/trails/elder.jsonl (rendered copy)
4. dashboard/static/lanes/elder.md (rendered copy)

Mechanism: mag/lane_runner.py line 853 wrote a CYCLE_FAIL event whose detail
was the raw exception body "Invalid header value b'Bearer sk-or-v1-...'" - the
header value echoed verbatim into the trail.

## Git exposure: NONE

`git grep sk-or-v1-41679b3f HEAD` reads zero; the leak entered the working
tree AFTER commit a7ca49be1 and was caught by tools/prepush_credential_shape.py
(lane 10 of go_wave_20261004) on its first live run before any commit carried
it. The second env key (prefix sk-or-v1-6be0272f) appears nowhere outside .env.

## What was done

1. Scrubbed all 4 occurrences to sk-or-v1-41679b3f[REDACTED] (prefix kept for
   forensics). Verified: repo-wide grep for the live value reads zero files.
2. Fixed at source: mag/lane_runner.py _trail() now runs every detail through
   _scrub_credentials() (sk-/xai-/AIza/gsk_/Bearer shapes redacted, 12-char
   prefix preserved) - the chokepoint all lane events flow through, so every
   lane is covered, not just elder.
3. Regression tests: tests/test_lane_runner_scrub.py, 4 passed in 1.01s
   (instrument: pytest -q -p no:cacheprovider).
