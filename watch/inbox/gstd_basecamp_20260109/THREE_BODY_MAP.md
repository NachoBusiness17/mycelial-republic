## The filter reading

A 5-node DePIN with a settlement rail is a measurement instrument before it is a market. What it FILTERS for a harness:
- WORK QUALITY via settlement: a task pays only on delivery (POST /api/v1/tasks/complete, BUILD sect 1); vacuous work earns nothing while the ledgers already price the difference (day-1: $20.53 of $29.91 vacuous, FOLD).
- NODE TRUST via receipts: the census separates earners from ghosts - the Pi (288 tasks, rep 37) vs localhost-node (dark ~26d) vs a wallet-less unknown node (PROBE2 sect 1); trust is observable bytes, not assertions.
- DEMAND SIGNALS via task mix: the census converts "what should we build" into bytes - the net pays for thin local inference today and zero fat shapes (PROBE2 sect 4-5); it already filtered once tonight: the route-table join read 0 of 15 routable shapes served.
What it CANNOT filter:
- HYPE: node counts and gstd_earned totals say nothing about utility - a wallet-less node with 0 everything rides the same API (PROBE2 sect 1).
- COLD-START: 5 nodes cannot tell us whether the installer thesis converts; the demand leg stays an assumption until probes (b)/(c) run (DIST, demand-side proof owed).
- INTENT: settlement proves delivery, not judgment - no node serves a fat shape, so quality-of-judgment stays our router/arena lane (PROBE2 sect 4).
