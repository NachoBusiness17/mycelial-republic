**THE MECHANISM**  
A **Schema‑Bound Extraction Engine (SBEE)** that runs as a tiny, self‑contained Python service:

```python
#!/usr/bin/env python3
import sys, json, hashlib, dataclasses
from typing import Dict, Any

# 1. Load economic schema (JSON Schema) from stdin
schema = json.load(sys.stdin)

# 2. Define extraction function per schema
def extract(data: Dict[str, Any]) -> Dict[str, Any]:
    out = {}
    for field, spec in schema.get("properties", {}).items():
        if "extract" in spec:
            out[field] = spec["extract"](data)  # user‑provided extractors
        else:
            # default: direct copy if present
            if field in data:
                out[field] = data[field]
    return out

# 3. Bounded size guard: compute max size from schema
max_size = sum(v.get("max_length", 0) for v in schema.get("properties", {}).values())
# 4. Main pipeline
def run(input_json: str) -> str:
    data = json.loads(input_json)
    result = extract(data)

    # Ensure no extra fields
    allowed = set(schema.get("properties", {}).keys())
    if not set(result.keys()).issubset(allowed):
        raise ValueError("Output contains non‑schema field")

    # Enforce size bound
    serialized = json.dumps(result, separators=(",", ":"))
    if len(serialized.encode("utf-8")) > max_size:
        raise ValueError("Output exceeds size bound")

    return serialized

if __name__ == "__main__":
    try:
        inp = sys.stdin.read()
        print(run(inp))
    except Exception as e:
        sys.exit(f\"ERROR: {e}\")
```

- The script takes a JSON‑Schema describing allowed economic fields (each may include an `extract` function reference). It reads JSON input from stdin, applies the extractors, and writes JSON output that conforms *only* to the schema.  
- No external dependencies, no logging, no optional fields – the output is strictly bounded and verifiable.  
- The script can be placed in a seat’s entry point (e.g., `/usr/local/bin/ntpepe-simulator`) and invoked with standard I/O.

**WHY IT MATTERS**  
It guarantees deterministic, schema‑only economic extraction without leakage or size overruns, turning an opaque data‑processing pipeline into a provably correct, auditable component.
