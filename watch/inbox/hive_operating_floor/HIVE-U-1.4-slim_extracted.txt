Hive workshop sourcebook
U-1.4-slim · 17 September 2026 · Tokens only · No profile folder · No host tree chrome · No liturgy
 This book rebuilds the shop that puts one named job on disk and brings back a receipt. It does not rebuild a church, a
 court, or a second operating system.
A local globe board was one worked example. Do not treat that example as the workshop.

1. What the workshop is
A split bench.
Research stays in chat. Lead is the clerk on the host PC. Build is the bench.
They pass one job through two files. The notes file and the work tree stay pickup-ready so the next sitting can continue without
git.
Output of the shop is whatever the operator named. The shop does not care which domain it is in. It cares that one job lands on
disk and comes back with a receipt.

Does not

Edit the host PC. Dump notes onto Build.
Lead
Write the out-box. Watch the in-box. Pass the brief.
Invent the product. Mix two lanes.
Build
Do the job. Write the tree. Reply with a receipt.
Pull extra scope. Put secrets in a share zip.
Lead is a clerk, not an architect. Build is a bench, not a product manager. Research is a mouth and a checklist, not a second
disk.
2. House rules
1. This lane does not need git. Pickup is the folder, NOTES.md, and the two handoff files.
2. The bot writes on the host PC. A cloud workspace is not that PC.
3. One named lane per sitting. Do not mix trees.
4. One job per write. Last line is stop.
5. Missing data stays blank. Do not invent rows to look finished.
6. Keys stay on the box and out of zips.
7. Skills and briefs use tokens. Never print an expanded profile folder or host tree chrome.
8. Call Lead only when asked — talk to Lead, file bus, wake the box, send Build a job.
9. Software does not mark a claim proven. A person opens the file.
10. Do not delete existing skill folders. Asleep is fine. Recreating absorbed names is not the job.
11. Wake extra desks only when the job names their problem.

4. How a tool gets made
1. Operator names the next cut in one sentence and names the lane.
2. Research finds Lead by name search. Do not create another Lead.
3. Send Lead one async note — append this job, then watch the in-box.
4. Lead writes the dated block and reports heading + file time.
5. Build answers accepted <id> or blocked <id> first.
6. Build lists what changed, token path, what failed, stop.
7. Research tells the operator. Operator opens the artifact.
8. If Lead stops mid-write, check the heading before sending a second job.
9. If the operator is only talking, leave Lead alone.
10. Update NOTES.md with the job id, path, and blanks. Then stop.

# File-bus
On command only.
Out-box: `%USERPROFILE%\.grok\handoff\LEAD-TO-BUILD.md`
In-box: `%USERPROFILE%\.grok\handoff\BUILD-TO-LEAD.md`
Tree: `%HIVE_ROOT%\work\<lane>`
Notes: `%HIVE_ROOT%\work\<lane>\NOTES.md`
Find Lead by name search. Do not create Lead.
Send one async job block. Watch the in-box.
Appending is not done.
Mid-write: check heading and time. Do not double-send.
Out-box shape:
```
## YYYY-MM-DD HH:MM ET short-name
id: JOB-YYYYMMDD-HHMM
who: Lead
lane: <lane>
job: <one sentence>
tree: %HIVE_ROOT%\work\<lane>
stop
```
In-box shape:
```
id: JOB-YYYYMMDD-HHMM
accepted: yes | blocked
who: Build
lane: <lane>
what: <what changed>
path: <token path>
failed: <list or none>
stop
```
Off switch: if the operator is only talking, do not ping Lead.
