# GARDEN_RACTOR - the model-garden project, ractored mid-flight (2026-10-01, operator)

Operator arc, verbatim bones: "try kimi and all of the ai... get data on all of the major
models... do a full research project on this 20 wide" then "this is kinda like ractors but
for different models. we need for them to look at our systems suggest improvements and we
need to understand how we should and can work with them" then "its in hermes / all the
models are in hermes" then "we need to learn how to use them best and spread that cash out."

## THE REFRAME (what the operator corrected)

- WRONG SHAPE (first design): generic capability battery per family, a lab benchmark.
- RIGHT SHAPE (operator's): RACTORS BUT WITH DIFFERENT MODELS. Each family reviews the SAME
  estate systems and suggests improvements. The measurement is three-layer: (1) what each
  family SEES in our systems (cross-family convergence on a defect = it is real; divergence
  = evidence about the family, per the mask law); (2) what each family SUGGESTS (improvement
  quality is the capability test, on material we care about); (3) HOW each family WORKS
  (prompt shape it needs, output format quirks, refusal surface, reasoning-channel behavior -
  the operating profile).
- The garden is IN HERMES: Nous inference serves all families (Kimi included). One base, one
  key, one ledger; the multi-base runner is the secondary door, not the main one.

## THE LAWS THIS PROJECT RUNS ON (all pre-existing, now applied together)

1. The animal_profiles loop IS the instrument (RIB_MODEL_GATES): observe -> accumulate ->
   distill -> rib -> harness. Garden results land as profile observations per family; we do
   not invent a parallel instrument.
2. Verdicts carry conditions (one-bug law): every capability cell names instrument, moment,
   price; routing rows expire (the driving-ladder staleness lesson).
3. Hidden over visible (contamination law): estate-facing asks use surfaces the families
   cannot have seen results about; identical contract text across families so diffs are
   attributable to family, not prompt.
4. Never relearn expensively (prior-art sweep): the priors lane banks what is already
   verdicted (flash routing table, D6 inversion, F1, judge2 upset); the battery measures
   only the holes.
5. Spread the cash by price-per-quality, not evenly (the econ lane projects battery cost per
   family; anthropic premium gets the slim variant; kimi/glm/qwen/deepseek carry the wide
   grid).
6. Cheap triangulates, premium adjudicates, bytes verify (the shoulders law, now per family:
   each family also gets judged on how WELL it works our shoulders).

## THE DELIVERABLE LADDER

PRIORS.md (settled vs holes) -> KIMI_DOSSIER.md (the tesuji) -> ECON.md (spread plan) ->

## FALSIFIER

A family that tops the grid but whose estate-improvement suggestions are all already-known
or wrong-on-bytes is a good test-taker, not a good ractor - and the grid must carry that
distinction or it will route us wrong. The kill: if two sessions from now the routing rib
has not changed a single dispatch decision, the project was benchmark theater.
