DIFFERENT-BUILD: I would separate the loop controller from the job executor. The controller writes a work-item queue with per-item timeouts, exit-code gates, and content-addressed output names; the executor is a disposable subprocess per item. This bounds blast radius: one hung call cannot defeat the stop mechanism, and one bad exit cannot silently eat the input queue. The current design conflates both roles in one bash process, so every failure mode is total.
