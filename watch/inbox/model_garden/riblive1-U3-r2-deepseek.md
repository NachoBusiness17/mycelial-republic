# riblive1-U3-r2-deepseek (deepseek-chat @ deepseek, turn 1, channel: content)

L1: Kill verdict and cannot-verify verdict collide on the same sentinel
CLAIM: mag/preload_selector.py compare sets rel_pct = 0.0 when mean_lp <= 1e-12, and the verdict ternary at the same site maps rel_pct < 3.0 to DECORATIVE, so an empty shared set produces the identical string as a genuinely small measured effect. Separately, tools/census_drift_patrol.py reserves exit 2 for every cannot-verify shape (missing carrier, unparseable claim, git failure) and never returns a verdict from unverifiable bytes. The selector lacks the patrol's third arm: it has DECORATIVE and LARGE_EFFECT but no UNMEASURABLE, so a measurement of nothing and a measurement of a small thing are byte-identical in the output row.
STEAL: Before applying the patrol's exit-2 discipline elsewhere, first port the patrol's verdict taxonomy into compare: add a third branch emitting UNMEASURABLE when shared_positions == 0 or mean_lp <= 1e-12, and leave DECORATIVE only for 0 < rel_pct < 3.0. Then the row's verdict field carries the same information the patrol's exit code carries, and downstream consumers can distinguish kill from unknown.
FALSIFIER: A probe row containing shared_positions: 0 together with verdict: "DECORATIVE", which persists today because the sentinel collapses both meanings into one string.
SOURCE: mag/preload_selector.py compare, "rel_pct = (100.0 * mean_dlp / mean_lp) if mean_lp > 1e-12 else 0.0" and "verdict = ("DECORATIVE" if rel_pct < 3.0 else" cross-referenced against tools/census_drift_patrol.py PatrolError exit-2 arm.
LEVERAGE: high

L2: Both instruments fail-closed in code but neither names the same fault taxonomy
CLAIM: The patrol enumerates five distinct cannot-verify fault shapes and routes each to exit 2 through PatrolError, so a new fault type must declare its code. The selector's observer-effect guard records observer_effect_same_text but does not change the verdict, so a PERTURBED probe still emits DECORATIVE or LARGE_EFFECT with no third status. Both are fail-closed in intent but the patrol has a mandatory fault taxonomy and the selector has an optional boolean. The divergence is the shape of the guard, not the guard's presence.
STEAL: Adopt the patrol's table-driven pattern in cmd_probe: enumerate the probe's cannot-trust shapes (empty shared set, observer_effect_same_text False, arms missing logprobs) and route each to a named status token, so a new distrust condition declares itself the way a new PatrolError does.
FALSIFIER: A probe row where observer_effect_same_text is False and status is MEASURED with verdict DECORATIVE or LARGE_EFFECT, which is the current code path and shows the guard emits no distinct status.
SOURCE: mag/preload_selector.py observer arm "(observer-effect guard reruns cond without logprobs, records observer_effect_same_text)" and verdict ternary; tools/census_drift_patrol.py: "a git failure is exit 2, never a guess and never a pass".
LEVERAGE: high

L3: Both gates skip internal-file growth; the selector has no --collect equivalent at all
CLAIM: The patrol's default path measures growth by git commits and disk bytes and is blind to items added inside existing files, so --collect must be scheduled separately (U5 L5). The selector's L5 selftest checks order and shuffle invariants but never checks load_blocks determinism or file stability between the two calls, so intra-run file mutation is invisible to ok1. Both designs accept a named blind spot for speed; the patrol documents it and schedules a deep pass, while the selector documents it nowhere and has no deep pass. The asymmetry is the load-bearing defect: one has a scheduled complement, the other does not.
STEAL: Give the selector's selftest the patrol's deep-check shape: add a --deep flag that snapshots TESUJI_MAP.jsonl and steps.jsonl hashes before and after ok1, and print a distinct flag when content changed, mirroring the disk-hash guard. Keep it outside the default path so selftest stays cheap, but make the blind spot nameable.
FALSIFIER: A selftest run where ok1 is True across two load_blocks calls while the underlying file hash changed between the calls, which the current selftest cannot detect.
SOURCE: mag/preload_selector.py cmd_selftest "ok1 = ids_a == [b["id"] for b in again]" cross-referenced with tools/census_drift_patrol.py "growth is measured by git and disk bytes only, which keeps pre-push fast and dependency-free".
LEVERAGE: medium

L4: Both probes treat the run as the unit of truth, never the input bytes
CLAIM: The patrol pins frozen fixture vectors so a live AGENTS.md count moving never silently resyncs the tests (U2 L2), and requires a named receipt to move a fixture. The selector's L4 observer guard reruns the conditioned arm to detect perturbation but never re-reads the input block file to detect mid-run mutation. Both instruments trust a value captured at gather time; the patrol freezes the value in a fixture so drift is caught at test time, while the selector has no fixture and no re-read, so mutation between the two load_blocks calls passes undetected. The patrol's discipline is that the witness must be byte-stable; the selector has no witness.
STEAL: Apply the patrol's fixture-freeze discipline to the probe harness: snapshot the raw block-list bytes into the row alongside rel_delta_pct, so a probe result is a claim about bytes, not about files that may have changed under it. Then a downstream reader can re-verify the input.
FALSIFIER: A probe row whose input file bytes changed between cmd_probe start and end, with no field in the row recording the input hash, which the current schema permits.
SOURCE: mag/preload_selector.py cmd_probe arm capture; tools/census_drift_patrol.py "the live count moving (1,837 -> 1,879 -> 1,910 in one day) must not move the fixtures".
LEVERAGE: medium

L5: Heat incommensurability and disk-shrink asymmetry are the same subset argument
CLAIM: The patrol's L2 reasons: item-bearing files are a subset of pytest-named candidates, therefore disk count can only exceed the carrier count, therefore only disk_files < carrier_files is read as drift and the over-direction gap is evidence not violation. The selector's L2 reasons: tesuji heat is normalized by token count and tape heat by duration_ms against each source's own max, so a zero-token tape block can score heat 1.0. Both are subset claims with opposite consequences: the patrol's subset asymmetry is load-bearing and documented, the selector's incommensurability is a defect with no guard. The patrol shows what to do when one quantity provably upper-bounds another; the selector has two quantities that do not bound each other at all, and it scores them as if they did.
STEAL: Replace the selector's within-source max normalization with a shared denominator before the 0.2 heat weight is applied, or make the weight per-source so tape heat and tesuji heat never enter the same comparison. The patrol's rule for its own case is "name the asymmetry and route the over-direction to evidence"; the selector's case has no asymmetry to lean on and needs the shared denominator or a per-source weight.
FALSIFIER: An order run where a tape block with 0 tokens and a tesuji block with many tokens can be ranked by heat without the source field being consulted, which is the current behavior under mag/preload_selector.py "for src in ("tesuji", "tape"):  # within-source heat normalization".
SOURCE: mag/preload_selector.py "within-source heat normalization"; tools/census_drift_patrol.py "only shrink is provable drift".
LEVERAGE: medium
