DEFECT 1: `record_call` appends to JSONL while holding `_LOCK`, so the lock covers blocking disk I/O and serializes every concurrent caller (wave threads in `_dogfood` and any multithreaded probe) at file-write granularity, turning telemetry into a fleet-wide bottleneck. | EVIDENCE: mag/flight_recorder.py:148 (the `with _LOCK: with open(...) as fh: fh.write(...)` block inside `_emit`) | FIX: move JSON serialization + `os.makedirs` outside the lock and keep only the `open`/`write`/`close` under `_LOCK` (or swap to a `queue.Queue` + single writer thread).

DEFECT 2: `_utcnow` builds ISO timestamps by strftime str concatenation; the `since` filter in `summarize` then does lexicographic string comparison `str(r.get("ts","")) >= since`, which is correct only while ts is millisecond-fixed and month/day are zero padded (they are here), but the same filter silently drops every row when `since` is a bare year like `"2026"` because `"2026-..." >= "2026"` is true by prefix, while `since="2026-9"` (unpadded month, a plausible caller input given the docstring's `"2026-09-03T23"` example) drops all September rows since `"2026-09" < "2026-9"`. | EVIDENCE: mag/flight_recorder.py:270 (the `rows = [r for r in rows if str(r.get("ts", "")) >= since]` line in `summarize`) | FIX: parse `since` with `datetime.fromisoformat` after normalizing `Z` to `+00:00`, and compare parsed datetimes instead of raw strings.

DEFECT 3: `_interpret` treats any dict without an `error` key as `status="ok"`, so a wrapped function that returns a vendor body containing top-level `"code": 1302` or `{"message": "...rate limited..."}` without the `error` wrapper is recorded as ok, polluting p50/p95 and ok-rate which the doctrine re-fit consumes. | EVIDENCE: mag/flight_recorder.py:112 (the `err = result.get("error")` line; only that key flips status) | FIX: also treat a dict with truthy `result.get("code")` outside 2xx, or truthy top-level `result.get("message")` combined with missing `choices`/`data`, as an error, and pull `error_code` from `result.get("code")`.

DEAD-CODE: `_pctl` is never called with a `q` other than 0.50 and 0.95, and `_agg` never reads `cache_miss_tok`, so the deepseek-specific `cache_miss_tok` field written on every `_emit` row (mag/flight_recorder.py:200, 210) is dead output: no reader in this file consumes it. | EVIDENCE: mag/flight_recorder.py:170 (the `"cache_miss_tok": cache_miss_tok` key in the success `_emit` dict) through mag/flight_recorder.py:280 (end of `summarize`, no `cache_miss_tok` reference).

ONE-SITTING FIX: shrink the `_LOCK` critical section in `_emit` so concurrent burst probes do not serialize on `json.dumps` and `makedirs`, since `_emit` is the hot path for every wrapped call across the whole fleet. | EVIDENCE: mag/flight_recorder.py:145 through mag/flight_recorder.py:152 (the `line = json.dumps(...)` line sits inside the `try` and the `with _LOCK:` opens immediately after, so everything from `os.makedirs` through `fh.write` is under the lock in the current code; only `fh.write(line + "\n")` needs it).
