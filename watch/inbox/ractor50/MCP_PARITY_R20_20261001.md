## Parity check design (3 sentences)

Each transport (host stdio, gateway POST /mcp with the gateway's own
api_key() door, docker TCP bridge) gets a real JSON-RPC initialize +
tools/list for the profile it actually serves (self-declared via
_meta.mag.profile), and is compared against a live gated stdio probe of the
current tree on the tool-name set plus a content digest (name + description +
inputSchema, _meta excluded); a fourth stanza compares the mag-mcp container
image digest against the current mag-sovereign:local tag, which is the exact
R2.0 defect class (image rebuilt, container never recreated). Pin-gate
withholds (declared in tree, withheld by the drift alarm) are named per
transport and verdict-neutral while host and transport withhold the same
names; name/digest divergence, a wrong served profile, or a stale image is
exit 1 fail loud with counts and missing/extra names. A down transport is a
named SKIP that never flips the verdict (exit 0 still possible), all-down
with no comparable signal is exit 2 CANNOT-VERIFY, so the check runs on dark
boxes and says so.
