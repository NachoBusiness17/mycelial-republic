## THE STRUCTURAL REFUSAL (the device this version performs)

The usual duel is assertion versus denial. Denial is a trap: "there were no
clients" is itself an unfalsifiable line unless it names the instrument that
would flip it. So this version refuses at the grammar level: the Tiller has
exactly two legal moves, STAMP (a dated, instrumented fact from the spine)
and DEMAND (name the paper that would change the stamp). She never asserts a
negative about the world. Every Controller myth is answered by naming its
falsifying instrument, not by denying it. The unfalsifiable line does not get
argued with; it gets made structurally inexpressible in the Tiller's voice.
The half-step sharp is then inevitable: the room hears the demand go
unanswered, which is the point.

when two different lenses reject it for the same reason. Nobody defined what
happens when a line is rejected by every lens for pairwise-different

mtime (instrument 1) and authorship (instrument 2) disagreed, and the cure

:89-93, with the reasoning registered at state/CURRENT.md:74-89 (machinery
pages excluded from the mtime crown; their mtime moves on automation cadence,
not window authorship). The gauntlet needs the same clause. Proposal for the
merge receipt: class every rejection into a small fixed set (fabrication-risk,

same-class quorum of two kills; a line rejected across classes survives only
if it passes citation_lint --files at merge time and carries its
performed-quotation label in the receipt. The class table is the
adjudicator.

findstr.exe receives the switches through MSYS path conversion, which

`Tiller` as a file to open, failed, and because `2>nul` inside MSYS bash
redirects stderr into a REAL FILE named `nul` (not the Windows NUL device),
the errors vanished and exit 1 zero-hits looked exactly like a genuine
empty census. The stray nul file was removed this ask (rm -f nul; git
status clean). Sibling corroboration that this invocation class pollutes
the tree: accuracy.md:49-50 already carried "nul-protected dirs were
skipped on access errors".
