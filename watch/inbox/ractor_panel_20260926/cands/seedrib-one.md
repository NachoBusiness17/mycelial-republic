# seedrib / candidate one: SEED-RIB as a generative directory (seed_rib.v1)

## Approach

The merge is already three-quarters landed; the missing piece is the DIRECTORY itself. The estate holds: format v0 as a single JSON (watch/inbox/SEED_RIB_FORMAT_v0_20260926.md, B2-180; generator tools/seed_rib.py:1-188), a real filed seed (watch/inbox/SEED_RIB_CURRENT_20260926.json, 42,727 B, 13 entries) served cold over MCP with a 10/10 cold join (B2-181), a handoff-kernel table of contents with byte caps (watch/inbox/SEED_RIB_HANDOFF_KERNEL_20260926.md, B2-300), an external steal dig (B2-153: the Nix closure is the strongest steal, "a small text derivation describes the whole buildable world"), and the operator's public pack seed-3.2.0.zip (53 files, 229,749 B uncompressed; hash E9F4603A4484DAFB3D79103AEF63C678774EC508F9CD573677E91F83BC78F87E matches its watch/inbox/INDEX.json row, verified this session) with successor seed-3.3.0.zip (57 files, 236,383 B, hash 015ACFA0C5903F6F67305A188BE2C830CAD098A906678FBA009069B0AA8EAADA, also row-verified).

Proposal: evolve seed_rib.v0's single JSON into `seed-rib/`, a generative directory of ~33 files on five layers (boot kernel / method extracts / generators / state snapshots / pointer seals plus a join protocol), schema `seed_rib.v1`, hard budget 102,400 B. "Generative" means each file either carries sealed bytes, IS a generator that regenerates a fleet surface from the directory alone, or IS a pointer manifest that hash-seals files the directory deliberately does not carry. The fleet-proper is ~4,000 files under 0.1 GB (watch/inbox/TWO_MACHINE_SYNC_20260919.md:9, THE MAP at :45); bytes for all of them can never fit under 100KB, so the directory carries the DERIVATION, never the mass. Every named file falls in exactly one of three declared classes, and the manifest names the class:

1. INLINE: sealed bytes in the directory (boot laws, law corpus, DNA, method extracts, generators).
2. GENERATED: produced by a generator in the directory from directory contents alone (repo-root AGENTS.md from kernel/agents.md; docs/DNA.md from kernel/dna.md; memory/law/* from kernel/law/*; the estate skeleton from gen/scaffold.py; MANIFEST.sha256 itself from gen/seed_rib.py build).
3. POINTER: declared underivable-from-directory; fetched from a NAMED source (git clone at sealed commit, Drive mirror, ESSENTIALS_PACK tarball, seed-3.3.0.zip) and hash-checked against the seal; if unfetchable it is reported UNRESOLVED by name and stubbed, never invented (the v0 law at watch/inbox/SEED_RIB_FORMAT_v0_20260926.md:71-76).

The cold-seat floor, stated honestly: from the directory ALONE a rebuilder gets a working cold seat (boot kernel + 9 law files + registry + DNA + method + skeleton + generators + join protocol, ~29.7 KB rebuilt, mechanism verified live this session: `tools/seed_rib.py verify --seed watch/inbox/SEED_RIB_CURRENT_20260926.json --into <tmp>` with no source printed "inline 12 hash-matched, pointers 0 source-checked / 1 UNRESOLVED (stubbed, named)" and rebuilt 13 files / 29,715 B at exit 0). The full 4,000-file fleet additionally needs one fetch from a named source, verified against the git tree seals. The directory never claims to derive pointer-class bytes, so it never names a file it cannot deliver under its declared class.

Numbering debt named up front: the card label "B2-150..153" collides with landed unrelated briefs (QUEUE.md:271 B2-150 blocked-line delta, :272 B2-151 pid survivor, :275 B2-152 roblox ractor panel spec). The SEED-RIB cluster the burn plan means (watch/inbox/BURN_PLAN_20260927.md:9-16) is B2-153 (steal dig) plus B2-180 (format) plus B2-181 (MCP) plus B2-300 (handoff kernel), with the merge itself the open want; B2-181's receipt already filed this exact mis-cite as erratum ("said B2-150 format, the SEED-RIB format is B2-180"). This design is the merge body; the build is its owed follow-through.

## Falsifier

Four named falsifiers, one per kill condition plus the estate's own:

1. BUDGET (kill 1): instantiate the directory from live bytes and sum; FAIL if the sum exceeds 102,400 B, and the build itself must exit nonzero on overflow (the --budget arm of move 1). Today's measured estimate: 85,072 B. This falsifier dies the moment an instantiation lands over bar with the reduction path above unapplied.
2. DERIVATION (kill 2): a cold agent holding ONLY the directory (no repo, no git remote) runs join/PROTOCOL.md steps 1-3; FAIL if (a) any manifest file's rebuild writes bytes not present in the directory (invention), (b) verify reports PASS while any inline hash mismatches (the v0 clause, SEED_RIB_FORMAT_v0:97-99, already enforced at tools/seed_rib.py:135-139), or (c) any file the protocol claims to rebuild from directory alone arrives instead from a fetch (class mislabeled). The live pre-run of the mechanism passed this session: 12/12 inline hash-matched cold, 1 pointer honestly UNRESOLVED, exit 0.
3. STALE-TRAP (B2-300 lesson): every state snapshot must carry as-of equal to the build ts; FAIL if a snapshot's stamp predates the manifest's (a hand-carried fossil wearing a fresh face).
4. LAW-REFS (v0 clause e): law_refs in the manifest must be exactly the ids held in kernel/law_registry.json; FAIL on any id the registry does not hold (checked at build from memory/law/registry.json keys, the pattern at tools/seed_rib.py:95-101).
