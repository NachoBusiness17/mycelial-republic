Pages the child walks past gain detail where her attention stayed and stay fog where she never went, so the book can answer the only question a Primer must answer, "what have you learned since I last held you," from bytes alone, and any adult can check that answer by recomputing every page state from the chain tip, because fidelity lives in files plus chain, not in a process that must stay awake. Where the book still invents, the fabrication density is not noise to suppress: it is the map of where the corpus is thin, and the next walk prospects exactly there. The book reads the walker, the walker grows the book, and the growth is auditable by a stranger who holds nothing but the frozen bytes and the chain.

## 4. THE DICE-LAW CLAUSE

The law as the ask states it: the DND module's sha256 preimage law, chain_tip in every preimage, so the book's state is recomputable by anyone. The DND receipt itself is not in this evidence set (UNVERIFIED beyond the ask's wording); the spec below applies the law to pages using chain facts the evidence does carry: chain leaf + tip at every close, the verkle chain files, sha-stamped manifests.

Page-identity format (PRIMER-PAGE-v1):

    page_id     = sha256( preimage )

    preimage    = "PRIMER-PAGE-v1"
                + "|" + book_id            # the rib-named frozen region id (rung 1)
                + "|" + freeze_tip         # the corpus freeze tip stamped at binding
                + "|" + page_ordinal       # stable 1-based integer, fixed at print
                + "|" + content_sha256     # sha256 of the frozen page bytes
                + "|" + chain_tip          # verkle tip at commit; the dice law: tip in every preimage
                + "|" + visitation_epoch   # integer; which visitation generation this state commits

    state leaf  = a chain leaf in the verkle chain:
                  { page_id, epoch, patina_digest, fog_flags, prev_state_sha256 }

    recompute   = sha256(preimage) == page_id
                  and walk leaves from the freeze tip forward,
                  each prev_state_sha256 chaining to the last

Laws the format carries:

1. Immutable under visitation. content_sha256 and freeze_tip bind the frozen bytes; a visit appends a new leaf at a new epoch and never mutates an old one (freeze-to-calibrate).
2. Tip-chained. chain_tip in every preimage means a page identity is valid only against a named chain state; a fork or reorg breaks the identity loudly at recompute instead of silently.
3. Stranger-recomputable. Frozen bytes plus chain rows from the DNA backup list are sufficient; no seat, no daemon, no API.
4. Duplication is emphasis. Two walkers' leaves at the same page and epoch are rank on that region, never collapsed (dedupe-arrivals is forbidden).

Open dials the evidence does not fix (UNVERIFIED, settle at rung 2's first mint): whether book pages ride the session chain or get their own chain (the DNA spine note says the verkle tip covers sessions); whether chain_tip in the preimage is the session tip or a region tip; whether patina_digest is a merkle over visit leaves or a plain digest.
