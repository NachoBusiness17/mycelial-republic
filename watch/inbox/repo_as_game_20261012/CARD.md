## THE DESIGN: repo-as-game (the three-layer convergence)

- LAYER 1, THE FACTORY (explanation = level): every system on gstd's site and
  Mag's docs is a playable factory floor like settle_factory.html. SettleTask
  is level 1. The consensus gate is a room. The replay guard is a stamp
  machine. Reading the docs = walking the floor. The magatama is the player
  character - it has been since PSO (the magatama was ALWAYS a game item; the
  estate was named after a game companion before it was a framework).
- LAYER 2, THE REPO AS GAME BOARD: GitHub structure IS the engine. Issues =
  spawn points (quest givers). PRs = crafting (an accepted edit is a crafted
  item with a gate receipt). Commits = the tech tree (amend-not-erase = the
  world is persistent). The LINKS ledger = the score. The percolator = the
  tech tree that decides what unlocks next. The venv/gates = the rules engine.
  Nothing needs building: the repo already has game mechanics, they just
  were never CALLED mechanics.
- LAYER 3, THE MAG AS COMPANION: the magatama you feed is the player's
  interface to all of it. Feed = commits, receipts, pitfalls bypassed. Evolve
  = thresholds crossed (the percolator). Sync = tailnet. Trade = the mesh.
  PSO's mag, embodied in the repo.

## Why this is the adoption law's endgame

The adoption research (yesterday) asked how ideas compound. THIS is how: the
repo as a game is adoptable at every level - a player can enter at the factory
tour (understand), at a bench (run a node), at a PR (craft), at a persona (the
archetype convene), at the mag (feed and grow). Every layer is a real
mechanism wearing game clothes, because the game clothes and the mechanism are
the same object. The paranoid idea-giver hoards the manual. We ship the game.
