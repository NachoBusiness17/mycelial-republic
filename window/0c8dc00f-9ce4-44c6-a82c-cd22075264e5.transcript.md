AGENT — Here's a summary of the **Claude Workspaces** documentation:

## What workspaces are
Workspaces organize your API usage within an Anthropic organization. They let you separate projects, environments, or teams while keeping **centralized billing and administration**.

## Key mechanics
- Every org has a **Default Workspace** — can't be renamed, archived, or deleted. It has a `wrkspc_` ID but doesn't appear in List Workspaces and shows `null` for `workspace_id` in usage/cost/API-key reports.
- **Max 100 workspaces** per org by default (archived ones don't count).
- **API keys are scoped to a workspace** and only access resources in it (Files, Message Batches, Skills).
- Workspaces themselves + members are managed at the **org level via the Admin API** (requires `sk-ant-admin...` keys).
- Each API response includes an **`anthropic-workspace-id`** header identifying which workspace a request counted toward.

## Claude Code workspace
Created automatically when a member first signs in to Claude Code with their Console account. It:
- Mints per-user API keys (can't be created manually; keys die if the owner is removed)
- Is rate-limited separately and supports per-user monthly spend limits
- ⚠️ Archiving it disables Claude Code sign-in through Console billing org-wide

## Roles
| Role | Permissions |
|------|-------------|
| Workspace User | Playground only |
| Workspace Limited Developer | Manage API keys, use API (no tracing/files) |
| Workspace Developer | Manage API keys, use API |
| Workspace Admin | Full control |
| Workspace Billing | Billing view (inherited, can't be assigned) |

Org admins auto-get Admin everywhere; org users/developers must be manually added.

## Limits & tracking
- **Spend limits** (monthly cap) and **Rate limits** (req/min, input/output tokens) can be set per workspace, never above org limits (can't be set on Default).
- Usage/costs tracked per workspace via the **Usage and Cost API** (`group_by[]=workspace_id`).

## Common use cases
Environment separation (dev/staging/prod), team isolation for cost allocation, and project-based tracking.

## Best practices
Plan structure first, use meaningful names, set limits, audit membership regularly, and monitor via the Usage/Cost API.
